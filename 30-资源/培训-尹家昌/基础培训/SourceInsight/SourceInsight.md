# Source Insight

Source Insight（简称 SI）是一个面向代码阅读的静态分析工具，核心能力是建立**符号数据库**——将项目中所有函数、变量、宏、类的定义和引用关系索引起来，实现秒级跳转和搜索。它不同于 IDE（不能编译），也不同于普通编辑器（理解代码结构），专为阅读大型 C/C++/嵌入式工程而设计。

> 使用流程：创建工程 → 导入源码 → 等待解析 → 浏览代码（跳转、搜索、符号查看）。

## 一、工程操作

### 新建工程

1. 菜单栏 `Project` → `New Project`
2. 在弹出的对话框中配置：
   - **New Project Name**：输入工程名称（建议与项目名一致）
   - **Project Directory**：工程配置文件（`.SI`）存放位置——**不是源码目录**，建议放在源码根目录同级或专门的 `SourceInsight` 文件夹
3. 点击 `OK`

![](pictures\新建项目.png)

> 工程目录和源码目录要分开。工程目录只存 SI 的配置文件，源码目录保持整洁。
>
> **Source Insight 的工程本质上是一个独立的代码索引数据库，而不是代码文件的容器。**它和本地文件相当于是索引和被索引的关系。
>
> **移动文件必须先删除工程文件然后再填加**，因为原本的索引已经更改，只有重新从新的路径加载才能找到。

下面是新建项目的具体过程：

### 导入源码

紧接着新建工程后，弹出 `Project Source Directory` 对话框：

1. 点击 `Browse`，选择你的**源码根目录**
2. 点击 `Add All`，弹出 `Add to Project` 对话框
3. 勾选 `Include subdirectories`（包含子目录）
4. 在右侧 `File Filter` 中筛选文件类型（如 `*.c;*.h;*.cpp`），默认 `*.*` 表示全部
5. 点击 `Add`

<img src="pictures\添加工程.png" style="zoom:67%;" />

或者更精细地按需添加：

1. 在左侧目录树中展开源码根目录
2. 只勾选需要的文件夹（如 `APP`、`BSP`、`Driver`）
3. 点击 `Add Tree` 将选中目录及其子目录全部加入

> `Add` 只加当前目录下的文件，`Add Tree` 递归加所有子目录。大型项目建议按模块 `Add Tree`，避免一次性导入不必要的文件。



### 等待解析

添加完成后，SI 在后台自动解析所有源文件，建立符号数据库。观察以下标志确认完成：

| 标志     | 位置                                        |
| -------- | ------------------------------------------- |
| 文件列表 | 左侧 `Project Files` 窗口显示所有已添加文件 |
| 符号列表 | 底部 `Symbol Window` 显示函数、类、宏等     |
| 进度条   | 底部状态栏，大型项目可能需几分钟            |



### 后期增删文件

- **新增文件**：`Project` → `Add and Remove Project Files` → 在左侧勾选新文件 → `Add` → `Close`
- **添加整个新目录**：同上，选中目录 → `Add Tree`
- **移除文件**：`Project` → `Add and Remove Project Files` → 在右侧点击`Remove File`或者其他Remove选项

<img src="pictures\添加文件.png" style="zoom:67%;" />

> SI 不会自动检测磁盘上新增的源文件——必须手动通过上述对话框添加。但已有文件的**内容变更**会自动检测并同步符号表。

`Add All`：将选中的源码根目录下**所有文件**加入工程，但**不递归子目录**（除非勾选了 `Include subdirectories`）。

`Add Tree`：选中某个目录后递归添加该目录及**所有子目录**下的全部文件。

`Add`：仅添加当前目录下的文件，不涉及子目录。

`Remove Tree`：从工程中移除选中目录及其子目录下的文件（仅移除工程引用，不删除磁盘文件）。





### 新建/打开文件

SI 主要用于**阅读**代码，不推荐用它新建源文件（会缺少工程模板和编译配置）。但可以编辑已有文件：

**打开文件**：

- 在 `Project Files` 窗口中双击文件名
- 或在符号窗口双击函数/变量名
- 或 `File` → `Open...`（`Ctrl+O`）



**新建文件**（仅限简单场景）：

- `File` → `New`（`Ctrl+N`）→ 编辑 → 保存到源码目录
- 保存后需要**手动添加到工程**：`Project` → `Add and Remove Project Files`

> 新建源文件建议在 IDE（如 IAR、Keil）中做，SI 专注于阅读和搜索。

![](pictures\新建文件.png)



### 工程重载

当项目目录整体移动后，原工程路径失效，需要进行工程重载：

`Project` → `Project Settings` → 在 `Project Source Directory` 中重新指定源码根目录路径，SI 会重新扫描并建立符号索引。

> 工程重载不同于重建工程——它保留原有的工程配置（include 路径、宏定义等），只更新源码目录位置。

如不需要更改路径，则只需点击`Project` → `Rebuild Project`进行重载

## 二、符号表管理

符号表是 Source Insight 的核心，存储了所有函数、变量、宏、类的定义位置和引用关系。跳转和搜索都依赖它。

### 自动同步（默认）

Source Insight 默认自动检测文件变化并更新符号数据库：

- 在外部编辑器（IAR、VS Code 等）修改源码并保存
- 切换回 SI 时，底部状态栏自动显示 `Synchronizing...`
- 完成后符号数据更新，无需手动操作

### 手动同步

当自动同步失效或需要全量重建时：

**增量同步（推荐，快速）**：**更新已有文件的索引**。不会清除旧数据，仅分析变更行，速度快。

**日常写代码时使用**。新增或修改文件后，点一下即可刷新，几秒钟就能恢复符号跳转。

```
Project` → `Synchronize Files` → 保持默认选项  → `OK
```

<img src="pictures\同步.png" style="zoom:67%;" />



**全量重建（耗时，彻底）**：**彻底清空旧库，重新扫描所有文件**。耗时较长（可能几分钟）。

**遇到以下情况必须用全量重建：**

1. 出现大量**黑色符号**（无法解析）。
2. 文件路径变更或项目设置（如 Conditions 宏）被修改。
3. 跨平台拷贝工程后，原索引路径失效。

```
Project` → `Rebuild Project` → 勾选 `Re-parse all Source files` → `OK
```

![](pictures\重载工程.png)

| 方式     | 菜单路径                        | 耗时 | 适用场景                 |
| -------- | ------------------------------- | ---- | ------------------------ |
| 增量同步 | `Project` → `Synchronize Files` | 快   | 日常改代码后             |
| 全量重建 | `Project` → `Rebuild Project`   | 慢   | 符号跳转不准、配置修改后 |

> 跳转不到定义时，优先试增量同步。不行再全量重建。如果仍不行，检查项目配置文件中的宏定义和 include 路径是否正确。

### 符号窗口

符号窗口是 Source Insight 中最常用的窗口之一：

可通过Alt+F8快速打开，通常停靠在主编辑区的**左侧**，与当前正在浏览的文档窗口绑定联动。

**查看当前文件结构，按下 `Alt+F8`。看不见符号就需要Rebuild Project。**

![](pictures\符号窗口.png)

1. 符号窗口展示的是**当前打开文件**中的所有符号列表

- 符号窗口不仅包含函数，它解析了文件中的各类标识符：

  - **函数/方法**：包括函数名、参数列表、返回值类型。

  - **全局变量与宏**：文件顶层定义的变量和 `#define`。

  - **类型定义**：包括 `struct`、`class`、`enum`、`typedef` 等自定义类型。

符号窗口**默认不显示**函数内部的局部变量（如函数内的 `int i`），它主要聚焦于全局可见的符号。但是配合 **“Context Window”** 会更容易看到局部变量，但纯符号窗口（Symbol Window）的核心作用永远是**宏观定位**，而非微观查看栈变量。



2. 可用于查看函数及参数所定义的位置，点击符号可直接跳转

3. 符号窗口显示在文档编辑区左侧，与文档窗口相依相存——当前编辑哪个文件，符号窗口就显示该文件的符号

4. 符号窗口默认显示的是当前文件符号，要查看项目全局符号需使用项目符号列表窗口



下面两个窗口任意混淆

| 对比项       | **符号窗口 (Symbol Window)**           | **项目符号窗口 (Project Symbol Window)**                     |
| :----------- | :------------------------------------- | :----------------------------------------------------------- |
| **作用范围** | 仅显示**当前打开的这一个文件**中的符号 | 显示**整个 Source Insight 项目**（所有源文件）中的全局符号   |
| **快捷键**   | `Alt + F8`                             | `Ctrl + F8` 或点击左侧工具栏图标                             |
| **适用场景** | 浏览当前文件结构、快速阅读新加入的代码 | 全局搜索某个函数定义在哪里、查询整个工程中使用了某个结构体多少次 |



### 上下文窗口

`View` → `Panels` → `Context Window`，或直接按下快捷键 **`Alt+F11`**。通过菜单相同路径可将其关闭。

![](pictures\上下文窗口.png)

上下文窗口用于在**不离开当前编辑位置**的情况下预览光标所在符号的定义内容。当光标停在某个函数名上时，上下文窗口自动显示该函数的定义代码。

在上下文窗口中，当光标停留在代码中的某个**函数名、变量名或宏**上时，上下文窗口会自动抓取其**定义或声明**的代码片段进行**即时预览**，无需频繁跳转文件即可快速确认函数参数、返回值或变量类型。

但是上下文窗口的显示内容依赖于**项目已成功建立符号索引**。若项目未同步，该窗口将显示为空白，且无法触发预览功能。





### UTF-8 编码支持

Source Insight 默认**不**支持 UTF-8 编码，中文注释会出现乱码。需要进行额外设置：`Options` → `Preferences` → `Files`的Other栏里选择对应的文件类型 → `Default encoding` 下拉框中选择 `UTF-8`。设置后重新打开文件才能正常显示中文。

### 函数黑名问题

当 SI 中某个函数名称显示为黑色（正常应为蓝色可点击状态），说明符号表未能正确解析该函数。

常见原因包括：

1. **条件编译宏缺失（最常见原因）**
   - 代码中包含 `#ifdef`、`#ifndef` 等预处理指令。
   - 若 Source Insight 的 `Project Settings` → `Conditions` 中未添加对应的宏定义（如 `DEBUG`、`STM32F1` 等），**未定义宏分支下的所有代码会被 SI 视为不可见**，导致该分支内的函数全部变黑。
2. **头文件路径配置缺失**
   - 符号的声明位于外部头文件（`.h`）中。
   - 若 `Project Settings` → `Include Paths` 中未包含该头文件所在的目录，SI 无法获取该符号的声明位置，导致解析失败。
3. **项目索引未更新**
   - 项目经过大幅重构（添加新文件、修改头文件结构），但符号缓存未同步更新。



**解决办法**:

**补全宏定义**

- 打开 `Project` → `Project Settings` → 切换到 `Conditions` 选项卡。
- 根据代码中实际使用的预编译宏，逐行添加（如 `DEBUG`、`CHIP_TYPE` 等）。

**补全头文件路径：**

- 在 `Project Settings` → `Include Paths` 中，添加所有包含 `.h` 声明文件的**根目录路径**。

**强制重建符号表：**

- 配置完成后，执行 `Project` → `Rebuild Project`（勾选 `Re-parse all source files`）。
- 全量重建会清空旧缓存，重新扫描并解析所有源文件，绝大多数黑名问题在此步后消失。







## 四、代码导航与搜索

### 跳转到定义

光标放在函数名、变量名、宏名上：

| 操作                 | 快捷键         |
| -------------------- | -------------- |
| 跳转到定义           | `Ctrl+=`       |
| 跳转到定义（新窗口） | `Ctrl+Shift+=` |

### 搜索引用

搜索引用是 Source Insight 最核心的功能——查找某个符号（函数、变量、宏、类型）在整个项目中的全部使用位置。与普通文本搜索不同，引用搜索基于符号数据库进行智能匹配，能区分读取、赋值、地址取用等不同上下文。

#### Lookup References（查找引用）

这是 Source Insight 查找引用的标准入口，也是考试中出现频率最高的搜索操作。

**打开方式**：

菜单栏 `Search` → `Lookup References...`，或右键点击符号 → `Lookup References`。光标停在函数名、变量名、宏名上即可触发。

<img src="pictures\Lookup搜索.png" style="zoom:67%;" />

**工作流程**：

1. 光标定位到需要查找的符号
2. 执行 `Lookup References`
3. SI 基于符号数据库查询该符号的所有引用位置
4. 结果输出到 `References` 窗口，按文件分组排列
5. 双击任意结果行直接跳转到对应代码位置

**核心特点**：

Lookup References 是基于符号数据库的智能搜索，不是纯文本匹配。它能够区分每次引用是读取还是写入、是函数调用还是地址取用。支持过滤选项——可选择仅显示只读引用、仅显示写入位置，或排除条件编译分支中的引用。

> `Lookup References` 是 "引用搜索" 的正确答案——题目中出现 "查找引用"、"谁调用了"、"被谁修改"、"基于符号" 等关键词时，选这个。



#### Search Files 

`Search` → `Search Files...`（或 `Find in Files`）本身是普通文本搜索

<img src="pictures\Search搜索.png" style="zoom:67%;" />



#### 搜索结果的使用

引用查找结果在 `References` 窗口中按文件分组列出。选中任意一行引用，上下文窗口自动显示该引用位置的代码片段，无需跳转即可预览。在多个引用之间往返查看时使用 `Alt+,`（后退）和 `Alt+.`（前进）快速切换浏览位置。



需要注意：

`Context Window` 用于预览光标所在符号的定义内容，不输出引用列表。`Symbol Window` 用于浏览全局符号列表，不搜索引用。`Project Files` 窗口展示工程文件树，与引用搜索无关。

## 六、常见问题与注意事项

1. **跳转到定义不生效**：优先检查符号表是否同步（`Project` → `Synchronize Files`），再检查项目配置中的 include 路径和宏定义是否正确。SI 不是编译器，它靠这些配置理解代码结构。
2. **搜索结果不全**：确认 `Search` 对话框中的搜索范围选的是 `All Project Files`，而非 `Current File`。
3. **新增文件后搜索不到**：SI 不会自动检测新增文件，必须通过 `Project` → `Add and Remove Project Files` 手动添加。
4. **外部改了代码，SI 里符号跳转不准**：切换回 SI 时等底部状态栏同步完成再操作。如果始终不同步，手动执行 `Project` → `Synchronize Files`。
5. **工程文件路径变了怎么办**：SI 工程文件（`.SI`）记录的是相对路径。如果整个项目目录移动了，重新打开工程时需要重新指定源码根目录：`Project` → `Project Settings` → 修改 `Project Source Directory`。
6. **工程文件很大，同步慢**：删除 SI 不需要的文件类型（如图片、二进制、文档）：`Project` → `Add and Remove Project Files` → 取消勾选无关文件 → `OK`。解析文件越少，同步越快。
7. **窗口布局乱了**：`View` → `Reset Layout...` 恢复默认布局，或 `View` → `Save Layout...` 保存你喜欢的布局。
8. **Add All 不递归子目录**：`Add All` 添加源码根目录下的文件，但**不递归子目录**——除非额外勾选了 `Include subdirectories`。递归添加子目录应使用 `Add Tree`。
9. **SourceInsight 默认不支持 UTF-8**：中文注释出现乱码时需要手动设置：`Options` → `File Type Options` → 选择对应文件类型 → `Encoding` 设为 `UTF-8`。

10. **搜索引用的几种方式**：`Search Files` 在指定文件范围内搜索、`Find in Files` 在文件内容中搜索、`Search Project` 在整个项目中搜索，这三种都属于 SourceInsight 中的搜索引用方式。`Lookup References` 是工具栏上的精确查找引用按钮，图案为大写 R，可区分引用类型（函数调用/变量赋值/类型引用），支持设置大小写限制和跳过无效代码。

11. **关联窗口（Relation Window）的作用**：展示光标所在函数的调用关系——谁调用了它、它调用了谁。注意：关联窗口不用于查看开启的文件列表或函数参数定义位置。前者属于项目文件列表窗口的功能，后者属于符号窗口和上下文窗口的功能。

12. **符号窗口显示局部变量**：符号窗口不仅显示全局符号，也包含当前文件中函数的**局部变量**。认为符号窗口只有全局符号是常见误解。

13. **SourceInsight 支持多窗口**：可以同时打开多个代码文件窗口进行对比浏览，通过 `Tile Horizontal` / `Tile Vertical` 平铺排列。SourceInsight 适合大工程、多层次代码的显示阅读，关键字可彩色显示，各种类型（函数名、宏定义等）一目了然。

14. **窗口布局的保存**：通过 `View` → `Save Layout` 可将当前布局保存到 Layout A-D 四个预设位置之一。布局保存适用于各功能窗口的排列和可见性，可通过工具栏按钮快速切换。布局保存的是窗口排列信息，不包含文件窗口的具体内容。

15. **通过文件结构可以查找**：SourceInsight 通过文件结构和定义可以进行简单查找，并能定位到项目中的具体位置。利用符号表和索引功能，代码定位和文件查找方便。
