```c
#define REG_ADDR   (*(volatile uint32_t *)0x40020000)

void set_bit3(void) {
```

**堆栈的区别，其他内存区**
栈：
- 由编译器管理，函数调用时自动分配/释放；
- 存局部变量、函数参数、返回地址；
- 容量有限（栈溢出 risk），一般是连续的一块内存；
- 在 OS 里还有用户栈、内核栈、可能还有中断栈。
堆：
- 程序运行时用 `malloc/free`（或内核里的 `kmalloc/kfree`）动态分配；
- 生命周期由程序员控制，容易产生内存泄漏、碎片；
- 适合比较大、生命周期不固定的对象。


**其他典型内存区域：**
- 全局/静态区（data / bss 段）：存全局变量、静态变量；
- 代码段（text 段）：存可执行指令；
- 在内核/驱动里，还有“寄存器映射区”（memory-mapped IO）、DMA 缓冲区等特殊内存。


**中断函数**
第一次做
```c
_interrupt double compute_area(double radius)
{
    double area = PI * radius * radius;
    printf("%Area=%f", area);
    hal_delay(100);
    return area;
}

```
- **ISR 一般不能有返回值**
中断服务函数签名通常是 `void isr_name(void)`。返回值没有对象接收，不需要返回值
- **中断里尽量不要用 `printf`**
    - `printf` 很重，可能不是可重入的，还要访问堆栈、锁、缓冲区；
    - 中断本来就要“又短又快”，`printf` 会大幅拉长 ISR 执行时间，影响实时性。
- **中断里不宜调用长时间延时 `hal_delay(100)`**
    - 延时 100ms 的话，这段时间其他中断可能都处理不了，实时性直接崩掉。
    - 正常做法是：中断只做“标记/采样/简单计算”，剩下的让主循环/线程去干。
- **浮点运算在某些 MCU 上的 ISR 里也不推荐**
    - 如果 MCU 没有硬件 FPU，或者中断现场不保存浮点寄存器，会有额外开销或风险。
```c
volatile double g_radius;
volatile int g_area_ready;
void radius_isr(void)
{
    g_radius = read_radius_sensor();
    g_area_ready = 1;         // 通知主循环
}
/* 主循环里 */
void loop(void)
{
    if (g_area_ready) {
        g_area_ready = 0;
        double area = PI * g_radius * g_radius;
        printf("Area=%f\n", area);
    }
}
```
ISR 的最佳实践：短、小、快，不做耗时和复杂操作。

### 内存池
实现固定大小内存池，有创建和free函数，避免内存碎片，支持多任务环境的安全访问
```c
typedef struct block {
    struct block *next;
} block_t;

typedef struct {
    void *pool;
    block_t *free_list;
    size_t block_size;
    size_t block_count;
    mutex_t lock;
} mempool_t;

void *mp_alloc(mempool_t *mp) {
    lock(&mp->lock);
    block_t *b = mp->free_list;
    if (!b) {
        unlock(&mp->lock);
        return NULL;
    }
    mp->free_list = b->next;
    unlock(&mp->lock);
    return (void *)b;
}

void mp_free(mempool_t *mp, void *p) {
    lock(&mp->lock);
    block_t *b = (block_t *)p;
    b->next = mp->free_list;
    mp->free_list = b;
    unlock(&mp->lock);
}

```
多任务环境下，要加锁保护 free list（互斥锁 / 自旋锁）。

```c
#define my_sizeof_var(var) ((size_t)((char*)(&var + 1) - (char*)&var))
```

标准`sizeof`是**编译时运算符**，不是在运行时计算的。

sizeof用函数实现的缺陷：
sizeof是编译时运算符，函数是运行时调用
sizeof可以用于类型（int, double），函数只能用于变量
sizeof返回值是编译时常量，函数返回值是运行时计算

```c
int my_strcmp(const char *s1, const char *s2)
{
    const unsigned char *us1 = (const unsigned char *)s1;
    const unsigned char *us2 = (const unsigned char *)s2;
    
    while (*us1 && *us1 == *us2)

        us2++;
    }
```

### `sizeof`
sizeof是关键字，在编译器执行，
```c
(1) sizeof( object ); // sizeof( 对象 );  
(2) sizeof( type_name ); // sizeof( 类型 );  
(3) sizeof object; // sizeof 对象;
```
sizeof计算对象的大小也是转换成对对象类型的计算，也就是说，同种类型的不同对象其sizeof值都是一致的。
sizeof的对象也可以是表达式，根据表达式的最终结果类型来确定大小，一般不会对表达式进行计算。
sizeof的计算发生在编译时刻，所以它可以被当作常量表达式使用，如： 
```c
char ary[ sizeof( int ) * 10 ]; // ok
```

对结构体
**(1) 结构体变量的首地址能够被其最宽基本类型成员的大小所整除；  
(2) 结构体每个成员相对于结构体首地址的偏移量（offset）都是成员大小的整数倍，如有需要编译器会在成员之间加上填充字节（internal adding）；  
(3) 结构体的总大小为结构体最宽基本类型成员大小的整数倍，如有需要编译器会在最末一个成员之后加上填充字节（trailing padding）。**


对位域
**(1) 如果相邻位域字段的类型相同，且其位宽之和小于类型的sizeof大小，则后面的字段将紧邻前一个字段存储，直到不能容纳为止；  
(2) 如果相邻位域字段的类型相同，但其位宽之和大于类型的sizeof大小，则后面的字段将从新的存储单元开始，其偏移量为其类型大小的整数倍；  
(3) 如果相邻的位域字段的类型不同，则各编译器的具体实现有差异，VC6采取不压缩方式，Dev-C++采取压缩方式；  
(4) 如果位域字段之间穿插着非位域字段，则不进行压缩；  
(5) 整个结构体的总大小为最宽基本类型成员大小的整数倍。**
