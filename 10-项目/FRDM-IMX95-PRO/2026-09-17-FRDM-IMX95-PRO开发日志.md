# 2026-09-17 FRDM-IMX95-PRO 开发日志（A55 / Harpoon 验证）

> 板型：NXP FRDM-IMX95-PRO（i.MX95 B0，19x19，LPDDR5 16GB，eMMC 32GB，板载 6.18-whinlatter 原厂系统）。
> 记录时间：2026-09-17。当日主题：验证下载的 Harpoon 能否用于本板，并找出"在 A55 上跑 FreeRTOS"的最短可行路径。

## 一、今天要解决的问题

负责人已把目标从 M7 改为 **A55 上跑 FreeRTOS**。手上已有从 NXP 下载的 Harpoon 包（`HS_v3.5_IMX95-19X19-LPDDR5-EVK.zip`，解压为 `Real-time_Edge_v3.3_IMX95-19X19-LPDDR5-EVK`）。今天要回答：**这个包能不能直接用在 FRDM-IMX95-PRO 上？** 如果不能，最短路径是什么。

## 二、结论速览

1. **Harpoon 是正确方案**：Linux(PREEMPT-RT) 作 root cell + Jailhouse 分区 + FreeRTOS/Zephyr 作 inmate 跑在 A55 上。
2. **下载包不能直接认定可用**：它是 `imx95-19x19-lpddr5-evk` 的板级构建，Pro 板不在 Harpoon 官方支持清单里（详见 `2026-09-17-Harpoon可用性验证.md`）。
3. **但底座比预期好得多**：**FRDM-IMX95-PRO 的原厂 Linux 已经预装整套 Jailhouse**（工具、内核模块、固件、`imx95` cell、示例 inmate），U-Boot 也内置 Jailhouse 启动流程。缺的只是"把内存让出来"和"FreeRTOS inmate"这两块。
4. **今天没跑成实机验证**：卡在"抢 U-Boot autoboot"这一步，并因此踩出一个把 A55 串口彻底打哑的坑（问题 4）。这条坑的根因已定位清楚，规避办法也有了。

## 四、遇到的问题：现象 → 排查 → 根因 → 解决

### 问题 1：串口打不开，`Access to the port 'COMxx' is denied`

- **现象**：PowerShell/.NET 打开 COM16–19 全部报 `Access to the port 'COMxx' is denied`。
- **排查**：先怀疑沙箱拦截；但沙箱拦截会带 `[sandbox: ...]` 标记，这里没有，只有 .NET 异常。列进程发现 `MobaXterm`（PID 27856）在跑。
- **根因**：MobaXterm 打开着串口会话，Windows 串口是独占资源。
- **解决**：关闭 MobaXterm 的串口标签页（保留 SSH 页），四个口立即可打开。
- **验证**：关闭后逐个 `Open()` 全部成功。

### 问题 2：沙箱拒绝执行外部程序

- **现象**：`uuu.exe`、`tar.exe`、`python.exe`、`git.exe`、`cmd.exe` 一律 `Access is denied` / `[sandbox: file access denied under workspace-write mode]`。
- **排查**：逐个试，发现规律——**新进程创建被拦，进程内的 PowerShell/.NET 代码不受影响**。
- **根因**：当前 DSH 文件策略为 `workspace-write`，工作区外的可执行文件/设备访问被拒。
- **解决**：需要跑 uuu 时按沙箱规则单次提权；本次的串口读写、二进制字符串提取全部改用纯 PowerShell/.NET 实现，不需要提权。
- **附带收获**：写了 `serial-probe.ps1`（单口交互）与 `serial-capture.ps1`（多口并发抓取），后续一直用。

### 问题 3：抢 U-Boot autoboot 失败（命令落在了错误的时刻）

- **现象**：第一次尝试时，`printenv` 命令的回显出现在 **BL31 之后、U-Boot banner 之前**，说明命令在 ATF 阶段就发出去了；板子随后正常自启。
- **排查**：读脚本逻辑，发现提前退出条件是 `$all -match '=>\s*$'`——用"累积输出里是否出现 `=>`"来判断是否到了 U-Boot 提示符。
- **根因**：Linux 关机日志里出现了能匹配该正则的字符组合，脚本**误判提前结束发送**；而 i.MX95 的 autoboot 只有 2 秒，发送窗口一旦错过就必然失败。
- **解决**：改为"整个窗口内持续轮发 Ctrl-C/空格/回车，不做提前判断"，并且必须在**上电之前**就开始发键。
- **教训**：用文本匹配当状态机很脆；抢 autoboot 这种一次性窗口，宁可多打也不要提前收手。

### 问题 4（今天最值钱的坑）：A55 控制台彻底静默，看起来像"板子挂了"

- **现象**：COM17 发什么都不回（CR、`version`、`root` 全部无响应），持续几分钟。
- **排查路径（逐步排除）**：
  1. 怀疑内核 panic / 板子复位 → 但没有新的启动日志，M33 侧也没有复位迹象；
  2. 怀疑 USB 串口重新枚举、COM 号变了 → 读注册表 `HKLM\HARDWARE\DEVICEMAP\SERIALCOMM`，映射**未变**：`\Device\Serial2 = COM17`，四个口都还在，也都能打开；
  3. 怀疑板子掉电 → 探测 COM19（M33 SM 控制台），此时**还能进 `*** SM Debug Monitor ***`**，说明 SoC 有电、M33 正常；
  4. 结论收敛到"只有 A55 的串口登录会话出了问题"。
- **根因**：上一轮我连续 28 秒轮发 Ctrl-C（每 120 ms 一个），把 `serial-getty@ttyLP0` 反复杀死并重启。systemd 默认 `StartLimitBurst=5` / `StartLimitIntervalSec=10s`，超过后**放弃重启该单元** → 登录提示符永久消失 → 串口一个字都不再输出。**内核和系统是活的。**
- **解决/规避**：
  - 抢 autoboot 的发送时长限制在启动窗口内（脚本加了 `-BlastSec`，默认 90 秒），抢不到就停手，不再继续砸 getty；
  - 需要重新拿到控制台时，断电重启即可（今天结束时板子已断电）；
  - 判断"板子是否活着"必须用**独立通道交叉验证**（M33 SM 控制台、网络、串口端口映射），不能只看一个串口有没有回显。
- **验证**：后来 COM19 也静默，是因为用户把板子断电了；这条时间线对得上。

### 问题 5：PowerShell 脚本里中文注释把下一行"吃掉"

- **现象**：改完 `uboot-run.ps1` 后运行报 `Attempted to divide by zero`，原因是 `$keys` 变成了 `$null`（`$null.Count` 在 PS 3+ 返回 0，取模即除零）。
- **排查**：读回文件，行内容本身是正确的。
- **根因**：文件是无 BOM 的 UTF-8，Windows PowerShell 5.1 按 ANSI（CP936）解码，中文注释的字节序列在行尾被解成续行/转义，把紧随其后的赋值行吞掉了。
- **解决**：交互脚本改成**纯 ASCII**（注释也用英文），中文说明放到 Markdown 笔记里。
- **教训**：给 Windows PowerShell 5.1 写的 .ps1 一律用 ASCII，或显式带 BOM 保存。

**内存账**：DRAM 16 GB；`jh_root_mem` 给出的 root cell 内存是 `0x90000000+0x58000000`（到 0xE8000000）和 `0x180000000+0xc0000000`（到 0x240000000），约 4.4 GB。这样 Linux **看不到** `0xf0000000+0xf700000`（inmate 区，约 247 MB）和 `0xffc00000+0x400000`（hypervisor 区，4 MB）——正好就是 Jailhouse 需要的两块。**所以不需要那个缺失的 `-root.dtb` 文件，只要让 U-Boot 带上 `jh_root_mem` 就能安全启用 Jailhouse。**

## 九、当日补充：Jailhouse 在 Pro 板上实机跑通（当天下午后半段）

前面第八节写的都还成立，但**当天下班前把实机链路打通了**，这是今天最重要的结果。

### 9.1 可复现步骤

1. 用脚本在上电前开始轮发回车抢 U-Boot（CR 能打断 autoboot，但不会像 Ctrl-C 那样打死 getty），拿到 `u-boot=>` 后**在同一个进程里立刻**下发：

```text
setenv jh_root_mem 0x58000000@0x90000000,0xc0000000@0x180000000
setenv jh_clk kvm.enable_virt_at_load=false cpuidle.off=1 clk_ignore_unused kvm-arm.mode=nvhe
printenv jh_root_mem jh_clk
run bsp_bootcmd
```

2. 启动后内核内存从 15.75 GB 降到 4.375 GB，命令行带上 jh_clk：

```text
Kernel command line: kvm.enable_virt_at_load=false cpuidle.off=1 clk_ignore_unused kvm-arm.mode=nvhe console=ttyLP0,115200 earlycon root=/dev/mmcblk0p2 rootwait rw
Memory: 3407188K/4587520K available     ← 未设置 jh_root_mem 时是 15106208K/16515072K
MemTotal: 4398132 kB
```

3. 登录 root，加载模块并启用 hypervisor：

```text
modprobe jailhouse                     # lsmod: jailhouse 45056 0
jailhouse enable /usr/share/jailhouse/cells/imx95.cell
```

输出的关键行（实机）：

```text
Initializing Jailhouse hypervisor v0.12 (393-gcda91277-dirty) on CPU 0
Code location: 0x0000ffffc0200800
Page pool usage after early setup: mem 71/993, remap 0/131072
Initializing processors: CPU 0... OK ... CPU 5... OK
Initializing unit: irqchip / ARM SMMU v3 / ARM SMMU / PVU IOMMU / PCI
Adding virtual PCI device 00:00.0..00:03.0 to cell "imx95"
Activating hypervisor
jailhouse cell list → 0  imx95  running  0-5
```

4. 创建 inmate cell（CPU5 从 Linux 划走）并把厂商自带演示 inmate 跑起来：

```text

  → Created cell "inmate-demo"
  → cell list: 0 imx95 running 0-4 / 1 inmate-demo shut down 5
jailhouse cell load inmate-demo /usr/share/jailhouse/inmates/uart-demo.bin
  → Cell "inmate-demo" can be loaded   (RC=0)
jailhouse cell start inmate-demo
  → 串口持续输出：Hello 144284 from cell! ... Hello 166434 from cell!
```

**结论：在 FRDM-IMX95-PRO 上，"Linux 作 root cell + Jailhouse 分区 + 一个 A55 核跑独立实时域并对外输出"这条链路已经实机跑通。** 也就是说 Harpoon 所依赖的底座，这块板子的原厂系统自己就具备。

### 9.2 这一步暴露的新问题（都要记）

1. **U-Boot 变量不持久**：原厂环境区 CRC 损坏，U-Boot 每次都用编译进镜像的默认环境。断电后 `jh_root_mem`/`jh_clk` 全部丢失，必须重做；板载也没有 `fw_printenv`/`fw_setenv`，无法从 Linux 写 U-Boot 环境。
2. **U-Boot 提示符不是"安全停车位"**：停在 `u-boot=>` 不操作，一分多钟后会被看门狗复位并自启回 Linux（上一轮的 `setenv` 就是这样失效的）。所以必须"抢到提示符→立刻 setenv→立刻启动"，全在一个进程内完成。
3. **inmate 会抢走调试串口**：`uart-demo.bin` 占用 LPUART1 及其中断后，**Linux 控制台彻底失去输入**（回车、Ctrl-C 都无效），只能靠复位板子收回控制权。这正是 Harpoon 给 inmate 单独分配一路 UART 的原因。
4. **我的串口读取函数在持续数据流下会无限等待**：`Read-UntilQuiet` 只按"多久没有新数据"退出，遇到 inmate 每秒上百行刷屏就永远等不到安静，表现为脚本挂死、看起来像板子卡死。已加绝对超时上限（`maxMs`）并截断输出。**这几次"板子挂了"的假象，根因都在工具侧，不在板子。**
5. **抢 autoboot 的按键选择很关键**：Ctrl-C 会杀死 `serial-getty@ttyLP0`，连续打会触发 systemd 的 `StartLimitBurst=5/StartLimitIntervalSec=10s`，导致 getty 永久不再启动（表现为串口彻底静默，但内核正常）。**只用回车（CR）轮发即可打断 autoboot，且不会打死 getty。**

### 9.3 对下一步的影响

- 底座已验证 → 不再需要"赌 EVK 容器能不能在 Pro 上启动"。路径 A（UUU 送 EVK 容器）可以降级为备选。
- 剩下要解决的是 **inmate 侧**：把演示 inmate 换成 Harpoon 的 FreeRTOS 应用，并解决三件事：
  1. 拿到 `imx95-harpoon-freertos.cell`（或等价 cell 配置）、FreeRTOS inmate 二进制、inmate 设备树；
  2. 给 inmate 指定**独立于 Linux 控制台**的串口（否则又会失去 Linux 控制权）；
  3. `jh_root_mem`/`jh_clk` 每次启动都要重设，后续要么固化进 U-Boot 环境区，要么写进启动脚本/自制容器。

## 十、当日收尾：Harpoon 的 FreeRTOS inmate 实机跑通（最重要的结果）

第九节只跑到"厂商自带的演示 inmate"。当天最后一步把 **Harpoon 自己的 FreeRTOS inmate** 跑起来了。

### 10.1 关键转折：网络通了，SSH 成为主控制通道

- 网线插在板子的 1GbE 口和电脑的板载网口（Realtek PCIe GbE）之间，两端自动配 `169.254.x.x/16` 链路本地地址，**不需要 DHCP、不需要手工配 IP**。
- 板子 `eth0` 默认 DOWN，串口执行 `ip link set eth0 up` 后拿到地址（本次是 `169.254.170.232`；下次启动可能变）。
- 板子 sshd 允许 **root 免密** 登录，`ssh -o BatchMode=yes root@<IP>` 直接可用。
- **这一步解决了第九节 9.2-3 的痛点**：inmate 抢走串口后 Linux 控制台失去输入，但 SSH 通道仍然好用，后续所有 jailhouse 操作都改走 SSH。

### 10.2 把 Harpoon 文件传上板

`vmexits_mmio` 占绝大多数，说明 inmate 在持续访问被 hypervisor 模拟的 MMIO（即它在写自己的控制台），是"真的在跑"的硬证据。

### 10.4 与第九节结论的关系（口径修正）

- 第九节写"剩下要解决的是 inmate 侧"——**当天就解决了**。
- 需要修正的表述：**不能说"下载的 Harpoon 完全不能用"**。准确结论是：
  - 作为 **EVK 整机镜像** → 不能直接用在 Pro 板（启动容器/DTB/SM/脚本机器判断都对不上）；
  - 作为 **Harpoon 资产（FreeRTOS inmate 二进制 + cell 配置 + 控制程序）** → **能用**，已在 Pro 板上实机跑起来；
  - 真正缺的是"官方针对 Pro 板的板级适配"（`imx95-19x19-frdm-pro-root.dtb`、脚本机器判断、inmate 控制台 UART）。
- 做法本质是"拆开用"：**底座用 Pro 板原厂的 Jailhouse + `imx95.cell`，inmate 用 Harpoon 包里的 FreeRTOS 二进制 + Harpoon cell 配置**。

### 10.5 仍待处理

1. **看不到 FreeRTOS 的打印**：两个 harpoon cell 的 console 都是 LPUART3（`0x42570000`），而 Pro 板 J22 只引出 UART1/2/7；要看到输出需改 cell/console 到已引出 UART 并重编 inmate 的 console 配置。
