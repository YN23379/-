## 三、SD 启动问题与排查

### 1. 初始现象

- USB SDPS 临时启动时，M7 FreeRTOS 串口和 GPIO 均正常。
- 同一类镜像写入 SD 卡并完整启动后，M7 串口任务仍在运行，但 GPIO14 无波形，GPIO15读回始终为0。
- M7诊断值由正常状态变为：`PCNS=FFFFFFFF`、`PCNP=FFFFFFFF`、`PDOR/PDIR/PDDR`访问异常。
- 在 U-Boot 中直接写 GPIO2 的 PSOR/PCOR 可以改变实际引脚电平，因此没有先判定为硬件损坏。

### 2. 关键判断

USB SDPS 流程停留在 SPL 阶段，不能代表完整 A55 启动链已经执行。SD 启动会继续经过 BL31 和 U-Boot，启动阶段不同是两种结果的关键差异。

匹配板载版本的 TF-A 源码为：

```text
F:\project\Learning\RTOS\tools\imx-atf-source
branch: lf_v2.12
commit: 4a2e9ef5f9f185bda68470b46365add008903b8c
```

文件 `plat/imx/imx9/imx95/imx95_bl31_setup.c` 中明确有：

```c
mmio_write_32(GPIO2_BASE + 0x10, 0xffffffff); /* PCNS */
mmio_write_32(GPIO2_BASE + 0x18, 0xffffffff); /* PCNP */
```

因此，SD 启动时 BL31 会把 GPIO2 的按引脚安全/特权属性重新设置为全1。M7虽然已经启动，但随后访问被改变属性的 GPIO14/15时读为0、写入无效。问题不是 M7 没启动，也不是 FreeRTOS 没调度。

## 四、修复方案

### 1. SM 配置

最终使用：

```text
F:\project\Learning\RTOS\tools\imx-sm\configs\other\mx95frdm-pro-m7gpio.cfg
```

保留以下关系：

```text
LM1/M7: GPIO2 OWNER
LM2/A55: GPIO2 ACCESS
LM2/A55: PERLPI_GPIO2 ALL
M7: PIN_GPIO_IO14/15 OWNER
```

不能把 GPIO2 和 A55 所需 API 全部移走，否则 A55 启动过程会出现 `WDOG3 -> FCCU errId=19 -> Reset LM2`。

### 2. M7 代码

文件：

```text
F:\project\Learning\RTOS\SDK_26_06_00_IMX95LPD5EVK-19\boards\imx95lpd5evk19\freertos_examples\freertos_hello\cm7\freertos_hello.c
```

只清除 GPIO2 bit14/15：

```c
#define GPIO_PIN_MASK ((1UL << 14U) | (1UL << 15U))
GPIO2->PCNS &= ~GPIO_PIN_MASK;
GPIO2->PCNP &= ~GPIO_PIN_MASK;
```

当前稳定实现为：初始化前清除一次；任务循环中先检查 bit14/15，只有被重新设置时才调用 `gpio_reclaim_pins()`。实测表明，单次清零或只在进入循环前清零受启动时序影响，不能作为稳定结论。按位清除后全寄存器预期为 `0xFFFF3FFF`，不会影响 GPIO2 其他引脚。

## 六、实机结果

COM18持续输出 M7 FreeRTOS UART 和 GPIO信息；GPIO14输出约1 Hz方波。将 J15-8（GPIO14）与 J15-10（GPIO15）连接后，稳定得到：

```text
GPIO OUT=0, IN=0
GPIO OUT=1, IN=1
```

逻辑分析仪确认 GPIO14 有波形，说明 M7启动、FreeRTOS调度、IOMUX、RGPIO输出和输入回读均通过；SD卡掉电后可自动启动同一程序。

## 七、实时性初测

使用 M7 DWT 周期计数器和 `vTaskDelayUntil(500 ms)`：

```text
M7主频约 800 MHz
周期约 400000000 CPU cycles
周期抖动约 0~6 cycles
```

该结果只代表当前任务、当前负载和当前启动镜像下的初测结果。后续产品级验证还需要增加高低优先级抢占、外部中断响应、通信负载、临界区和长时间运行测试。

## 八、今天结论

1. SD启动问题已定位到 BL31 对 GPIO2 PCNS/PCNP 的启动时序改写。
2. 当前 M7侧按需 reclaim 方案已经通过 USB、SD、串口、GPIO和掉电启动验证。
3. 早期“循环外清零两次即可稳定”的判断已纠正，不再作为结论。
4. 产品化方案仍应优先考虑源码级修改匹配版本 BL31，并完成 Linux/A55 与 M7 的资源回归。
