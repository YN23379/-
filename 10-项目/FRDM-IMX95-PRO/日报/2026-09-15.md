# 2026-09-15 每日总结

今天重新排查了 FRDM-IMX95-PRO 的 GPIO 权限问题。主要参考了 NXP 的 [AN14748：How to Run Application on M7 Core of i.MX95](https://www.nxp.com/docs/en/application-note/AN14748.pdf)、[FRDM-IMX95 Getting Started](https://www.nxp.com/document/guide/getting-started-with-frdm-imx95:GS-FRDM-IMX95) 以及 UUU 的使用说明，结合板子上的启动日志和 `imx-atf` 源码，继续确认 M7 程序从 USB 临时启动和从 SD 卡完整启动时的差异。

先根据官方流程重新生成包含 M7、System Manager 和 A55 启动组件的启动镜像，使用 UUU 写入 SD 卡，再把 SW4 调整为 `1011`，让板子从 SD 卡启动。启动后，COM18 仍然能够看到 M7 FreeRTOS 的串口输出，但 GPIO14 实际电平没有变化，GPIO15 也没有输入变化，说明 M7 已经运行，问题集中在 GPIO 访问上。

随后在 M7 程序中增加 GPIO 寄存器状态输出，并和 USB 启动时的结果进行对比。SD 启动后发现 `PCNS` 和 `PCNP` 被设置成 `FFFFFFFF`，GPIO 输出寄存器虽然有写入动作，但实际引脚没有变化；在 U-Boot 中直接操作 GPIO2 又能够改变电平，因此排除了 GPIO 引脚、复用配置和硬件损坏的问题。继续查看与板载版本对应的 TF-A 源码，发现 A55 启动经过 BL31 时会把 GPIO2 的安全属性重新设置为全 1，导致 M7 对 GPIO14、GPIO15 的访问失效。

确认原因后，保留 A55 启动所需的 GPIO2 资源和 API 权限，只在 M7 程序中按位恢复 GPIO14、GPIO15 的 `PCNS/PCNP` 权限。程序启动时先恢复一次，任务运行过程中再检查对应位，发现权限被重新设置时才再次恢复。重新编译、重新生成启动镜像并写入 SD 卡后，GPIO14 可以输出波形；将 GPIO14 和 GPIO15 直接连接后，串口能够同步显示 `OUT=0, IN=0` 和 `OUT=1, IN=1`，GPIO 输入输出恢复正常，SD 卡掉电重启也能够自动运行。

今天还进行了 M7 FreeRTOS 的实时性初步测试，使用 DWT 周期计数器测量 `500 ms` 周期任务，得到 M7 主频约 `800 MHz`，周期约 `400000000` 个 CPU 周期，当前测试条件下周期抖动约 `0~6` 个周期。这个结果可以作为后续测试的基准，下一步还需要继续测试中断响应、任务抢占和不同负载下的实时性。

# 2026-09-15 每日总结

今天完成了FRDM-IMX95-PRO的GPIO权限排查和SD卡持久化启动验证。先解决了早期SM配置把GPIO2及其API从A55侧整体移走后引起的`WDOG3 -> FCCU errId=19 -> Reset LM2`问题，最终保留A55的`PERLPI_GPIO2 ALL`和GPIO2访问权限。

随后进行SD卡持久化。写入前先通过UUU内置`sd`脚本、官方Pro启动镜像中的`sd_dev=1`以及实机U-Boot的`mmc 0=eMMC、mmc 1=SD`三项信息确认目标设备。UUU先临时加载官方Pro `flash_a55`进入Fastboot，再选择`mmc 1`，最终把`flash-m7-gpio-reclaim.bin`写入32 GB SD卡启动区，未写入eMMC。

写入后发现USB模式GPIO正常，SD模式M7任务仍运行，但GPIO读0、写入无效。M7诊断显示SD启动后`PCNS/PCNP=FFFFFFFF`；U-Boot直接写PSOR/PCOR能改变实际电平，排除引脚、IOMUX和硬件故障。通过与板载日志版本匹配的NXP TF-A源码，最终确认BL31会把GPIO2的`PCNS/PCNP`写成全1。

最终在M7程序中于GPIO初始化前清除一次，并在任务循环中按需检查bit14/15；发现`PCNS/PCNP`被重新设置时才再次清除。单次清零或只在进入循环前清零受启动时序影响，不作为稳定结论。重新生成并写入最新`flash-m7-gpio.bin`后，SD启动实测`PCNS/PCNP=0`，`PDOR`在`0/4000`之间翻转，GPIO14有波形；J15-8与J15-10连接后`OUT=0/IN=0`和`OUT=1/IN=1`稳定同步。串口输入输出、GPIO输入输出以及SD掉电自启动已完成实机验证。

同时核对了`AN14120 Rev.5.0`。该文档覆盖i.MX95，主要介绍VS Code、MCUXpresso for VS Code和J-Link调试Cortex-M的方法，可用于以后进行断点、单步、变量、寄存器和内存调试；它不是本次SD卡烧写教程。当前SD流程的主要依据仍是UM12527、AN14748和UUU内置脚本。

完成了M7实时性初测。使用DWT周期计数器和`vTaskDelayUntil(500 ms)`测得M7约800 MHz，周期约400000000周期，周期抖动约0~6周期；该结果只能说明当前测试任务和启动方式下调度稳定，后续仍需增加中断响应、抢占延迟和负载场景测试。
