## 一、PLSR

PLSR是多段脉冲输出指令。它不是单纯打开PWM，而是按照公共参数和段表，连续处理频率变化、脉冲计数、方向控制、等待条件、段跳转和结束动作。

信捷定位控制手册把PLSR数据分为三类。

| 数据类型 | 主要内容 | 我的理解 |
|---|---|---|
| 脉冲数据 | 总段数、每段频率、脉冲个数、等待条件和跳转段 | 说明每一段做什么 |
| 用户参数 | 相对绝对模式、起始执行段 | 说明从哪里开始以及脉冲数怎样解释 |
| 系统参数 | 发送模式、方向、起止速度、加减速时间和曲线 | 说明整条指令按什么规则执行 |

一个脉冲通常对应驱动器内部一个位置增量。脉冲数量决定移动量，脉冲频率决定速度，方向端子的电平决定正向或反向。因此PLSR同时包含位置、速度和流程三个问题。

```text
位置问题：到底要发多少个脉冲
速度问题：每个脉冲应该在什么频率下输出
流程问题：本段结束后等待什么，下一步去哪个段
```

本项目是在STM32F407上实现一路PLSR。上位机通过Modbus写参数，运动任务生成离散计划，定时器输出PWM，更新中断按实际周期登记脉冲，状态再映射给上位机读取。

### 1. PLSR和普通PWM的区别

普通PWM主要关注频率和占空比。PLSR还必须知道已经完成多少个周期，并在准确的周期边界改变频率或停止。

例如设置10000Hz和10000个脉冲，理想持续时间约为1秒。若启动时多登记一个，停止时截断半个周期，或者段切换时又触发一次更新，最终位置都会错误。PLSR最难的部分不是让端子翻转，而是让数量、频率、方向和段状态始终对应。

### 2. 官方规则和项目实现要分开

信捷手册定义业务语义，例如负脉冲表示反向，Wait时间从本段完成后开始，ACT可以在本段未发完时切段，完成方式和后续方式的段边界不同。

Q16、Backup SRAM、定时器预装载、任务与中断拆分属于本项目实现。这些方法用于复现业务效果，不能反过来说信捷PLC内部一定采用相同算法。

## 二、频率、周期和脉冲

### 1. 频率与周期

```text
周期 = 1 / 频率
100Hz对应10ms
1000Hz对应1ms
10000Hz对应100us
100000Hz对应10us
```

100kHz时，MCU每10us就要处理一次周期边界。这个时间不是全部留给中断，串口和系统调度也要运行，所以高频设计必须减少每周期的软件工作。

### 2. 一个脉冲怎样统计

一个脉冲应理解为一个完整PWM周期。逻辑分析仪可以按上升沿或下降沿统计，但采集窗口包含空闲电平时，两种边沿可能相差一个。

例如输出从低电平开始，窗口恰好在第一次上升沿前打开，可能看到的上升沿比完整下降沿多一个。这不等于硬件多输出一个完整脉冲。正确判断要同时看首尾电平、两类边沿数量和完整周期。

### 3. 定时器频率换算

```text
输出频率 = 定时器时钟 / ((PSC + 1) × (ARR + 1))
CCR约等于(ARR + 1) / 2
```

`PSC`负责预分频，`ARR`决定周期，`CCR`决定比较位置。寄存器都按实际值增加一参与计算。

PSC、ARR和CCR是整数，所以目标频率不一定能被定时器时钟整除。实际频率存在量化误差。频率越高，ARR越小，一个计数误差所占比例越大。这是硬件分辨率问题，不是改成浮点数就能消除。

### 4. 高低电平顺序

PWM模式和输出极性共同决定先高后低还是先低后高。不能只看LED，因为PLC输出端可能经过光耦和三极管，端子电平可能与MCU逻辑相反。

调试时先用100Hz，同时观察MCU测试点、LED和Y端子。此时半周期为5ms，容易看清空闲电平、首半周期和末半周期。高频下只看总数，很难分清极性和毛刺。

## 三、方向、位置和累计数

### 1. 脉冲数符号

信捷手册说明，频率为非负数，只表示速度；脉冲个数可以为正或负，负数表示反向发脉冲。

| 脉冲个数 | 实际数量 | 方向 |
|---:|---:|---|
| `1000` | 1000 | 正向 |
| `-1000` | 1000 | 反向 |
| `0` | 0 | 不运动 |

正逻辑下正向对应方向端子ON，反向对应OFF。负逻辑下两者相反。方向逻辑只改变电平解释，不改变正负脉冲的运动含义。

### 2. 为什么需要方向延时

信捷手册默认方向延时为10ms。脉冲端子使用高速输出，普通方向端子的光耦响应较慢。若方向和第一个脉冲同时输出，驱动器可能先收到脉冲，后识别新方向。

```text
判断目标方向
  -> 写方向端子
  -> 等待方向延时
  -> 启动脉冲PWM
```

方向未改变时不需要每段重复等待。真正换向时，前一段先结束，再改变方向并等待。

### 3. 当前位置与累计实际脉冲数

当前位置是有符号量。正向增加，反向减小。绝对定位要用目标位置减当前位置。

累计实际脉冲数是无符号统计量。每完成一个实际周期就增加一，不区分方向，并且需要掉电保持。

```text
正向发1000，再反向发400
当前位置 = 600
累计实际脉冲数 = 1400
```

两者不能共用一个变量。把累计数当当前位置会破坏绝对模式，把当前位置叫累计数又会在反向后出现负数。

## 四、相对模式和绝对模式

### 1. 相对模式

相对模式把段表脉冲数解释成本段增量。正1000表示从当前位置再向正方向移动1000，负1000表示向反方向移动1000。

### 2. 绝对模式

绝对模式把段表脉冲数解释为目标位置。

```text
本段实际脉冲增量 = 目标位置 - 当前有符号位置
```

当前位置3000，目标1000，实际增量为负2000，需要反向发送2000个脉冲。当前位置等于目标时不发脉冲，但仍要正确处理该段的等待和跳转。

### 3. 多段绝对模式

下一段可能在当前段尚未完成时提前规划。此时不能直接用当前瞬时位置计算，而要用当前段预计结束位置作为下一段基准。

这说明预加载不只是存一个频率，还要提前确定实际脉冲量、方向和曲线边界。

## 五、段表、起始段和跳转

| 段字段 | 作用 |
|---|---|
| 频率 | 本段希望达到的目标速度 |
| 脉冲个数 | 相对增量或绝对目标，符号决定方向 |
| 等待类型 | 决定何时进入下一段 |
| Wait时间 | 本段完成后的等待时长 |
| ACT时间 | 从本段开始计算的动作时长 |
| 跳转段 | 条件满足后进入哪一段 |

本题最多10段。跳转值为0时进入顺序下一段，最后一段的跳转值为0时结束。跳转值非0时进入指定段。

跳转到自己或前面段可能形成循环。循环不一定错误，但若无退出条件就会持续运行，配置时必须明确。

起始执行段表示从段表中哪一段开始。若从第3段开始，第3段就是本次指令的首段，从全局起始速度进入其目标频率。

## 六、完成方式和后续方式

### 1. 完成方式

信捷手册中，完成方式是在上一段按照上一段频率完成设定数量后，再加减速到当前段频率。

```text
第1段达到自己的频率并完成数量
  -> 段边界
  -> 再变化到第2段频率
```

### 2. 后续方式

后续方式要求上一段数量完成时，频率已经变化到下一段频率。到下一段的过渡被提前安排在当前段后部。

```text
第1段前部按自己的频率运行
  -> 第1段后部向第2段频率变化
  -> 第1段数量完成时已经到第2段频率
```

### 3. 为什么要预加载

后续方式要提前知道下一段编号、方向和频率，还要判断当前段剩余脉冲能否容纳过渡。因此不能等当前段结束后再解析下一段。

项目提前准备一个下一段计划。定时器到边界时只接管已准备的数据，不在10us中断中读取段表或搜索曲线。

方向改变、Wait时间和Wait信号需要真正停止，不能无缝继承。ACT和EXT触发时刻不固定，也可能让已准备计划失效。预加载表示可以提前算，不表示一定无条件接管。

## 七、等待条件

信捷原始PLSR包含脉冲完成、Wait时间、Wait信号、ACT时间、EXT信号、EXT信号或完成。本题将主要业务整理为五种等待类型，完成行为结合类型处理。

### 1. Wait时间

当前段脉冲完成后才开始计时。时间到后进入指定段。

```text
本段完成 -> PWM停止 -> 记录等待起点 -> 等待 -> 启动下一段
```

若从本段开始时计时，长段运行后会把等待时间提前消耗掉，这是错误语义。

### 2. Wait信号

本段完成后检查指定输入。信号已经有效时可以立即进入下一段；无效时保持等待。Wait偏向电平语义，重点是等待阶段它是否有效。

### 3. ACT时间

ACT从本段开始计时。时间到后，不管本段脉冲是否发完，都进入下一段。若脉冲先完成而ACT未到，仍要等待ACT。

ACT说明段结束条件不一定是目标脉冲数。统计只能记录真正输出的脉冲，不能为了凑目标补计数。

### 4. EXT信号

EXT检测外部输入从OFF到ON。信号提前到达时可以提前退出；若本段先发完而EXT未到，则继续等待EXT。

EXT是边沿语义，所以进入新段时要重新记录前一电平，否则上一段残留高电平可能被误判为新边沿。

### 5. EXT信号或脉冲完成

EXT先到就放弃剩余脉冲并进入下一段，脉冲先完成也立即进入下一段，不再等待EXT。

同方向时适合无缝接管。若方向不同，仍要结束输出、改变方向并等待方向延时。

### 6. 需要停到0Hz时为什么使用10Hz

0Hz意味着没有下一个周期，定时器无法输出一个频率为0的PWM。方向切换、Wait时间和Wait信号边界在业务上需要减速到停止，项目以10Hz作为最低可执行边界。完成最后一个10Hz周期后关闭PWM，效果上进入静止。

下一段理论从0开始，实际同样从10Hz开始。不能重新使用全局起始频率，因为全局起始频率只在整条指令开始时使用一次。

## 八、起始速度、终止速度和加减速时间

### 1. 全局起止速度

手册把起始速度定义为指令开始时的频率，终止速度定义为指令结束时的频率。它们不是每一段都重复使用。

```text
整条指令开始：使用全局起始速度
中间段：按发送模式、等待条件和方向衔接
整条指令正常结束：尽量到达全局终止速度
```

最后一段脉冲不足时，曲线可能来不及到达终止速度。应优先保证脉冲总数，按离散计划在可达频率结束，不能为了凑频率额外多发。

### 2. 加减速时间定义斜率

信捷手册明确说明，默认速度和时间共同定义斜率。

```text
加速斜率 = 默认速度 / 加速时间
减速斜率 = 默认速度 / 减速时间
```

默认速度1000Hz、加速时间100ms，表示每增加1000Hz需要100ms。从0加速到5000Hz约需500ms，不是所有加速都固定100ms。

所以“加速时间”更准确地理解为斜率标定时间。每一段实际过渡多久，要根据频率差和斜率计算。

### 3. 时间为0

加速时间为0表示没有加速阶段，直接跃变到较高目标。减速时间为0表示没有减速阶段，直接跃变到较低目标或结束边界。

减速时间为0不只影响最后一段。中间段从高频切到低频也要直接跃变，判断依据是当前频率和目标频率关系。

## 九、三种加减速曲线

### 1. 共同思路

三种曲线都要从起始频率变化到目标频率。输入包括频率边界、斜率和可用脉冲数，输出是每个脉冲边界应使用的频率。

项目按脉冲序号推进，不按任务执行时间推进。低频时一个周期可能大于1ms，高频时1ms内有很多脉冲，按脉冲推进更容易让曲线位置和实际输出对应。

### 2. 直线曲线

直线曲线表示频率随时间按固定斜率变化。

```text
df / dt = a
```

程序在一个周期结束后计算下一频率。当前频率为`f`时，周期约为`1 / f`秒，因此每个脉冲内的频率变化近似为加速度乘当前周期。

规划时还要判断脉冲预算。

| 形状 | 条件 | 结果 |
|---|---|---|
| 梯形 | 加速减速后仍有剩余脉冲 | 达到目标频率并存在匀速区 |
| 三角形 | 无法达到目标频率 | 找到可容纳峰值后立即减速 |
| 单调过渡 | 脉冲很短或边界特殊 | 只向一个方向变化 |

直线逐脉冲模拟精度高，但低频、低斜率和大频差时规划循环可能较长。解析公式可以粗估峰值或数量，最终仍要按离散规则确认，否则计划字段和运行序列会改变。

### 3. S曲线

S曲线不是把频率简单分三段，而是让加速度经历增加、保持和减小。加速与减速镜像组合并配合恒速段，构成七段式过程。

项目采用固定三等分速度比例。`x`是过渡时间占比，`y`是已经完成的频率变化比例。

```text
0 <= x < 1/3       y = 9x² / 4
1/3 <= x < 2/3     y = 3x / 2 - 1/4
2/3 <= x <= 1      y = 1 - 9(1-x)² / 4
```

| x | y约为 |
|---:|---:|
| 0 | 0 |
| 1/6 | 0.0625 |
| 1/3 | 0.25 |
| 1/2 | 0.5 |
| 2/3 | 0.75 |
| 5/6 | 0.9375 |
| 1 | 1 |

中间三分之一是直线，速度对时间的斜率保持不变，也就是加速度保持最大。前后是二次曲线，加速度分别增加和减小。

手册只说明S形速度变化，没有公开信捷固件的逐点公式。因此应表述为项目采用固定比例七段式，不应宣称与信捷内部逐点相同。

### 4. 正弦曲线

正弦曲线通过归一化比例得到平滑变化。100kHz路径不适合反复调用浮点三角函数，因此项目使用归一化查表和线性插值。

```text
计算进度x -> 找左右采样点 -> 按余数插值 -> 得到比例y -> 换算当前频率
```

表格值不是频率，只是0到1的曲线形状。加速和减速共用形状，通过频率差的方向得到上升或下降。

### 5. shapeQ的含义

`shapeQ`不是时间，也不是本次增加频率，而是总频率变化已经完成的比例。

```text
当前频率 = 起始频率 + 总频率差 × shapeQ
```

从1000Hz加速到5000Hz，比例为0.25时，完成4000Hz差值的四分之一，当前频率约2000Hz。

## 十、Q16和64位

### 1. 为什么使用Q16

Q16把低16位作为小数。1表示65536，0.5表示32768。

```text
Q16值 = 实际值 × 65536
实际值 = Q16值 / 65536
```

低斜率或高频下，每个脉冲的变化可能小于1Hz。直接整数除法会得到0，曲线长期不变化。Q16可以累计小数，足够大后再反映到整数频率。

### 2. 为什么中间值使用64位

频率100000本身用32位足够，但两个32位量相乘，或先左移16位再除，可能在除法前超过32位。若此时溢出，最后结果即使落回正常范围也已经错误。

`xQ`最终只在0至65536之间，但形成它的分子可能需要64位。64位主要保护中间运算，不代表实际比例特别大。

### 3. 能不能全部去掉Q16

可以减少运算，但低斜率下会停滞，S曲线和正弦插值会出现明显台阶。更合理的优化是把完整规划放到任务，恒速区只推进序号，只有频率变化时才做定点计算和寄存器换算。

## 十一、uC/OS-II、任务和中断

### 1. 两个应用任务

| 任务 | 工作 |
|---|---|
| Modbus通信任务 | 校验帧、解析功能码、映射寄存器和应答 |
| PLSR控制任务 | 启停、变频、等待、方向、跳转和预加载 |

通信解析、曲线规划和等待不是每个脉冲都必须执行的操作，放在任务中可以阻塞等待信号量，也便于串行修改运动状态。

### 2. UART与T3.5

USART1中断逐字节接收并重启帧间隔定时器。TIM2达到T3.5后通知通信任务，CRC和响应构造在任务中完成。

最后一个字节之后不会再有新接收中断，因此不能把封帧判断只放在“下一个字节到来”时。独立帧间隔定时器能在总线静默时主动确认帧结束。

### 3. 脉冲中断做什么

```text
清中断标志
  -> 本段已发数量和累计值增加
  -> 更新32位位置增量
  -> 推进曲线游标
  -> 频率变化时预装PSC、ARR、CCR
  -> 判断段尾
  -> 接管已准备段或安全停止
```

完整曲线规划、三角峰值搜索、Modbus解析、等待和阻塞操作不能放在每10us热路径中。

### 4. 中断里为什么仍有计算

定时器硬件自行翻转GPIO，中断不模拟高低电平。但逐脉冲曲线和运行中变频要求下一周期参数随实际脉冲序号变化，所以频率变化时必须在边界准备下一组寄存器。

这是边沿同步的必要计算，不等于在中断里规划整段。验收时应区分每脉冲热路径和每段一次冷路径，并用最坏执行时间证明实时性。

## 十二、Modbus地址映射

### 1. 寄存器不是必须存在的数组

Modbus寄存器是协议地址空间。读取`0x1000`时可以从参数结构取值，读取`0x2004`时可以从运行状态接口取值。只要地址、数据宽度和权限符合协议，就不要求内部有同地址数组。

这种映射只保留一份真实数据，避免寄存器数组和业务结构不同步。

### 2. 32位拆成两个16位

项目约定低地址保存32位数低16位，高地址保存高16位。单个Modbus寄存器在RTU帧中仍按高字节先发送。两种字节顺序不能混淆。

### 3. 当前地址

| 区域 | 地址 | 内容 |
|---|---|---|
| 系统参数 | `0x1000`至`0x1013` | 端子、模式、频率和加减速时间 |
| 段表 | `0x1100`起 | 每段频率、脉冲数、等待和跳转 |
| 状态 | `0x2000`至`0x2006` | 累计数、实际频率、状态、段号和错误码 |
| 控制 | `0x3000` | 启动、停止和清累计 |

```text
0x2000至0x2001  32位无符号累计实际脉冲数
0x2002至0x2003  当前实际输出频率
0x2004           运行状态
0x2005           当前段号
0x2006           错误码
```

当前位置没有放在`0x2000`。最终要求的是无符号、正反方向都增加、掉电保持的累计实际脉冲数。

### 4. 运行中修改

运行中可以写参数，但只有当前运行段频率会登记实时变频请求，从当前实际频率和剩余脉冲重新规划。方向、定位模式、段数等修改留到下一次启动，避免半条指令中结构突然改变。

## 十三、Backup SRAM掉电保持

### 1. Flash逐脉冲保存

Flash要先擦除，写入时间长且有寿命限制。累计值最高每秒变化100000次，不适合逐脉冲写Flash。

Backup SRAM由VBAT保持，访问接近普通RAM，不需要擦除，没有Flash擦写寿命问题。缺点是依赖VBAT，电池丢失后数据不能保证。

### 2. 参数记录

参数记录包含Magic、版本、长度、参数和CRC。加载时逐项检查，再检查参数范围。失败时使用默认值。

保存时先使记录无效，写完数据和CRC后最后发布Magic。若中途复位，下次不会把半条记录当作有效参数。

### 3. 累计记录

累计值为32位无符号数，每完成一个实际周期增加一。控制清零命令才清零。记录同时保存反码，用于发现多数半写和位翻转。

32位最大值为4294967295，长期运行最终会回绕。当前需求接受32位，就要明确这个边界。

## 十四、预加载和段边界

### 预加载

当前段只需要知道下一次边界由谁接管。一个预加载槽可以覆盖顺序和指定跳转，代码和RAM开销较小。

预加载更多段并不一定更好。ACT、EXT和运行中变频都会使后续计划失效，缓存越深，重新计算和一致性处理越复杂。

### 包含项

预加载包含实际脉冲数、方向、曲线计划和边界频率，不只是下一频率。中断只接管已确认计划，不重新解析业务参数。
