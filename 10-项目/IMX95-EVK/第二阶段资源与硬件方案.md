# 第二阶段（多任务实验）的资源与硬件落地方案

> 板型：IMX95LPD5EVK-19。软件：RTE 3.3 SD 镜像 + Harpoon，A55 inmate（CPU5）。
> 证据等级：本文的引脚/连接器/权限结论均为**源码确认**（`UM12022` 抽取文本 + `mx95rte.cfg` + MCUXpresso SDK 头），
> 尚**未实机验证**。

## 一句话结论

**第二阶段要求的 LED、按键，不要去找 GPIO 排针 —— 这块 EVK 上没有。**
真正的入口是 **J22 这个已焊的 I2C 排针**：它接的是 `I2C6`，
而 `I2C6` 的控制器和引脚在 SM 配置里都归 A55 非安全域。**一条 I2C 就能同时解决 LED 和按键**
（挂一块 I2C 扩展板）。而**最核心的互斥量 / 优先级反转实验完全不需要任何硬件**。

## 一、板上"用户能插线"的地方（盘点）

先分清两类连接器：**J3 是板对板（SOM↔底板，不是给用户插的）**，下面这些才是用户能碰的。

| 连接器 | 是什么 | 已焊？ | 能不能当 GPIO / 传感器入口 |
|---|---|---|---|
| **J22** | **I2C6 排针，8-pin `SSM-104-L-DV`** | **✅ 已焊** | **★ 最佳入口**。`UM12022` p.60：「Generic I2C header」，3.3 V |
| J20 / J21 | ADC 输入 1x4 排针各一个 | ✅ 已焊 | 接 `ADC_IN[3:0]` / `ADC_IN[7:4]`，可插电位器；`ADC` 在 A55 非安全段是 `OWNER` |
| J38 | SAI3_TXC/SAI3_TXFS 方向跳线，1x2 | ✅ 已焊 | 只有 2 个脚，不通用 |
| J19 | microSD 卡座 | ✅ | **不建议**：RTE 系统就从 SD 启动，拔卡会挂 |
| J24 | M.2 KEY-E 75-pin 卡座 | ✅ | 要插 M.2 卡才有意义；`I2C7`/`SAI3`/`SPI`/`GPIO` 在这里 |
| J25 | PCIe x4 槽 | ✅ | `I2C7` 也引到这里 |
| J27 | 音频板 2x49 排针 | ✅ | SAI3 音频，不通用 |
| J29 | SMI debug 3-pin | ✅ | MDIO |
| **J37** | 1x4，`M2_GPIO1/2/3_RSVD` + GND | ❌ **未焊（DNP）** | 本来最像 GPIO 排针，可惜没焊 |
| **JP1** | SPI7 1x6 排针 | ❌ **未焊（DNP）** | 同上 |
| J11 / J12 / J28 | 以太网 RJ45 / 60-pin / 10G RJ45 | ✅ | 网络 |
| J13–J16 | Mini-SAS（MIPI CSI/DSI/LVDS） | ✅ | 摄像头/显示 |
| J10 | 扬声器 4-pin | ✅ | 音频 |

**结论：真正"能插杜邦线、而且总线在 A55 域"的只有 J22（I2C6）和 J20/J21（ADC）。**

## 二、为什么 J22 能直接用：引脚和权限都对得上

### 2.1 J22 用的是 I2C6

`UM12022` p.60 表：「`I2C6` → I2C header (J22) → Generic I2C header，3.3 V」。
同一个 I2C6 还挂着 `PCAL6416A (U88, 0x21)` 和音频板连接器 J27，**是共享总线**，
所以插模块时要避开已占用的地址。

### 2.2 I2C6 的引脚就是 GPIO_IO02 / GPIO_IO03

`UM12022` §2.5 原文：

```text
• I2C6_SDA and I2C6_SCL signals are muxed with GPIO_IO02 and GPIO_IO03 signals, respectively
```

SDK 里对应的复用枚举（`hal_pinctrl_platform.h:72,79`）：

```c
HAL_PINCTRL_PLATFORM_IOMUXC_PAD_GPIO_IO02__LPI2C6_SDA   0x443C0018, 0x06, 0x443C051C, 0x00, 0x443C021C
HAL_PINCTRL_PLATFORM_IOMUXC_PAD_GPIO_IO03__LPI2C6_SCL   0x443C001C, 0x06, 0x443C0518, 0x00, 0x443C0220
```

（mux 值 **0x06**；同一根脚 mux 0x00 就是 `GPIO2_IO2` / `GPIO2_IO3`，和 IO14/15 同一个 bank。）

### 2.3 控制器和引脚在 SM 层都归 A55 非安全域

`mx95rte.cfg` 的 **A55 non-secure 段（526 行起）**：

| 行 | 内容 | 意思 |
|---|---|---|
| 750 | `LPI2C6 OWNER` | 控制器归本域 |
| 915 | `PIN_GPIO_IO02 OWNER` | 引脚 IOMUX 归本域 |
| 916 | `PIN_GPIO_IO03 OWNER` | 同上 |
| 746-752 | `LPI2C2..LPI2C8 OWNER` | 所有 I2C 都归本域 |
| 754-761 | `LPSPI1..LPSPI8 OWNER` | 所有 SPI 都归本域 |
| 581 | `ADC OWNER` | ADC 归本域 |
| 911-948 | `PIN_GPIO_IO00..IO37 OWNER` | **几乎所有 GPIO_IO 脚都归本域**（只有 IO14/15 是 `ACCESS`） |

**所以 I2C6 在 SM 这一层不需要改。** 和 GPIO2 那次一样，只要补 cell 和一级页表两处。

### 2.4 关键地址

| 外设 | 基地址 | 中断号 |
|---|---|---|
| **LPI2C6** | **0x426C0000** | **214** |
| LPI2C7（M.2/PCIe） | 0x426D0000 | 215 |
| LPSPI7（JP1，未焊） | 0x42710000 | 211 |
| ADC（J20/J21） | 0x44530000 | — |

## 三、LED 和按键怎么办：四个方案

### 方案 A：全部虚拟到 PC 串口（零硬件，已实测）

| 计划里的东西 | 替代成 | 已实测证据 |
|---|---|---|
| LED 闪烁任务 | 往 `GPIO_IO14` 位翻转 / 或直接 `printf` | `[[GPIO-TX]] ...` 能被 PC 收到 |
| 按键检测任务 | UART 收到的字符（PC 敲键） | `samples==0 : 2768`、`edges : 84` |
| 传感器 | **SCMI 读板载温度**（见方案 E） | 权限已有 |

- 优点：**现在就能做**，不接线、不碰借来的板子；而且"多个任务抢同一个串口"正好就是
  计划第 3 条互斥量实验要保护的资源，**天然贴合**。
- 缺点：不是物理灯/键，给别人演示不够直观。

### 方案 B：J22 挂一块 I2C 扩展板（真硬件，推荐）

一块 `PCF8574` / `PCA9554` 之类的 I2C 扩展板（几块钱），**8 个 I/O 同时当 LED 和按键**，
从 J22 引 4 根线（3V3 / GND / SDA / SCL）即可。

- 需要先打通 I2C6（见第四节）
- **地址要避开已有的 0x21（PCAL6416A U88）**
- 好处：LED 和按键一次解决，而且顺带把"用 I2C 接外设"这条主线做了

### 方案 C：从 J3 的 42/44 脚飞线（不推荐）

`GPIO_IO14/15` 在 J3（板对板）的 42/44 脚上。要拆开 SOM 和底板，连接器很密，
**板子是借的，不建议**。

> 更靠谱的线索：**用户手上有 EVK 原理图**（`C:\Users\chen\Desktop\资料\IMX95_19_19_EVK\`）。
> 在原理图里搜 `UART3_TXD` / `UART3_RXD`，看这两根线上有没有**测试点（TP）**或可焊的 0 Ω 电阻。
> 有的话就是最干净的"真接线"路径。**这一步还没做。**

### 方案 D：先实测 D24 / D25 是不是这两个脚的指示灯（零成本，建议顺手做）

`UM12022` Table 6：D24 = "UART3 data transmitted to host computer"、D25 = "…received…"，
而正文注明 `UART3 TXD/RXD` 就复用在 `GPIO_IO14/15`。

**如果这两颗灯是 SoC 侧驱动的，那你就白得两个 LED** —— 位翻转 `GPIO_IO14` 就能让 D24 闪。
**目前是推测，未证实。** 验证方法：跑 `[3]` 位翻转那一段，盯着 D24 看有没有闪。
（另一个判据：串口空闲时 TXD 是高电平，D24 应该常亮或常灭——看开机时常亮还是灭。）

### 方案 E：传感器用 SCMI 读温度，不用 I2C

`mx95rte.cfg` A55 non-secure 段里已经给了权限：

```text
555  BRD_SM_SENSOR_TEMP_PF09   ALL     <- PMIC 温度
576  SENSOR_TEMP_ANA           SET     <- 模拟温度传感器
```

SDK 里 `scmi_sensor.c` 已经编进应用了。**这是真数据，不是模拟的，而且不需要插任何东西。**
计划第 2 条要的"温度值 + 时间戳 + 状态码"完全可以这么来。

## 四、要新增一个外设：改哪几处（GPIO2 那次已经验证过的套路）

加 GPIO2 时实机确认的结论是：**SM 层往往本来就放行，只要补两处**。加 I2C6 同理：

```text
① SM 资源表（TRDC/RDC）  —— 不用改。mx95rte.cfg 里 LPI2C6 / PIN_GPIO_IO02/03 都是 OWNER
② jailhouse cell（stage-2）—— 要加：phys=0x426C0000 size=0x10000 flags=0x0013 (R|W|IO)
                              中断 214 要加进 irqchip 位图（I2C 要中断的话）
③ inmate 一级页表（stage-1）—— 要加：MMU_REGION_FLAT_ENTRY("LPI2C6", LPI2C6_BASE, KB(64), ...)
                              放在应用自己的 boards/imx95lpd5evk19/app_mmu.h 里
④ 引脚复用             —— 经 SCMI 请求 GPIO_IO02->LPI2C6_SDA、GPIO_IO03->LPI2C6_SCL
```

工具现成：`build\tools\cell_add_gpio.py` 改一下 `NEW_REGIONS` 就能生成带 I2C6 的 cell。

**不用改公共文件**（`mmu.c`、`board.c`、`flags.cmake` 都不动）。

## 五、第二阶段计划的可落地改写

计划里最难的两条（LED、按键）用上面方案解决之后，逐条映射：

| 计划原文 | 怎么落 |
|---|---|
| LED 闪烁任务，不同优先级，验证抢占 | **用 `GPIO_IO14` 翻转**（PC 端当"LED"，或方案 B/D 的真灯）。**抢占的量化证据**建议配合 TPM2 计时（cell 里已有 TPM2 + IRQ 62），或打开 `configGENERATE_RUN_TIME_STATS` | 
| 按键检测任务，扫描 + 消抖 | **UART 收到的字符就是"按下"**；消抖改成"同一个键 200 ms 内只算一次"。或用方案 B 的真按键 |
| 传感器采集任务，I2C/SPI 读温度 | **两条路**：`SCMI 读温度`（零硬件，推荐先做）／`I2C6 + J22 挂温度模块`（真 I2C） |
| 控制台命令任务，UART 收字符串 | 现成的（LPUART3 + 我们有轮询收的代码） |
| 每任务独立栈 + 栈溢出检测 | `xTaskCreate` 给不同栈深 + `configCHECK_FOR_STACK_OVERFLOW=2` + `vApplicationStackOverflowHook` |
| 空闲任务 + `vApplicationIdleHook` | 直接做；顺便观察 idle 占比 |
| `uxTaskGetSystemState` 打印任务信息 | 直接做（任务名/优先级/剩余栈 `usStackHighWaterMark`） |
| 按键 → 二进制信号量 → 触发采集 | 直接做 |
| 采集数据结构体 → 消息队列 → 控制台任务 | 直接做（温度值+时间戳+状态码） |
| 事件组管全局状态（3 个事件位） | 直接做 |
| **禁止全局裸变量跨任务传数据** | 直接做 |
| 共享资源 UART 打印 + 互斥量 | 直接做 |
| **构造优先级反转 + 对比优先级继承** | **直接做，不需要任何硬件** ← 这是本阶段最有价值的一条 |

**一句话：第 3 组（互斥量 / 优先级反转）现在就能做；第 1、2 组只要把"LED/按键"换成串口或 I2C 扩展板就能做。**

### 一个要注意的冲突

`GPIO_IO15` 和 `LPUART3_RX` 是**同一根脚**，不能同时当"GPIO 按键"和"串口收"。
所以"按键任务"和"控制台任务"**不能各读一个物理输入**。建议：

```text
一个 UART RX 任务（唯一读 LPUART3 的任务，生产者）
   ├── 每个字节当一次"按键按下" -> 消抖 -> xSemaphoreGive(bin_sem)
   └── 攒成整行 -> 放进 queue -> 控制台命令任务解析
```

这样既是唯一读取者，又正好把"队列/信号量"用起来。

## 六、还没确认的

1. `J22` 的 8 个脚具体哪个是 3V3 / GND / SDA / SCL —— `UM12022` 的表里没有 J22 逐脚定义，
   要查 **EVK 原理图**（用户手上有）。
2. I2C6 上已挂 `PCAL6416A @0x21`，插模块要避开的完整地址表 —— 查 `UM12022` §2.5 的 I2C 设备表。
3. D24/D25 是 SoC 侧驱动还是 FT4232H 侧驱动 —— 实测（方案 D）。
4. 原理图上 `UART3_TXD/RXD` 有没有测试点 —— 查原理图。
5. **ADC 的引脚权限**：`ADC` 控制器在 A55 非安全段是 `OWNER`，但权限表里**没有 `PIN_ADC_*` 条目**，
   要试才知道能不能用 J20/J21。
