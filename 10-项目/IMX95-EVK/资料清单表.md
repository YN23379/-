### 最容易搞混的一对：UM12527 vs UM12022

> ⚠️ **2026-09-21 记录一次真实踩坑**：曾把 `UM12022`（EVK 手册）里 "J22 是 I2C 排针、J22 只引出 UART1/2/7"
> 的说法套到 Pro 板上，得出"LPUART3 没引出所以看不到输出"的**错误结论**。
> 两块板的 J22 **完全是两个东西**：

| 手册 | 对应板子 | 调试口器件 | J22 是什么 | 调试串口怎么出去 |
|---|---|---|---|---|
| **UM12527** | **FRDM-IMX95-PRO**（**我们的板**） | **CH9114F (U67)** | **USB Type-C 调试口** | 三个核共用这**一个 Type-C**，电脑认出 4 个 COM 口 |
| **UM12022** | IMX95LPD5EVK-19（**不是**我们的板） | FT4232H (U70) | **8-pin I2C 排针** | 走 FT4232H 的 UART 通道 |

**UM12527 §2.19 原文要点**：
- CH9114F 是**四通道** USB 转串口（通道 0/1/2/3），A55、M33、M7 各占一个
- 电脑上会数出 **4 个 COM 口**；官方**建议四个都打开**，因为 A55/M33/M7 的端口映射**不固定**
- 终端参数：115200 / 8 / None / 1

**推论**：**J22 没有裸针脚可夹**，逻辑分析仪要夹的是 **J15**（2×20 EXPI 排针，UM12527 §2.20，官方写明"可用于访问各种引脚"）。

## 三、Harpoon 用户指南（HRPNUG_3.3 / UG10170）确认了什么

这份文档到手后，此前靠实机跑才推出来的几件事得到了**官方确认**，同时**推翻了一个猜测**：

| 事项 | 之前的认知 | 用户指南的说法 | 结论 |
|---|---|---|---|
| **官方支持的板子有哪些** | 只知道包名是 `imx95-19x19-lpddr5-evk` | §3.1 支持清单：i.MX 8M Mini EVKB / 8M Nano EVK / 8M Plus EVK / i.MX 93 EVK / **i.MX 95 15x15 LPDDR4x EVK** / **i.MX 95 19x19 LPDDR5 EVK** | **确认 FRDM-IMX95-PRO 不在官方支持清单里**（只有两款 EVK） |
| **给 inmate 分几个核** | 实测是 1 个核（CPU5） | §1.4：`For i.MX 95, CPU core 5 is assigned to the cell: .cpus = { 0b100000, }` | **官方就是 1 个核（CPU5）**，与实测**完全一致**；周报里"两个核"是早期规划，不是官方配置 |
| **能不能用 2 个核** | 不确定 | §1.4：`For a multicore (SMP) cell, two cores can be used. For instance, on i.MX 8M: .cpus = { 0b1100, }` | 可以（SMP cell），但**官方举例只给了 i.MX 8M**；i.MX95 要给 2 核需自己改 `.cpus` 位图并重编 cell |
| **LPUART 归谁用** | 实测推出"LPUART3 不归 Linux 域" | §1.5：`Harpoon provides a custom System Manager configuration that describes the hardware used for its applications, such as the TPM and LPUART usage for its guest cell.` | **官方明确 SM 配置里专门描述了给 guest cell 用的 LPUART**。所以要改 console，**要改的是 SM 配置 + cell 配置两处**，不只是 cell |
| **cell 配置源码在哪** | 从 git 仓库猜的 | §1.4 给出**确切路径**：`configs/arm64/imx{8m*,93,95}-harpoon-freertos.c` 在 **Harpoon meta-layer 的 Jailhouse recipe 补丁里** | **确认了改 cell 的确切文件**：要改的是 `imx95-harpoon-freertos.c` |
| **应用源码怎么拉** | 只知道仓库地址 | §6.2：`west init -m https://github.com/NXP/harpoon-apps --mr harpoon_3.3.0 hww` | **给了准确命令和 tag**（`harpoon_3.3.0`） |
| **启动 Linux 的正确方式** | 自己拼的 `setenv jh_root_mem` + `run bsp_bootcmd` | §4.2：官方是 `setenv jh_root_dtb imx95-19x19-evk-harpoon.dtb` + **`run jh_mmcboot`** | **官方用 `jh_root_dtb` + `jh_mmcboot`**；我们手工设 `jh_root_mem`/`jh_clk` 是因为**没有 Pro 板对应的 `-harpoon.dtb`** |
| **跑应用的正确方式** | 手敲 `jailhouse cell create/load/start` | §4.3/§4.6：`harpoon_set_configuration.sh freertos latency` + **`systemctl start harpoon`** | 官方走 systemd 服务；我们手敲是等价的，但官方方式会自动配对 RPMsg |
| **启动配置持久化** | 以为只能每次重设 | §4.2 注：`setenv bootcmd 'run jh_mmcboot'` + **`saveenv`** 即可持久 | **官方给了持久化方法**（前提是环境区可写；本板环境区 CRC 损坏，见开发日志） |

### 两个直接可用的官方结论

1. **核数没问题**：官方 i.MX95 就是 **CPU5 单核**给 inmate。**你现在的复现结果和官方定义一致，不用改。**
   要 2 核是**额外需求**，得自己改 `.cpus = { 0b110000, }` 并重编 cell。
2. **无输出的排查方向要修正**：不是"换根线接上就行"。官方 §1.5 明说 **LPUART 的分配写在 Harpoon 定制的 SM 配置里**
   （`Harpoon provides a custom System Manager configuration ... such as the TPM and LPUART usage for its guest cell`）。
   而 **EVK 的 SM 配置和 Pro 板的不是同一份**，所以 LPUART3 在 Pro 板上不归 Linux 域。
   → 要解决得**同时改 SM 配置和 cell 配置**，或**问 NXP 要 Pro 版的 SM 配置 + cell**。

### §4.3 给出的官方预期输出（对照用）

官方文档说跑 `hello_world` 时，**inmate cell console** 上应看到：

```text
INFO: hello_func            : Hello world.
tic tac tic tac ...
```

**这句话是"应该有输出"的官方依据** —— 也就是说我们看不到输出**确实是异常状态**，不是设计如此。
