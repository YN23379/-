# SAM9X60 培训提问清单（2026-09-23 14:00–16:00）

> 场合：Microchip 培训，内容包括 SAM9X60 板卡介绍、Microchip MPU Linux 启动流程、
> MGS 图形工具、LCD demo，最后一项是"当前项目技术问题沟通交流"。
> 我们部门 5 个新人参加，老大指定要问**多核架构**。
>
> **本文的"预期答案"是公开资料层面的判断，置信度已标注；提问的目的就是让对方确认或纠正。**

## 零、开场前自己先记住的两件事

**① 我们手里是什么**

i.MX95（FRDM-IMX95-PRO / IMX95 19x19 EVK）：**6×Cortex-A55 + 1×Cortex-M33（AON 域跑 System Manager）+ 1×Cortex-M7** 。
我们现在做的事：用 **Jailhouse** 把 A55 静态分区（CPU5 单独给一个 inmate），
用 **SM 的 TRDC/RDC** 管"哪个域能用哪个外设"，用 **SCMI** 让 Linux/inmate 请 SM 代配时钟和引脚。
**这是一套"硬件级、启动时就定好"的隔离，不是软件约定。**

**② SAM9X60 大概是什么**

| 项 | 预期 | 置信度 |
|---|---|---|
| 核 | **单核 ARM926EJ-S**（ARMv5TEJ，最高 600 MHz） | 高 |
| MMU | 有 → 能跑 Linux | 高 |
| **TrustZone** | **没有**（TrustZone 从 ARMv6K / ARMv7-A 才有） | 高 |
| **虚拟化扩展（EL2 / stage-2）** | **没有** → 跑不了 Jailhouse 这类 Type-1 hypervisor | 高 |
| 安全启动 | 有 ROM code 安全启动 + OTP + 加密引擎 | 中（有 NXP 之外的官方 AN 佐证） |
| 多核版本 | Microchip 的多核在别的系列（SAMA5D4、SAMA7、PIC64GX、PolarFire SoC） | 中 |

**如果②成立，那么"资源隔离/权限分配"这件事在 SAM9X60 上和 i.MX95 完全不是一个层次** ——
i.MX95 有硬件分区，SAM9X60 只有 Linux 的 MMU（进程隔离）。**这就是要问清楚的核心。**

## 一、必问（5 条，按这个顺序问）

| # | 问题（一句话） | 想问出什么 | 预期答案 |
|---|---|---|---|
| **1** | **SAM9X60 是单核还是多核？** | 一句话定调。是单核的话后面所有"隔离"问题都要换问法 | 单核 ARM926EJ-S @600 MHz |
| **2** | **它有没有 TrustZone，有没有虚拟化扩展（EL2）？** | 直接决定"能不能做硬件分区" | 都没有 |
| **3** | **那 SAM9X60 上，外设的归属和权限是谁在启动时定的？有没有类似 TRDC/RDC 的硬件过滤器？** | 这是**权限分配**的关键。没有硬件过滤器，就只能靠 Linux 驱动不加载 | 没有；靠设备树 + 驱动不加载 |
| **4** | **Microchip 这边要做"多核 + 硬隔离"，对应的是哪颗片子？有没有能跑 Type-1 hypervisor 的？** | 选型问题。SAMA5D4 / SAMA7G5 / PIC64GX / PolarFire SoC 里哪个是真异构多核 | 让对方点名具体型号 |
| **5** | **单核上如果同时要 Linux 和实时任务，Microchip 推荐哪条路？** | RT 需求怎么落。是 PREEMPT_RT、Xenomai，还是外挂协处理器 | 让对方给具体方案名 |

## 二、对比我们现有方案（3 条，第 5 项交流环节问）

| # | 问题 | 想问出什么 |
|---|---|---|
| **6** | **我们现在是 A55 上跑 FreeRTOS 当 inmate，用 Jailhouse 做静态分区，SM 的 TRDC/RDC 管权限、SCMI 做跨域代配。这套东西在 SAM9X60 上有没有对应物？** | 把我们的方案整条摆出来，看对方能不能一一对上。**对不上就说明层次差一档** |
| **7** | **SAM9X60 上"一个外设只给一个域用"这件事，是在启动时定，还是运行期还能改？** | i.MX95 是**启动时 SM 就配好 TRDC/RDC**，改要重烧启动容器。想知道 SAM9X60 的粒度 |
| **8** | **我们的实时指标是中断延迟 <1 µs、任务调度延迟 ~2 µs，SAM9X60 + Linux 能到什么量级？** | 拿数据对比。ARM926 600 MHz 的单核，和 A55 1.7 GHz 差得远 |

## 三、围绕培训内容顺手问（3 条）

| # | 问题 | 想问出什么 |
|---|---|---|
| **9** | **SAM9X60 从复位到 Linux 起来的完整链条是什么？每一段是谁在跑？** | 预期 ROM code → AT91Bootstrap → U-Boot → kernel。对方讲"Linux 启动流程"时会讲这一段，**但通常不讲"谁在什么时候把外设权限定下来"**，所以要主动追问 |
| **10** | **启动过程中，外设的时钟和引脚是谁配的？有没有一个中间层固件专门管这个？** | i.MX95 是 **SM（跑在 AON M33 上）** 管，Linux 通过 SCMI 请求。SAM9X60 单核上应该没有这一层 |
| **11** | **MGS 在 Linux 侧走 DRM/KMS 还是 Framebuffer？图形负载和实时任务抢资源时怎么保证实时性？** | 顺带问，但对我们"实时性"这条线有用 |

## 四、一个额外想问的（我们自己踩过的坑）

| # | 问题 |
|---|---|
| **12** | **SAM9X60-EK 板上有可以直接插线的 GPIO 排针/按键/LED 吗？** |

> 我们手里的 IMX95 19x19 EVK **没有任何用户 GPIO 排针、没有用户 LED、没有用户按键**，
> 唯一能插线又在 A55 域内的只有 `J22`（I2C6）和 `J20/J21`（ADC）。
> 害得我们做 GPIO 实验只能用 PC 串口当负载。**问一下 Microchip 的板子在这点上是什么情况**，
> 对我们后续选型有参考价值。

## 五、提问时的两条原则

1. **不要问"哪个更好"**，要问 **"机制上有没有对应物"**。
   问"哪个更好"只会得到场面话；问"你们有没有硬件级的区域过滤器"才有信息量。
2. **先问 1、2 定调，再问 3、4 挖机制，最后问 5–8 做对比。**
   如果对方答出 SAM9X60 是单核且没有 TrustZone，那"资源隔离"这个话题在 SAM9X60 上就已经结束了，
   直接跳到第 4 条问**哪颗片子能做**，不要纠缠。
