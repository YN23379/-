## 一、Modbus概述

Modbus是一种工业通信协议，最早用于控制器之间的数据交换。它的核心思想是：主站发起请求，从站按照请求访问自己的数据区，然后返回应答。Modbus本身只规定通信双方如何组织报文、如何表示地址、如何读写数据和如何处理异常，并不规定具体设备内部必须怎样存储变量。

Modbus常见形式有三种：Modbus RTU、Modbus ASCII和Modbus TCP。三者使用相近的数据模型和功能码思想，但外层封装、帧边界和校验方式不同。学习时应先抓住“PDU、ADU、主从事务、数据模型、功能码”这些共同概念，再分别理解RTU、ASCII和TCP的差异。

| 方式 | 典型传输介质 | 编码方式 | 帧边界 | 校验方式 | 主要特点 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Modbus RTU | 串口，常用RS-485 | 二进制 | 字符间静默时间 | CRC-16 | 效率高，工业现场最常见 |
| Modbus ASCII | 串口，常用RS-485 | ASCII十六进制字符 | `:`开始，CRLF结束 | LRC | 可读性较好，效率低 |
| Modbus TCP | 以太网/TCP | TCP中承载二进制PDU | MBAP长度字段和TCP字节流 | 不使用RTU CRC | 适合以太网和多客户端场景 |

注意事项：

- RTU和ASCII通常跑在串行链路上，TCP跑在以太网上；
- 三种方式不能直接混用报文外壳，例如RTU报文不能原样发到Modbus TCP端口；
- Modbus TCP不带RTU的CRC，因为TCP链路层和传输层已经提供差错检测与可靠传输机制；
- TCP是字节流协议，一个TCP包不等于一条Modbus报文，解析时要依靠MBAP中的长度字段。

## 二、主站、从站和事务

Modbus采用主从式通信。主站负责主动发送请求，从站负责被动等待请求并返回结果。从站在没有收到请求时不能主动发送业务数据。一次完整的“请求 -> 处理 -> 应答”称为一次事务。

| 角色 | 主要职责 |
| :--- | :--- |
| 主站 | 发起请求、等待应答、判断超时、重试或上报错误 |
| 从站 | 接收请求、校验报文、访问数据区、组织正常应答或异常应答 |
| 事务 | 一次完整读写过程，包括请求帧和对应应答帧 |

单播是主站向某一个从站地址发送请求，地址匹配的从站处理并应答。广播使用从站地址`0`，主要用于写操作，所有从站可以执行，但不允许任何从站返回应答，否则多个从站同时发送会造成总线冲突。广播读请求没有实际意义，一般不执行也不应答。

从站地址字段占1字节，理论数值范围是`0~255`，但Modbus规定：

| 地址范围 | 含义 |
| :--- | :--- |
| `0` | 广播地址 |
| `1~247` | 普通单播从站地址 |
| `248~255` | 保留地址 |

因此常说“Modbus最多支持247个从站”，指的是协议可寻址的普通从站地址最多有247个，不代表一条RS-485总线一定能物理连接247台设备。实际数量还受收发器负载、总线长度、分支长度、终端电阻、接地和现场干扰影响。

注意事项：

- 从站地址和数据地址是两件事，从站地址决定访问哪台设备，数据地址决定访问设备内部哪个对象；
- 同一总线上的从站地址必须唯一；
- 主站发送请求后，应等待本次事务结束或超时后再发下一帧；
- “通信成功”应以收到正确应答为准，不能只看某个本地计数是否变化。

## 三、modbus对象

Modbus把从站内部数据抽象为四类对象。对象类型决定数据宽度、读写权限和常用功能码。

| 对象区 | 英文名称 | 数据宽度 | 访问权限 | 常用功能码 |
| :--- | :--- | :--- | :--- | :--- |
| `0X` | Coil | 1位 | 可读写 | `0x01`读，`0x05`写单个，`0x0F`写多个 |
| `1X` | Discrete Input | 1位 | 只读 | `0x02`读 |
| `3X` | Input Register | 16位 | 只读 | `0x04`读 |
| `4X` | Holding Register | 16位 | 通常可读写 | `0x03`读，`0x06`写单个，`0x10`写多个 |

`0X`和`1X`都是位对象，但`0X`可读写，`1X`只读。`3X`和`4X`都是16位寄存器，但`3X`只读，`4X`通常可读写。这里的“通常”表示协议模型允许这样使用，具体设备仍然可以把某些地址设计为只读、只写、不可访问或厂家专用。

Modbus协议中的起始地址从`0`开始。例如读取保持寄存器起始地址`0`，表示读取该设备保持寄存器区的第一个寄存器。

注意事项：

- 协议地址从0开始，设备说明书或组态软件可能从1显示，使用前必须确认是否存在偏移；
- 32位整数、浮点数通常需要占用两个连续16位寄存器，还要约定字顺序；
- Modbus标准没有`2X`对象区，看到`2X`时应按厂家扩展处理。

## 四、PDU和ADU

PDU是Protocol Data Unit，表示与具体传输方式无关的协议数据单元。它由功能码和功能数据组成。

ADU是Application Data Unit，表示放到某种传输方式中发送的完整报文单元。不同Modbus形式的ADU不同。

| 形式 | PDU组成 | ADU组成 |
| :--- | :--- | :--- |
| RTU | 功能码 + 功能数据 | 从站地址 + PDU + CRC |
| ASCII | 功能码 + 功能数据 | `:` + 地址 + PDU + LRC + CRLF |
| TCP | 功能码 + 功能数据 | MBAP Header + PDU |

Modbus规定PDU最大长度为253字节。RTU的ADU最大长度为256字节：

```text
1字节从站地址 + 最多253字节PDU + 2字节CRC = 256字节RTU ADU
```

注意事项：

- PDU不包含RTU从站地址，也不包含RTU CRC；
- RTU、ASCII、TCP可以使用相同功能码思想，但ADU封装不同；
- 分析功能码数量上限时，经常要回到PDU最大253字节这个限制；
- 设备实际支持的数据区大小可以小于协议上限，协议上限不等于设备容量。

## 五、Modbus RTU报文

Modbus RTU使用二进制报文，基本格式如下：

```text
请求/应答：
从站地址 + 功能码 + 功能数据 + CRC低字节 + CRC高字节
```

| 字段 | 长度 | 说明 |
| :--- | :--- | :--- |
| 从站地址 | 1字节 | 指定接收请求的从站，`0`表示广播 |
| 功能码 | 1字节 | 指定读写类型 |
| 功能数据 | 变长 | 起始地址、数量、字节数或具体数据 |
| CRC | 2字节 | CRC-16校验，低字节先发送 |

RTU没有固定开始符和结束符，而是依靠字符之间的静默时间划分帧。标准规定：

| 时间 | 含义 |
| :--- | :--- |
| `t1.5` | 同一帧内两个字符之间的最大允许间隔，超过后该帧可能无效 |
| `t3.5` | 两帧之间至少需要的静默间隔，用于判断一帧结束和下一帧开始 |

在较低波特率下，`t1.5`和`t3.5`按字符时间计算；在较高波特率下，常采用固定时间。一个字符时间不仅包含8个数据位，还包含起始位、校验位和停止位。例如`19200, 8-N-1`时，一个字符共有10位：

```text
1起始位 + 8数据位 + 1停止位 = 10 bit
19200 bit/s ÷ 10 bit/字符 = 1920字符/秒
1个字符时间约为0.52 ms
```

波特率表示每秒传输多少个符号，比特率表示每秒传输多少个bit。在普通UART二进制传输中，一个符号通常承载1 bit，所以数值常常相同，但概念并不完全相同。



**Modbus RTU 一帧的最大长度是 256 字节**，包含：

```
从站地址(1) + 功能码(1) + PDU(N) + CRC(2) = 256 字节
```

因此，**PDU 部分最大只能是 253 字节**。



注意事项：

- 主从双方的波特率、数据位、校验位、停止位必须一致；
- RTU帧边界靠静默时间判断，不能收到一个字节就立即当成完整帧；
- 接收缓冲区溢出、帧间隔异常、CRC错误时应丢弃当前帧；
- 寄存器地址、数量和寄存器值按高字节在前发送，CRC按低字节在前发送，这两个顺序最容易写反。

## 六、CRC-16校验

Modbus RTU使用CRC-16校验传输错误。常用算法初始值为`0xFFFF`，多项式的反转形式为`0xA001`。CRC计算范围包括从站地址、功能码和功能数据，不包括CRC字段本身。

```text
crc = 0xFFFF
对报文中每个待校验字节：
  crc = crc ^ byte
  重复8次：
    如果crc最低位为1：crc = (crc >> 1) ^ 0xA001
    如果crc最低位为0：crc = crc >> 1
```

发送时CRC低字节在前，高字节在后。例如计算结果为`0x4B37`，RTU帧末尾发送顺序是`37 4B`。

注意事项：

- CRC错误说明报文内容不可信，从站应静默丢弃，不返回异常应答；
- CRC不包括最后两个CRC字节本身；
- CRC字节顺序与寄存器数据字节顺序不同；
- 排查CRC问题时，应先用已知标准报文核对计算结果，再分析通信链路。

## 七、常用功能码

### 1. `0x01`读取线圈

`0x01`用于读取一组连续线圈。请求包含起始地址和读取数量，应答把线圈状态按位打包返回。第一个线圈放在第一个数据字节的bit0，第二个线圈放bit1，依次类推。

```text
请求PDU：01 起始地址Hi 起始地址Lo 数量Hi 数量Lo
应答PDU：01 字节数 线圈位数据...
```

数量范围为`1~2000`。下限为1，因为读取0个线圈没有意义。上限为2000，是协议对单次读取线圈的规定上限。2000个线圈按位打包需要`ceil(2000/8)=250`字节，应答PDU长度为：

```text
功能码1字节 + 字节数1字节 + 数据250字节 = 252字节
```

该长度没有超过253字节PDU上限。

### 2. `0x03`读取保持寄存器

`0x03`用于读取一组连续保持寄存器。每个保持寄存器为16位，应答中每个寄存器按高字节、低字节顺序返回。

```text
请求PDU：03 起始地址Hi 起始地址Lo 数量Hi 数量Lo
应答PDU：03 字节数 寄存器1Hi 寄存器1Lo ...
```

数量范围为`1~125`。下限为1，是因为读取0个寄存器没有意义。上限为125，原因是125个寄存器需要250字节数据，应答PDU长度为：

```text
功能码1字节 + 字节数1字节 + 125*2字节数据 = 252字节
```

数量合法不代表地址一定合法。设备还必须检查`起始地址 + 数量 - 1`是否落在自己的实际保持寄存器范围内。

### 3. `0x0F`写多个线圈

`0x0F`用于写入一组连续线圈。请求中除了起始地址和数量，还包含字节数和按位打包后的线圈数据。成功应答不回传具体写入数据，只回显起始地址和数量。

```text
请求PDU：0F 起始地址Hi 起始地址Lo 数量Hi 数量Lo 字节数 线圈位数据...
应答PDU：0F 起始地址Hi 起始地址Lo 数量Hi 数量Lo
```

数量范围为`1~1968`。下限为1。上限1968是Modbus规范对该功能码规定的单帧写入上限。1968个线圈需要`1968 / 8 = 246`字节数据，请求PDU长度为：

```text
功能码1字节 + 起始地址2字节 + 数量2字节 + 字节数1字节 + 数据246字节 = 252字节
```

字节数字段必须等于`(数量 + 7) / 8`，并且字节数字段还必须等于后续实际线圈Data长度。写入前应先完整检查数量与Byte Count、Byte Count与实际Data长度、地址范围，全部合法后再执行写入，避免错误请求已经改变从站状态。

### 4. `0x10`写多个保持寄存器

`0x10`用于写入一组连续保持寄存器。请求中每个寄存器值按高字节、低字节排列。成功应答只回显起始地址和数量。

```text
请求PDU：10 起始地址Hi 起始地址Lo 数量Hi 数量Lo 字节数 寄存器数据...
应答PDU：10 起始地址Hi 起始地址Lo 数量Hi 数量Lo
```

数量范围为`1~123`。下限为1。上限为123，原因是请求PDU中除了寄存器数据，还必须放起始地址、数量和字节数字段：

```text
功能码1字节 + 起始地址2字节 + 数量2字节 + 字节数1字节 + 123*2字节数据 = 252字节
```

如果写124个寄存器，请求PDU长度为`1 + 2 + 2 + 1 + 248 = 254`字节，超过253字节PDU上限。

0x10写请求也有两层长度关系：Byte Count必须等于`数量*2`，后续实际寄存器Data长度必须等于Byte Count。站号和CRC正确但任意一层不一致时，属于非法数据值并返回异常`03`。



### 5. 功能码数量限制

| 功能码 | 操作 | 数量范围 | 上限依据 |
| :--- | :--- | :--- | :--- |
| `0x01` | 读线圈 | `1~2000` | 协议规定；线圈按位打包，应答PDU不超过253字节 |
| `0x03` | 读保持寄存器 | `1~125` | 125个寄存器应答数据为250字节，应答PDU为252字节 |
| `0x0F` | 写多个线圈 | `1~1968` | 协议规定；1968个线圈请求数据为246字节，请求PDU为252字节 |
| `0x10` | 写多个保持寄存器 | `1~123` | 123个寄存器请求PDU为252字节，124个会超过253字节 |



注意事项：

- 数量下限是1，数量为0通常返回异常码`03`；
- 数量上限是单帧协议上限，不等于设备实际支持的地址数量；
- 地址范围和数量范围要分开检查，返回不同异常码



## 八、异常响应

当从站收到属于自己的请求，且CRC正确，但无法正常执行时，应返回异常响应。异常响应的功能码等于原功能码最高位置1，也就是：

```text
异常功能码 = 原功能码 | 0x80
```

例如`0x03`异常响应的功能码是`0x83`，`0x10`异常响应的功能码是`0x90`。

| 异常码 | 名称 | 常见原因 |
| :--- | :--- | :--- |
| `01` | 非法功能 | 从站不支持该功能码 |
| `02` | 非法数据地址 | 起始地址不存在、地址范围越界、对象不可访问 |
| `03` | 非法数据值 | 数量为0、数量超上限、字节数不匹配、报文格式错误 |
| `04` | 从站设备故障 | 从站执行过程中发生内部错误 |

不是所有错误都会返回异常响应。能不能应答，取决于从站是否能确认这是一条发给自己的、可识别的、CRC正确的请求。

| 情况 | 处理方式 | 原因 |
| :--- | :--- | :--- |
| 从站地址不匹配 | 静默丢弃 | 请求不是发给本设备 |
| CRC错误 | 静默丢弃 | 报文不可信，不能基于错误内容应答 |
| 广播请求 | 不返回应答 | 广播规则要求不应答 |
| 功能码不支持 | 返回异常`01` | 请求属于本站且CRC正确 |
| 地址越界 | 返回异常`02` | 功能码可识别，但访问对象不存在 |
| 数量或字节数错误 | 返回异常`03` | 地址字段可识别，但参数值非法 |
| Byte Count与实际Data长度不一致，CRC正确 | 返回异常`03` | 请求属于本站且内容可校验，但数据域格式非法 |

注意事项：

- CRC错、站号错、广播请求通常表现为主站超时；
- 异常响应说明从站确实收到了请求，只是拒绝执行；
- 排查地址错误时，要同时检查起始地址、数量、地址偏移和对象类型。



## 九、串口和RS-485

RS-485是物理层或电气层，Modbus是应用层协议。RS-485只规定差分信号如何传输，不能决定报文含义；Modbus规定报文格式和数据含义，但不负责电气连接。

RS-485常用于半双工总线，同一时间通常只能有一个设备发送，其他设备接收。现场布线一般需要注意A/B差分线、公共参考地、终端电阻、偏置电阻、总线拓扑和屏蔽接地。



注意事项：

- A/B接反会导致无法通信或大量错误帧；
- 两端串口参数必须一致，包括波特率、数据位、停止位和校验位；
- 总线两端通常需要终端电阻，长线和高速通信时尤其重要；
- 半双工收发方向控制不当会导致从站无法收到请求或主站收不到应答；
- 不要把RS-485说成Modbus，也不要把Modbus说成RS-485。



## 十、Modbus ASCII

Modbus ASCII也是串行通信方式，但它不直接发送二进制字节，而是把每个字节转换成两个ASCII十六进制字符。

例如二进制字节`0x3A`会以字符`'3'`和`'A'`发送。

ASCII帧格式如下：

```text
: 地址 功能码 数据 LRC CR LF
```

其中`:`是起始字符，`CR LF`是结束符，校验使用LRC。由于每个二进制字节要变成两个ASCII字符，传输效率低于RTU，但报文在串口分析工具中更容易阅读。

注意事项：

- ASCII使用LRC，不使用RTU的CRC；
- ASCII帧靠起始符和结束符分帧，不依赖RTU那种`t3.5`静默时间；
- ASCII和RTU的功能码含义相近，但帧格式和校验完全不同；
- “ASCII”不是“ACSII”，写文档时应注意拼写。

## 十一、Modbus TCP

Modbus TCP运行在TCP/IP网络上，默认端口通常是`502`。它不使用RTU中的从站地址和CRC，而是在PDU前增加MBAP Header。

MBAP Header长度为7字节：

| 字段 | 长度 | 说明 |
| :--- | :--- | :--- |
| Transaction Identifier | 2字节 | 事务标识，用于匹配请求和响应 |
| Protocol Identifier | 2字节 | 协议标识，Modbus通常为`0` |
| Length | 2字节 | 后续字节长度，包括Unit Identifier和PDU |
| Unit Identifier | 1字节 | 单元标识，常用于网关后面的串行从站寻址 |

Modbus TCP的ADU格式如下：

```text
MBAP Header + PDU
```

TCP是面向字节流的协议，接收方不能假设一次`recv`就得到一条完整Modbus报文，也不能假设一次`recv`只包含一条报文。正确做法是根据MBAP中的Length字段从字节流中拆出完整ADU。

注意事项：

- Modbus TCP不使用RTU CRC；
- Unit Identifier不是RTU CRC，也不是TCP端口号；
- 同一个TCP连接上可能连续发送多个请求，解析时要按MBAP长度字段处理；
- 经过RTU-TCP网关时，要区分TCP侧的MBAP封装和RTU侧的地址加CRC封装。

## 十二、常见错误

| 易错点 | 正确认识 |
| :--- | :--- |
| 把`40001`当成报文地址 | `40001`常是文档显示编号，报文地址通常从`0`开始 |
| 把从站地址0当成普通设备地址 | `0`是广播地址，普通从站地址是`1~247` |
| 把RTU CRC按高字节先发 | RTU CRC低字节先发，高字节后发 |
| 把寄存器数据按低字节先发 | Modbus寄存器值通常高字节先发 |
| 数量合法就认为地址合法 | 还要检查`起始地址 + 数量 - 1`是否越界 |
| 读写0个对象 | 数量下限为1，0没有标准操作意义 |
| 把协议上限当设备容量 | 设备实际数据区可能远小于协议单帧上限 |
| CRC错还返回异常 | CRC错应静默丢弃，不能返回异常 |
| 把TCP包边界当Modbus边界 | TCP要按MBAP Length字段拆包 |
| 混用RTU、ASCII、TCP封装 | 三者PDU思想相近，但ADU、帧边界和校验不同 |
