#数据结构
## 数据结构
数据结构三要素：**逻辑结构、存储结构、数据运算**；
### 逻辑结构
数据元素之间的**关系**
- **集合**：元素同属一个集合，但无其他关系
    
- **线性结构**：**一对一**关系（如：线性表、栈、队列）
    
- **树形结构**：**一对多**关系（如：二叉树、B树）
    
- **图状结构**：**多对多**关系（如：有向图、无向图）

### 存储结构
逻辑结构在计算机内存中的**实现方式**。
- **顺序存储**：用连续内存单元（数组）
    
- **链式存储**：用指针链接离散内存单元（链表）
    
- **索引存储**：数据+索引表（如：数据库索引）
    
- **散列存储**：通过哈希函数直接定位（如：HashMap）
### 数据运算
对数据结构的**操作集合**。
- **创建/销毁**
    
- **插入/删除**
    
- **查找/遍历**
    
- **修改/更新**

### 概念
数据结构是相互之间存在一种或多种特定关系的数据元素的集合，它包括逻辑结构、存储结构和数据运算三方面内容
数据的逻辑结构和存储结构是密不可分的，算法的设计取决于所选定的逻辑结构，而算法的实现依赖于采用的存储结构
逻辑结构包括线性结构（线性表、栈、队列）和非线性结构（树、图、集合）

数据类型是一个值的集合和定义在此集合上的一组操作的总称
数据类型包括：原子类型、结构类型、抽象数据类型


数据的存储结构主要有顺序存储、链式存储、索引存储和散列存储
施加在数据上的运算包括运算的定义和实现。运算的定义是针对逻辑结构的，指出运算的功能；运算的实现是针对存储结构的，指出运算的具体操作步骤
在存储数据时，通常不仅要存储各数据元素的值，而且要存储数据元素之间的关系

对于两种不同的数据结构，他们的逻辑结构和物理结构完全有可能相同（比如二叉树和二叉排序树）
链式存储设计时，各个不同结点的存储空间可以不连续，但结点内的存储单元地址必须连续
算法是对特定问题求解步骤的一种描述，它是指令的有限序列，其中每条指令包括一个或多个操作。


算法的五个特性：有穷性、确定性、可行性、输入、输出
通常设计一个好的算法应考虑：正确性、可读性、健壮性、效率与低存储量需求
同一个算法，实现语言的级别越高，执行效率越低

## 链表
[[指针]]
### 概念
链表是一种物理存储结构上非连续、非顺序的存储结构，数据元素的逻辑顺序是通过链表中的指针链接次序实现的 。
**逻辑结构**：线性结构（一对一）结点间通过顺序关系连接
**存储结构**：链式存储
**数据运算**：
可分为：单向与双向，带头结点与不带头结点，有环或无环
好的，单链表和双链表是两种基础但重要的数据结构，它们的设计差异直接影响了其特性和适用场景。

| 特性         | 单链表 (Singly Linked List)                                     | 双链表 (Doubly Linked List)                                               |
| ---------- | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| **节点结构**   | `typedef struct Node { int data; struct Node* next; } Node;` | `typedef struct DNode { int data; struct DNode *prev, *next; } DNode;` |
| **内存占用**   | 较小（每个节点 1 个指针）                                               | 较大（每个节点 2 个指针）                                                         |
| **遍历方向**   | 只能从头到尾**单向**遍历                                               | 可以**双向**遍历（前驱和后继）                                                      |
| **删除指定节点** | 需要知道其**前驱节点**，否则需要从头遍历                                       | **不需要前驱**，可直接通过自身指针完成                                                  |
| **插入灵活性**  | 通常需要前驱节点                                                     | 前后插入都很方便                                                               |


| 方面      | 无头结点        | 有头结点              |
| ------- | ----------- | ----------------- |
| 空表判断    | `L == NULL` | `L->next == NULL` |
| 插入第一个节点 | 需要特殊处理      | 统一操作              |
| 代码简洁性   | 较差          | 较好                |
| 内存占用    | 少一个节点       | 多一个节点             |

### 基本实现
```c
// 初始化
InitList(&L);

// 插入到第i位
ListInsert(&L, i, e);
// 在结点p后插
InsertNextNode(LNode *p, ElemType e);
// 在结点p前插  
InsertPriorNode(LNode *p, ElemType e);

// 按位查找
GetElem(L, i, &e);
// 按值查找
LocateElem(L, e);

// 删除第i位
ListDelete(&L, i, &e);
// 删除指定结点p
DeleteNode(LNode *p);

// 头插法建表
CreateList_Head(&L, n);
// 尾插法建表
CreateList_Tail(&L, n);

// 求表长
ListLength(L);

// 打印链表
PrintList(L);

// 判空
ListEmpty(L);

// 销毁
DestroyList(&L);
```

## 栈（stack）
线性结构的一种，是后进先出（LIFO）的线性表

$$
若有n个元素进栈，则出栈有1/(n+1)*C_{2n}^{n}种方法（卡特兰数）
$$

应用：括号匹配，表达式求值，递归

允许插入和删除的一段称做栈顶，另一端称作栈底，不含任何数据元素的称作空栈
栈的插入删除操作始终在栈顶进行，栈底是固定的
**逻辑结构**：线性结构（一对一）
**存储结构**：顺序存储或者链式存储
数据运算：只能在栈顶进行插入、删除、读取等受限操作
### 基本实现
```c
//顺序栈
typedef struct Stack{
	int data[MAXSTACK];
	int top
}Stack;

//链栈
typedef struct LStack{
	int data;
	struct LStack *next;
}LStack;
```

```c
// 初始化栈
InitStack(&S);

// 入栈（压栈）push
Push(&S, x);

// 出栈（弹栈）pop
Pop(&S, &x);

// 取栈顶元素
GetTop(S, &x);

// 判断栈空
StackEmpty(S);

// 判断栈满（顺序栈）
StackFull(S);
```




## 堆（heap）
**堆**是一种特殊的**完全二叉树**，它满足以下性质：

1. **结构性**：是一棵**完全二叉树**
    
2. **有序性**：任意节点的值总是不大于（或不小于）其子节点的值
    
    - **大顶堆**：父节点 ≥ 子节点
        
    - **小顶堆**：父节点 ≤ 子节点

**逻辑结构**：树形结构，每个节点都满足堆序性质，但**兄弟节点间没有大小关系**
存储结构：**顺序存储**（数组），
```C
// 初始化堆
InitHeap(&H);

// 插入元素（上浮调整）
HeapInsert(&H, x);

// 删除堆顶元素（下沉调整）  
HeapDelete(&H, &x);

// 获取堆顶元素
GetTop(H, &x);

// 堆化（将数组调整为堆）
Heapify(H);

// 判断堆空
HeapEmpty(H);
```

## 队列（queue）
只允许在一段插入新元素，在另一段删除旧元素的线性表
**逻辑结构：线性结构，一对一，只能在**队尾**插入，在**队头**删除
存储结构：顺序存储（循环队列），链式存储（链队列）
FIFO

判断队空和队满：
1： 队列元素个数：（rear+MAX_QUEUE-front)%MAX_QUEUE
2: 在结构体中加上int size;每当新插入元素则size++，删除则size--，判断size是MAX_QUEUE还是0就能分辨
3： 在结构体中加上int tag,当最近一次操作是插入则设为1，是删除则设为0，当front`==`rear时，根据tag的值判断队空队满

### 基本实现
```C
// 初始化队列
InitQueue(&Q);

// 判断队空
QueueEmpty(Q);

// 入队（队尾插入）
EnQueue(&Q, x);

// 出队（队头删除）
DeQueue(&Q, &x);

// 读队头元素
GetHead(Q, &x);

// 销毁队列
DestroyQueue(&Q);
```

### 模式匹配
#### 朴素模式匹配
```c
// 时间复杂度：O(mn)
int Index(SString S, SString T) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) { i++; j++; }
        else 
        { i = i - j + 2; j = 1; }  // 回溯
    }
    return j > T.length ? i - T.length : 0;
}
```

#### KMP算法(必)
```c
// 时间复杂度：O(m+n)
// 核心：next数组，避免主串指针回溯
void get_next(SString T, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;
    while (i < T.length) {
        if (j == 0 || T.ch[i] == T.ch[j]) {
            i++; j++; next[i] = j;
        } else j = next[j];
    }
}
```

## 树（tree）

### 相关概念
树结构（Tree Structure） 是一种非线性的层级化数据组织方式，它通过 “节点”（存储数据）和 “边”（连接节点）模拟现实中树的形态（如树干、树枝、树叶），但通常以 “根在上、叶在下” 的倒序形式呈现。其核心特点是不存在循环路径，且任意两个节点之间有且仅有一条唯一路径，因此也被视为 “无环连通图” 的特殊形式。

**逻辑结构**：一对多的层次关系
**存储结构**：顺序存储（双亲表示），链式存储（孩子兄弟表示），顺序+链式存储（孩子表示）

- 双亲表示法：方便找父节点
    
- 孩子表示法：方便找子节点
    
- 孩子兄弟表示法：便于实现树与二叉树的转换

树是n（n≥0）个结点的有限集合，n=0时，称为空树，这是一种特殊情况。在任意一棵非
空树中应满足：
1）有且仅有一个特定的称为根的结点。
2）当n>1时，其余结点可分为m（m>0）个互不相交的有限集合T1,T2.,Tm，其中每个集
合本身又是一棵树，并且称为根结点的子树。

1. 树的根结点没有前驱，除根结点外的所有结点有且只有一个前驱。
2. 树中所有结点可以有零个或多个后继。

因此n个结点的树中有n-1条边。

树中一个结点的子树个数称为该**结点的度**,树中结点的最大度数称为**树的度**。如结点A的度为2,结点B的度为3,树只有这两个结点，则树的度为3。

度大于0的结点称为**分支结点**(又称**非终端结点**);度为0(没有子女结点)的结点称为**叶子结点**(又称**终端结点**)。在分支结点中,每个结点的分支数就是该结点的度。


**结点的层次**从树根开始定义,根结点为第1层,它的子结点为第2层,以此类推。双亲在同一层的结点互为**堂兄弟**。  
**结点的深度**是从根结点开始自顶向下逐层累加的。  
**结点的高度**是从叶结点开始自底向上逐层累加的。  
**树的高度**(或**深度**)是树中结点的最大层数。
**链**：从子树中的叶子节点到当前节点的路径。把最长链的长度，作为 dfs 的返回值。根据这一定义，空节点的链长是 −1，叶子节点的链长是 0。
二叉树的 **直径** 是指树中任意两个节点之间最长路径的 **长度** 。这条路径可能经过也可能不经过根节点 `root` 。
<[543. 二叉树的直径](https://leetcode.cn/problems/diameter-of-binary-tree/)>

**有序树和无序树**。
树中结点的各子树从左到右是有次序的,不能互换,称该树为有序树,否则称为无序树。假设图为有序树,若将子结点位置互换,则变成一棵不同的树。
路径和路径长度。
树中两个结点之间的路径是由这两个结点之间所经过的结点序列构成的,而路径长度是路径上所经过的边的个数。
注意:由于树中的分支是有向的,即从双亲指向孩子,所以树中的路径是从上向下的,同一双亲的两个孩子之间不存在路径。

森林。
森林是m (m≥0)棵互不相交的树的集合。森林的概念与树的概念十分相近，因为只要把树的根结点删去就成了森林。反之，只要给m棵独立的树加上一个结点，并把这m棵树作为该结点的子树，则森林就变成了树。

### 基本实现
#### 树的存储结构
**双亲表示法(顺序存储)**
在每个节点里，附设一个指示器指示其双亲在数组中的位置
```c
#define MAX_TREE_SIZE 100
typedef int TElemType
typedef struct PTNode
{
	TElemType data; //结点数据
	int parent;//双亲位置
}PTNode;
typedef struct
{
	PTNode nodes[MAX_TREE_SIZE];
	int root,n;//根的位置和结点数
}PTree;
```
根节点的位置为-1，数组下标代表该结点层次遍历的序号，parent是该结点的父节点的序号
也可以增加一个firstchild来指向最左边孩子的序号，解决找孩子结点的问题

**孩子表示法（链式存储）**
每个节点的子结点排列之后以单链表作为存储解决过，叶子结点的单链表为空，n个头指针组成一个线性表，顺序存储到一维数组
```c
#define MAX_TREE_SIZE 100
typedef int TElemType
typedef struct CTNode
{
	int data; //结点数据
	struct CTNode *next;
}*ChildPtr*;

typedef struct
{
	TElemType data;
	ChildPtr firstchild
}CTBox;

typedef struct
{
	CTBox nodes[MAX_TREE_SIZE];
	int root,n;//根的位置和结点数
}CTree;
```
改进：双亲孩子表示法，在CTBox加上int parent指向结点父结点的序号，能够直接找到父结点

**孩子兄弟表示法（顺序加链式）**
每个结点有两个指针，一个指向该结点的第一个子结点（最左孩子），另一个指向最近的兄弟节点（从左往右），没有则为空
```c
typedef struct CSNode{
	TElemType data;
	struct CSNode *firstchild,*rightsib;
}CSNode,*CSTree
```
也可以加parent指针使能够直接找到父结点

#### 基本操作
```c
// 初始化空树
InitTree(&T);

// 销毁树
DestroyTree(&T);

// 创建树
CreateTree(&T, definition);

// 清空树
ClearTree(&T);

// 判空
TreeEmpty(T);

// 求树的深度
TreeDepth(T);

// 求树的度（最大分支数）
TreeDegree(T);

// 获取根节点
Root(T);

// 求节点的父节点
Parent(T, cur_e);
// 求节点的左孩子/右兄弟
LeftChild(T, cur_e);
RightSibling(T, cur_e);

// 插入子树
InsertChild(&T, &p, i, c);

// 删除子树  
DeleteChild(&T, &p, i);

// 遍历树
// 先根遍历
PreOrderTraverse(T, Visit());
// 后根遍历
PostOrderTraverse(T, Visit());
// 层次遍历
LevelOrderTraverse(T, Visit());
```

### 树的性质
$$
\begin{aligned}
&1.\ \text{树中的结点数等于所有结点的度数之和加}1 \\
&2.\ \text{度为}m\text{的树中第}i\text{层上至多有}m^{i-1}\text{个结点}\\
&3.\ \text{高度为}h\text{的}m\text{叉树至多有}\frac{m^h-1}{m-1}\text{个结点}\\
&4.\ \text{具有}n\text{个结点的}m\text{叉树的最小高度为}\lceil \log_m(n(m-1)+1) \rceil
\end{aligned}
$$


### 常见结论
#### **一、通用树（m叉树）**

1. **节点与边的关系**：树中 **节点数 = 边数 + 1**。
    
2. **第 i 层最大节点数**：**度为 m 的树**第 i 层至多有 **$m^{i-1}$** 个节点。
    
3. **高度为 h 的m叉树最大节点数**：**$\dfrac{m^h - 1}{m - 1}$**。
    
4. **最小高度公式**：具有 n 个节点的 m 叉树，其最小高度为 **$\lceil \log_m(n(m-1)+1) \rceil$**。**$\lceil \ \rceil$为向上取整
	
5. 高度为h的m叉树至少有h个结点
	
6. 高度为h，度为m的树至少有m+h-1个结点


#### **二、二叉树（核心）**

1. **第 i 层最大节点数**：至多有 **$2^{i-1}$** 个。
    
2. **高度为 h 的二叉树最大节点数**：至多有 **$2^h - 1$** 个。
    
3. **叶子节点与度为 2 的节点关系**：**$n_0 = n_2 + 1$**。
    
    - `n₀`: 叶子节点数，`n₂`: 度为 2 的节点数。
        
4. **完全二叉树的深度**：具有 n 个节点的完全二叉树，其深度为 **$\lfloor \log_2 n \rfloor + 1$**。


#### **三、二叉遍历序列**

1. **已知前序 + 中序**，或 **已知后序 + 中序**，或者已知**层序+中序**，可以**唯一确定**一棵二叉树。
    
2. **已知前序 + 后序**，**无法唯一确定**一棵二叉树，除非它是一棵**真二叉树**（每个节点的度为 0 或 2）。
    

#### **四、二叉排序(搜索)树（BST）**
定义：
- 节点的左子树只包含 **严格小于** 当前节点的数。
- 节点的右子树只包含 **严格大于** 当前节点的数。
- 所有左子树和右子树自身必须也是二叉搜索树。
**整个左子树的所有节点 都小于 根**并且**整个右子树的所有节点 都大于 根**

**二叉搜索树的中序遍历是升序序列**，就是从小到大遍历结点

<[108. 将有序数组转换为二叉搜索树](https://leetcode.cn/problems/convert-sorted-array-to-binary-search-tree/)>

1. **中序遍历**二叉排序树，可以得到一个**递增的有序序列**。
    
2. 在二叉排序树中**删除节点**：
    
    - 若为叶子，直接删。
        
    - 若只有一棵子树，用子树顶替。
        
    - 若有两棵子树，用其**直接前驱**或**直接后继**（中序遍历序列中的相邻值）顶替，并转化为删除前驱/后继节点。



#### **五、平衡二叉树（AVL）**

1. 平衡因子：某节点的**左子树高度 - 右子树高度**，值只能为 **-1, 0, 1**。
    
2. 调整不平衡的四种基本操作：**LL（右单旋）、RR（左单旋）、LR（先左后右）、RL（先右后左）**。
    
3. 插入时，只需调整**从插入点到根节点路径上**第一个不平衡的子树。


#### **六、哈夫曼树**

1. **不存在度为 1** 的节点。
    
2. 给定 n 个权值，构造出的哈夫曼树共有 **2n - 1** 个节点。
    
3. 哈夫曼树的**带权路径长度（WPL）** 是**唯一且最小**的。
    
4. 哈夫曼编码是**前缀编码**，且是**最优**的。



### 二叉树

二叉树是另一种树形结构，其特点是每个结点至多只有两棵子树( 即二叉树中不存在度大于2的结点)，并且二叉树的子树有左右之分，其次序不能任意颠倒。
与树相似，二叉树也以递归的形式定义。二叉树是n (n≥0) 个结点的有限集合:

或者为空二叉树，即n=0。
或者由一个根结点和两个互不相交的被称为根的左子树和右子树组成。左子树和右子树又分别是一棵二叉树。
二叉树是有序树，若将其左、右子树颠倒，则成为另一棵不同的二叉树。即使树中结点只有一棵子树，也要区分它是左子树还是右子树。
#### 二叉树的存储结构

**顺序存储**：用一维数组存储二叉树结点，结点的存储位置就是数组的下标，对应位置没有该节点则当前数组位置为空，一般是用于完全二叉树

**二叉链表**，

#### 特殊二叉树
（1）斜树
所有的结点都只有左子树的二叉树叫左斜树。所有结点都是只有右子树的二叉树叫右斜树。这两者统称为斜树。

（2）满二叉树
一棵高度为h ，且含有$2^h-1$个结点的二叉树称为满二叉树，即树中的每层都含有最多的结点。满二叉树的叶子结点都集中在二叉树的最下一层，并且除叶子结点之外的每个结点度数均为2。
①只有最后一层有叶子结点
②不存在度为1的结点
③按层序从1开始编号，结点i的左孩子为2i，右孩
子为2i+1；结点i的父节点为【i/2】（如果有的话）

（3）完全二叉树
高度为h 、有n 个结点的二叉树，当且仅当其每个结点都与高度为h 的满二叉树中编号为1~n的结点一一对应时，称为完全二叉树。

特点：
1.若i ≤ n / 2 , 则结点i 为分支结点，否则为叶子结点。
2.叶子结点只可能在层次最大的两层上出现。对于最大层次中的叶子结点，都依次排列在该层最左边的位置上。
3.若有度为1的结点，则只可能有一个，且该结点只有左孩子而无右孩子(重要特征)。
4.按层序编号后，一旦出现某结点(编号为i )为叶子结点或只有左孩子，则编号大于i 的结点均为叶子结点。
5.若n 为奇数，则每个分支结点都有左孩子和右孩子;若n为偶数，则编号最大的分支结点(编号为n / 2 )只有左孩子，没有右孩子，其余分支结点左、右孩子都有。

##### **线索二叉树**
利用空指针域来存储遍历顺序信息，实现**不用栈/递归的中序遍历**。
指向前驱和后继的指针成为线索，加上线索的二叉链表成为线索链表，相应的二叉树就是线索二叉树。
可以在O(1)空间复杂度下实现中序遍历，而先序和后序分别不能实现找前驱和找后继，除非能直接找到父节点

#### 遍历
遍历指按照某种规则访问树中每个结点，且**仅访问一次**。
######  **先序遍历 (Preorder)**

- **顺序**：根 → 左 → 右(==N==LR)    先访问**根**结点
    
- **场景**：用于复制树的结构


#####  **中序遍历 (Inorder)**

- **顺序**：左 → 根 → 右(L==N==R)    根结点在**中间**访问
    
- **场景**：在**二叉搜索树**中得到升序序列
    



##### **后序遍历 (Postorder)**

- **顺序**：左 → 右 → 根(LR==N==)     最后访问根结点
    
- **场景**：用于释放树的内存（先释放子树）


##### 层次遍历

从根节点开始，**自上而下、自左至右**地逐层访问树的每个结点。

- **按层处理**：先访问第1层（根），再第2层，依次类推...
    
- **同层顺序**：在同一层内，严格按**从左到右**的顺序访问。

**算法步骤**：

1. 将根结点入队。
    
2. 当队列不为空时循环：  
    a. 队头结点出队，并访问它。  
    b. 将该结点的**左孩子**（如果存在）入队。  
    c. 将该结点的**右孩子**（如果存在）入队。


**用途**：
- 求树的**宽度**（某一层的最大结点数）
    
- 判断是否为**完全二叉树**
    
- 寻找**最短路径**或特定层级的结点
```c
void LevelOrder(BiTree T) {
    if (T == NULL) return;
    
    LinkQueue Q;
    InitQueue(&Q);          // 初始化队列
    EnQueue(&Q, T);         // 根结点入队
    
    while (!QueueEmpty(Q)) {
        BiTNode* node;
        DeQueue(&Q, &node); // 队头结点出队
        visit(node);        // 访问该结点
        
        // 左孩子入队
        if (node->lchild != NULL)
            EnQueue(&Q, node->lchild);
        // 右孩子入队  
        if (node->rchild != NULL)
            EnQueue(&Q, node->rchild);
    }
}
```



**前、中、后序遍历**：属于 **深度优先搜索**（DFS)。它们会先沿着一条路径**纵向**深入到底，再回溯。
**层序遍历**：属于 **广度优先搜索**(BFS)。它会按层次**横向**扫描，一层一层地访问。

| 特性         | **前、中、后序遍历**                   | **层序遍历**               |
| ---------- | ------------------------------ | ---------------------- |
| **遍历顺序**   | **纵向**深入，一条路走到底再回溯             | **横向**平推，一层结束再下一层      |
| **实现数据结构** | **栈** (递归或迭代)                  | **队列** (迭代)            |
| **解决问题**   | 树的**结构性**问题 (复制、求深度、表达式求值)     | 树的**层次性**问题 (找层宽、最短路径) |
| **序列特性**   | 在**二叉搜索树**中，**中序**遍历产生**有序序列** | 序列天然按**层级**和**从左到右**排序 |
| **“视角”**   | 像一只**爬虫**，沿着树枝爬遍每一个节点          | 像一台**扫描仪**，从上到下逐行扫描整棵树 |










## 哈希表（散列表）

哈希（h a s h ）又称散列，是一种组织数据的方式。从译名来看，有散乱排列的意思。
本质就是通过**哈希函数**把关键字key 跟存储位置建立一个映射关系，查找时通过这个哈希函数计算出 k e y 存储的位置，进行快速查找。

1. **负载因子**：α=N/M，控制扩容时机（通常α≥0.7时扩容）
2. **关键字转换**：非整数类型需通过仿函数转为整型（如字符串的BKDR哈希）
### 概念
#### **哈希集合 (HashSet)**

1. **核心概念**：哈希集合是一种用于存储**不重复元素**的数据结构，其核心功能是进行**快速的成员存在性检查**。
    
2. **存储内容**：它内部仅存储元素的**键（Key）** 本身，不关联任何额外的值。可以将其理解为一个只包含键的字典。
    
3. **主要操作**：主要包括 `add(key)`（添加元素）、`remove(key)`（删除元素）和 `contains(key)`（判断元素是否存在）。
    
4. **应用场景**：非常适合用于**数据去重**、检查某个项目是否在集合中，以及实现集合运算（如求并集、交集等）。
    

#### **哈希映射 (HashMap)**


1. **核心概念**：哈希映射是一种用于存储**键值对（Key-Value Pair）** 的数据结构，其核心功能是提供**基于键的快速值访问**。
    
2. **存储内容**：它存储的是键与值之间的映射关系。每个键（Key）在映射中是**唯一**的，但不同的键可以对应相同的值（Value）。
    
3. **主要操作**：主要包括 `put(key, value)`（插入或更新键值对）、`get(key)`（根据键获取对应的值）和 `remove(key)`（删除键值对）。
    
4. **应用场景**：广泛用于实现字典、缓存系统、频率统计以及任何需要通过一个键来快速查找另一个关联值的场景。

区别：
1. **根本区别**：
    
    - **存储单元**：哈希集合存储的是**单个元素（Key）**；而哈希映射存储的是**键值对（Key-Value）**。
        
    - **访问方式**：哈希集合回答的问题是“**这个元素存在吗？**”；哈希映射回答的问题是“**这个键对应的值是什么？**”。
        
2. **内在联系**：
    
    - 从实现角度看，**哈希集合可以看作是哈希映射的一种特殊形式**。通常可以在哈希映射的基础上，令所有键对应的值（Value）为一个固定的占位符（如 `null` 或 `True`），来实现一个哈希集合。
        
    - 两者底层都依赖于**哈希表**这一数据结构，共享相同的哈希函数计算和哈希冲突解决机制（如链地址法、开放地址法等）。


### 设计方法

| 方法   | 公式              | 适用场景         | 缺点    |
| ---- | --------------- | ------------ | ----- |
| 直接定址 | h(key)=key      | 关键字集中（如计数排序） | 空间浪费  |
| 除留余数 | h(key)=key%M    | 通用场景         | M需为质数 |
| 乘法散列 | ⌊M×(A×key)%1⌋   | 理论优化         | 计算复杂  |
| 全域散列 | [(a×key+b)%P]%M | 防恶意攻击        | 实现复杂  |
|      |                 |              |       |


### 冲突处理


#### 开放定址法
线性探测:**从发生冲突的位置开始**，依次**线性向后探测**，**直到寻找到下一个没有存储数据的位置为止**，如果走到哈希表尾，则回绕到哈希表头的位置。
二次探测：**发生冲突的位置开始**，依次**左右按二次方跳跃式探测**，**直到寻找到下一个没有存储数据的位置为止**，如果往右走到哈希表尾，则回绕到哈希表头的位置；如果往左走到哈希表头，则回绕到哈希表尾的位置。


#### 链地址法（哈希桶）
链地址法中所有的数据不再直接存储在哈希表中，每个存储位存储一个指针，当一个关键字 key用哈希函数计算出的位置冲突，就把这些冲突的数据链接成一个链表，挂在哈希表这个位置的下面。链地址法也叫做拉链法或者哈希桶。
哈希表中每一位都存储一个**结点**：

1. 当没有数据映射这个位置时，这个结点为**空**。
2. 当有多个数据映射到这个位置时，这些**冲突的数据**的结点链接成一个**链表**，挂在哈希表这个位置的下面。

#### 双重散列
第一个哈希函数计算出的值发生冲突，使用第二个哈希函数计算出一个跟key 相关的偏移量值，不断往后探测，直到寻找到下一个没有存储数据的位置为止。其本质也是为了跳跃存取数据，防止堆积。
