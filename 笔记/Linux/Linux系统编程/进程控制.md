[[多线程编程#进程与线程:]]


### 进程状态：
**创建态**：进程正在被创建，操作系统正在为其分配PCB、地址空间、资源等，创建完成后进入就绪态
**就绪态**：进程已获得除CPU外的所有必要资源，随时可以运行。等待操作系统调度器分配CPU时间片，获得CPU则进入运行态
**运行态**：进程正在CPU上执行指令，时间片用完 → 就绪态， 
需要等待I/O等事件 → 阻塞态
执行结束 → 终止态
**阻塞态**：进程因等待某些事件（如I/O完成、信号量、消息等）而无法继续执行，即使CPU空闲，该进程也不能运行，**直到等待的事件发生** → **就绪态**
**结束态** ：进程已结束执行，但还在进程表中占有一个位置，保留退出状态码供父进程查询，父进程通过wait()（阻塞）系统调用（或者是waitpid（），可以非阻塞）回收后彻底消失
（若只有主进程且在终端运行，它的父进程一般是shell，通过shell来回收，如果是图形界面运行它的父进程是桌面环境）

操作系统为每个进程维护了一个数据结构，称为**进程控制块 (PCB)**。PCB 是进程存在的唯一标志，它包含了：

1. **进程标识符 (PID)**：进程的“身份证号”。
    
2. **进程状态**：运行、就绪、阻塞等。
    
3. **程序计数器**：下一条要执行的指令的地址。
    
4. **CPU 寄存器**：当进程被切换时，需要保存现场。
    
5. **内存管理信息**：如基址寄存器、界限寄存器、页表等。
    
6. **记账信息**：CPU 使用时间、时间限制等。
    
7. **I/O 状态信息**：分配给进程的 I/O 设备、打开的文件列表等。

一个进程的真实面貌是：PCB + 程序代码 + 相关数据集合。


***僵尸进程：子进程已终止，但父进程尚未wait()***（或者是waitpid（），可以非阻塞）
**危害：占用内核进程表项**
- 每个进程在内核中都有一个`task_struct`结构体
- 系统有最大进程数限制（`/proc/sys/kernel/pid_max`）
- 如果僵尸进程太多，可能导致**无法创建新进程**
- 进程ID（PID）被占用
- 退出状态码、运行时间统计等信息占用的内存
- 一些文件锁可能未被释放

***孤儿进程：父进程先终止，子进程被init进程(pid=1)收养***
***无害：init进程会自动wait()回收***

**进程控制操作**：

- **创建**：`fork()` + `exec()` (Unix/Linux)
    
- **终止**：`exit()` (主动), `kill()` (被动)
    
- **等待**：`wait()`, `waitpid()` (父进程回收子进程资源，避免僵尸进程)
## 进程间通信IPC
在进程之间**传递数据**。

进程间通信（IPC）：管道是最基本的IPC，共享内存是最快的IPC
信号（异步机制），套接字（功能最强大，可用于网络通信），消息队列（内核的一个链表）。主要成本是上下文切换和数据拷贝
**管道**：
**匿名管道**：单向，用于有亲缘关系的进程。
`ps aux | grep nginx`
**命名管道**：有名字的文件，可用于无亲缘关系进程。
`mkfifo("/tmp/myfifo", 0666); // 创建命名管道,c语言`

**消息队列**
内核维护的**消息链表**。支持按类型读取消息，比管道更结构化。

**共享内存**
**最快**的IPC方式。
多个进程**直接读写**同一块内存区域。
必须配合**同步机制**使用，否则会产生数据混乱。

**信号**：
用于通知进程**某个事件已发生**的异步机制。
不传递数据，只传递信号编号（如 `SIGINT`, `SIGKILL`）。

**套接字**
功能最强大，可用于**网络通信**。
包括Unix域套接字（本机）和网络套接字。


1.“共享内存最快，为什么不是所有IPC都用它？”
  因为共享内存需要程序员自己处理同步问题（用信号量/互斥锁），否则会产生数据竞争。其他IPC如管道，内核帮我们处理了同步，更安全但性能有损失。”

2.“线程有自己的栈，那堆是共享的吗？
是的。堆是进程级别的资源，被该进程的所有线程共享。这正是为什么多线程操作堆上的全局变量时需要加锁保护。”

3.“进程上下文切换比线程上下文切换开销大在哪里？

最核心的开销是**页表切换**（即CR3寄存器的切换），这会导致TLB快表被刷新，引发大量缓存失效。线程切换在同一进程内，地址空间不变，没有这个开销。”

4.“并发在单核上有什么用？明明没有加快速度。”

并发主要提升**响应性**和**资源利用率**。比如一个线程在等待I/O（如读磁盘）时，CPU可以立刻切换到另一个线程计算，避免了CPU空转等待，从用户体验上看程序响应更快了。”

5.并发解决等待问题’具体指什么？”
当任务中有大量I/O等待或睡眠时，并发能让CPU在等待期间去执行其他就绪任务，把原本串行的‘计算->等待->计算’流程，重叠成并发的‘计算+等待+计算’，大幅提升系统吞吐量。


## 进程同步IPC
协调多个进程的执行**顺序**或**节奏**，防止因并发访问共享资源而导致的数据混乱（竞态条件）。

**信号量**

- 一个**计数器**，用于控制对多个共享资源的访问。
    
- **P操作**：申请资源（计数器-1），若为0则阻塞。
    
- **V操作**：释放资源（计数器+1），唤醒等待者。

**互斥锁**

- 信号量的一种特例（取值0/1）。
    
- 保证**同一时间只有一个进程**进入临界区。

**条件变量**

- 让进程在某个**条件不满足时睡眠**，条件满足时被唤醒。
    
- 必须与互斥锁配合使用。

| 机制       | 主要用途 | 特点          |
| -------- | ---- | ----------- |
| **管道**   | 数据传递 | 简单，单向，有亲缘关系 |
| **共享内存** | 数据传递 | **最快**，需同步  |
| **信号**   | 事件通知 | 异步，不传递数据    |
| **信号量**  | 进程同步 | 控制资源访问      |
| **互斥锁**  | 进程同步 | 保护临界区       |
- **数据量小、简单通信** → 管道
    
- **高性能、频繁数据交换** → 共享内存 + 信号量
    
- **结构化消息、解耦** → 消息队列
    
- **跨网络通信** → 套接字
    
- **紧急事件通知** → 信号
