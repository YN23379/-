






























### 对齐访问，sizeof
CPU在访问内存时，并不是以字节为单位随意读取的，而是以**字长**为单位。
- 32位CPU通常以4字节为单位访问内存
    
- 64位CPU通常以8字节为单位访问内存
    

如果数据没有对齐，CPU可能需要进行**两次内存访问**才能读到一个完整的数据，这被称为“不对齐访问”，会显著降低性能。在某些架构（如ARM）上，甚至会导致硬件异常。
对齐的目的是**用空间换时间**，提升CPU访问效率
每个数据类型都有其**自然对齐**要求，通常是其自身的大小：

- `char`：1字节对齐
    
- `short`：2字节对齐
    
- `int`：4字节对齐
    
- `double`：8字节对齐
    
- 指针：4字节（32位系统）或8字节（64位系统）对齐

对于结构体，**结构体的对齐规则**：

1. 结构体的起始地址要满足其成员中**最严格的对齐要求**
    
2. 每个成员要放在其**对齐倍数**的地址上
    
3. 结构体总大小要是其**最宽成员大小**的倍数
而需sizeof 反映的是**实际内存占用**，包含编译器插入的填充字节


通过**合理排列结构体成员**，可以显著减少内存浪费
```c
//12字节
struct BadLayout {
    char a;    // 1字节 + 3填充
    int b;     // 4字节  
    char c;    // 1字节 + 3填充
};

// 优化的排列 - 8字节  
struct GoodLayout {
    int b;     // 4字节
    char a;    // 1字节
    char c;    // 1字节 + 2填充（为了4字节对齐）
};
```
或者手动控制对齐：
```c
// 使用编译器指令取消对齐（不推荐，影响性能）
#pragma pack(1)
struct PackedStruct {
    char a;
    int b;    // 现在可能不对齐，访问会变慢
    char c;
};
#pragma pack()

// 或者使用属性语法
struct __attribute__((packed)) PackedStruct {
    char a;
    int b;
    char c;
};
```
