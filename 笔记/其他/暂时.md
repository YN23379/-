### 1. **线程池 - 从“会用”到“懂原理”**

**现状**：使用AI生成的线程池。  
**目标**：理解其内部机制，能白板画出工作流程图。

**深化步骤**：

1. **画图理解**：在白纸上画出你线程池的完整工作流程。
    
    - 主线程如何创建池？
        
    - 任务队列是什么样的数据结构？（很可能是链表）
        
    - 线程池中的工作线程如何从队列中取任务？
        
    - 用了什么同步机制（互斥锁、条件变量）来保护队列？
        
2. **回答灵魂三问**：
    
    - **问**：为什么需要线程池？（避免频繁创建销毁线程的开销）
        
    - **问**：线程数量如何设定？（IO密集型 vs 计算密集型）
        
    - **问**：如果任务队列满了怎么办？（你的线程池如何处理？是阻塞还是拒绝？）
        
3. **模拟面试**：准备好用1分钟讲清楚你的线程池工作原理。
    

### 2. **MQTT协议 - 从“通信”到“协议”**

**现状**：会调用API收发消息。  
**目标**：理解协议本质，能说明白技术选型。

**深化步骤**：

1. **抓包分析**（最关键的一步）：
    
    - 在电脑上使用 **Wireshark** 或 **MQTTX** 客户端。
        
    - 连接你的Hi3861使用的同一个MQTT服务器（如EMQX）。
        
    - **亲眼观察**：当你设备发布消息、小程序订阅消息时，网络上报文的结构。找到 **CONNECT, PUBLISH, SUBSCRIBE** 报文，理解其字段。
        
2. **理解核心概念**：
    
    - **QoS等级**：你的项目用的是QoS 0/1/2中的哪一个？为什么？（可靠性 vs 性能的权衡）
        
    - **遗嘱消息**：你的设备设置了遗嘱吗？为什么这对物联网设备至关重要？（设备异常离线时通知服务器）
        
    - **保留消息**：你的小程序是否需要一上来就看到设备的最新状态？
        
3. **回答灵魂三问**：
    
    - **问**：为什么选MQTT，不选HTTP？（低功耗、推送机制、报文精简）
        
    - **问**：MQTT心跳包的作用是什么？（保活，让服务器知道设备还在线）
        
    - **问**：如果网络不稳定，消息发丢了怎么办？（QoS机制）
        

### 3. **状态机 - 从“逻辑”到“设计”**

**现状**：实现了三状态逻辑。  
**目标**：能阐述设计理念和优化空间。

**深化步骤**：

1. **绘制标准状态转移图**：
    
    - 使用 [draw.io](https://draw.io/) 或 Excalidraw 画出清晰的状态机图。
        
    - 标注出每个状态转移的**条件**和**动作**。
        
    - 例如：`ALARM_OFF` --(检测到人)--> `ALARM_TRIGGERED` --(超时且无人)--> `ALARM_ON` (启动报警)。
        
2. **思考边界情况**：
    
    - 如果在 `ALARM_TRIGGERED` 状态时突然断电，重启后应该是什么状态？
        
    - 手动解除报警和自动解除报警的逻辑优先级是怎样的？
        
3. **回答灵魂三问**：
    
    - **问**：为什么用状态机？（逻辑清晰，避免复杂的if-else嵌套）
        
    - **问**：如果增加一个“布防/撤防”远程指令，状态机要如何扩展？
        
    - **问**：你的状态机是“事件驱动”还是“轮询检查”？（你的`timeout`是如何实现的？）
        

### 4. **Flash存储 - 从“存储”到“持久化”**

**现状**：同学实现，你会用。  
**目标**：理解底层机制和潜在风险。

**深化步骤**：

1. **理解OpenHarmony NV API**：
    
    - 找到对应的源码或文档，看它是如何封装Flash读写的。
        
    - 了解它是否做了**磨损均衡**？Flash有写入次数限制，频繁写同一区域会损坏。
        
    - 了解它是否做了**掉电保护**？是否确保一次写操作是原子的？
        
2. **设计你的“配置系统”**：
    
    - 你的配置在内存中是什么结构体？
        
    - 当收到小程序修改配置的命令时，流程是怎样的？（解析 -> 验证 -> 更新内存 -> 写Flash）
        
3. **回答灵魂三问**：
    
    - **问**：为什么存Flash，不存SD卡或别的地方？（嵌入式设备常用方案）
        
    - **问**：如果正在写Flash时突然断电，如何保证数据不损坏？（了解“写-读-验证”或事务机制）
        
    - **问**：Flash的寿命是多少？你的写操作频率会不会影响设备寿命？
