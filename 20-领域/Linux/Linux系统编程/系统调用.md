操作系统给用户提供的一组特殊接口，使用户程序可以通过此接口获得操作系统内核提供的服务


理解进程有独立的地址空间，而线程共享地址空间（共享全局数据、堆），但拥有独立的栈。
理解应用（用户空间）如何通过系统调用（如`brk`, `mmap`）向内核（内核空间）申请资源（如扩大堆内存）。
理解如何在x86主机上编译出能在ARM等架构上运行的程序。








### `clone`
`clone` 是 Linux 上用于创建**轻量级进程** 的系统调用，它是 `fork` 和 `pthread_create` 的底层实现基础。

`clone` 与 `fork`、`pthread_create` 的关系
`fork()`, `vfork()`, 以及创建线程的 `pthread_create()`，其底层都通过 **`clone()`** 系统调用实现。
`clone()` 提供了精细的控制 flags（如 `CLONE_VM`, `CLONE_FILES`, `CLONE_SIGHAND`），允许选择性地共享地址空间、文件描述符表、信号处理程序等，从而可以灵活地创建出介于传统进程和线程之间的“轻量级进程”。

|调用|创建对象|资源共享程度|关系|
|---|---|---|---|
|**`fork`**|**进程**|**不共享**。子进程获得父进程所有资源的**独立副本**（写时复制）。|**`fork` 是 `clone` 的特例**：`clone(SIGCHLD, 0)`|
|**`pthread_create`**|**线程**|**几乎全部共享**。共享内存空间、文件描述符表等。|**`pthread_create` 基于 `clone` 实现**：使用一组共享大部分资源的 flags。|
|**`clone`**|**轻量级进程**|**由 flags 精确控制**，可定制性极强。|**底层原语**，`fork` 和 `pthread_create` 都在它之上构建。|
在 Linux 内核中，**并不严格区分进程和线程**，它们都被统一称为“任务”，用 `task_struct` 结构体表示。

flags 决定了子进程与父进程**共享什么**。

|Flag|含义|影响|
|---|---|---|
|**`CLONE_VM`**|**共享内存描述符**|父子进程在同一虚拟地址空间中运行。**这是线程的核心标志**。|
|**`CLONE_FS`**|共享文件系统信息|共享根目录、当前工作目录等。|
|**`CLONE_FILES`**|**共享文件描述符表**|在父进程中打开的文件，在子进程中同样可访问。|
|**`CLONE_SIGHAND`**|**共享信号处理程序表**|对某个信号的设置，在父子进程中同时生效。|
|**`CLONE_PARENT`**|设置相同的父进程||
|**`CLONE_THREAD`**|**置于同一线程组**|拥有相同的 TGID（我们常说的 PID），不同的 PID（我们常说的线程 ID）。**这是线程的另一个核心标志**。|
|**`CLONE_SYSVSEM`**|共享 System V 信号量撤销值||
|**`SIGCHLD`**|子进程终止时向父进程发送 SIGCHLD 信号|这是传统进程的默认行为。|





### `mmap`
`mmap` 能将一个文件（或设备）的一部分直接映射到调用进程的虚拟地址空间。此后，进程就可以像访问普通内存一样，通过指针读写文件内容，而无需调用 `read` 或 `write`。


```c
#include <sys/mman.h>

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
```

|参数|类型|说明|
|---|---|---|
|**`addr`**|`void *`|**建议的映射起始地址**。通常设为 `NULL` 或 `0`，让内核自动选择合适地址。若指定，则作为提示，内核不一定采纳。|
|**`length`**|`size_t`|**要映射的字节数**。长度必须大于0。|
|**`prot`**|`int`|**映射区域的内存保护权限**。指定此区域内容可被如何访问。|
|**`flags`**|`int`|**控制映射区域的特性**。决定映射的类型、更新是否对其他进程可见、是否写入底层文件等。|
|**`fd`**|`int`|**文件描述符**。指明要映射哪个文件。|
|**`offset`**|`off_t`|**文件中的偏移量**。必须是与系统分页大小（通常4KB）的整数倍。|
**`prot` 参数（权限，可位或 `

|标志|值|说明|
|---|---|---|
|`PROT_READ`|`0x1`|页面可**读**。|
|`PROT_WRITE`|`0x2`|页面可**写**。|
|`PROT_EXEC`|`0x4`|页面可**执行**。|
|`PROT_NONE`|`0x0`|页面不可访问。|
**`flags` 参数（特性，可位或 `

| 标志                | 值      | 说明                                                           |
| ----------------- | ------ | ------------------------------------------------------------ |
| **`MAP_SHARED`**  | `0x01` | **共享映射**。对内存的修改会写回文件，且对其他映射了同一文件的进程**可见**。                   |
| **`MAP_PRIVATE`** | `0x02` | **私有映射**。对内存的修改不会写回文件，而是触发**写时复制**，创建一个私有副本。其他进程不可见。         |
| `MAP_ANONYMOUS`   | `0x20` | **匿名映射**。不映射任何文件，用于申请大块初始化为0的内存（类似`malloc`）。此时 `fd` 应为 `-1`。 |
| `MAP_FIXED`       | `0x10` | 强制使用 `addr` 作为映射地址。不推荐使用，可能导致地址冲突。                           |

返回值
- **成功**：返回映射区域的**起始虚拟地址**。
    
- **失败**：返回 `MAP_FAILED`（即 `(void *) -1`），并设置全局变量 `errno`。

#### 应用：
文件读写（I/O 的替代方案）
- **传统I/O**：`read(fd, buf, size)` -> 内核拷贝到内核缓冲区 -> 内核缓冲区拷贝到用户缓冲区 `buf`。**2次拷贝**。
    
- **`mmap` I/O**：将文件直接映射到用户空间。程序通过指针访问，缺页中断由操作系统自动处理，将文件数据从磁盘直接加载到这片内存。**0次拷贝**，效率极高，尤其适合大文件随机访问。
    
2. 大块内存分配（`malloc` 的幕后）
- 当申请一大块内存（例如超过128KB）时，`glibc` 的 `malloc` 函数底层会使用 `mmap` 来创建 **匿名私有映射**。
    
- 这相当于向操作系统“批发”了一大块内存，这块内存在分配之初就被初始化为0。
    
 进程间通信（IPC）
- 两个或多个进程可以通过 **共享文件映射** 进行通信。
- 进程A和B都使用 `MAP_SHARED` 映射同一个文件。A在映射区写数据，B能立刻从其映射区读到，效率远高于管道、消息队列等。
动态库加载
- 当程序使用 `dlopen` 或加载动态库（`.so` 文件）时，操作系统正是使用 `mmap` 将库文件的代码段、数据段映射到进程的虚拟地址空间。这使得多个进程可以共享同一份物理内存中的库代码，节省了大量内存。

#### 注意
1. **权限匹配**：`prot` 参数设置的权限不能超过打开文件描述符 `fd` 时的模式（例如，以只读方式 `open` 的文件不能映射为 `PROT_WRITE`）。
    
2. **偏移量对齐**：`offset` 必须是系统分页大小（`sysconf(_SC_PAGE_SIZE)`）的整数倍，否则会失败。
    
3. **长度舍入**：内核实际映射的大小会是分页大小的整数倍。例如，申请 `length=5000`，在4KB页的系统上，实际会映射 `8192` 字节（2页）。
    
4. **资源管理**：`mmap` 成功后，可以立即 `close(fd)`。这不会解除映射，只会关闭文件描述符。映射关系会持续到 `munmap` 或进程结束。
    
5. **错误检查**：**必须检查返回值是否为 `MAP_FAILED`**，这是最容易忽略导致段错误的地方。
    
6. **信号 `SIGBUS`**：访问的映射区域超出了底层文件的当前大小，可能会收到 `SIGBUS` 信号导致程序崩溃。

### `munmap`
```c
int munmap(void *addr, size_t length);
```
- **作用**：解除内存映射。
    
- **参数**：`addr` 必须是 `mmap` 返回的地址；`length` 应与 `mmap` 时的长度一致。
    
- **注意**：映射解除后，对 `MAP_PRIVATE` 区域的修改会丢失；对 `MAP_SHARED` 区域的修改，若已通过 `msync` 刷盘则会保留。

### `msync`
```c
int msync(void *addr, size_t length, int flags);
```
- **作用**：**主动**将 `MAP_SHARED` 映射的修改刷回磁盘文件。默认情况下，内核会异步回写，此函数确保数据落盘。
    
- **关键标志**：
    
    - `MS_SYNC`：同步刷盘，函数会阻塞直到完成。
        
    - `MS_ASYNC`：异步刷盘，函数立即返回，内核在后台完成。



### brk
每个进程都有一个名为 **“program break”** 的指针，它定义了进程堆的**结束地址**。
堆是用于动态内存分配的区域，位于未初始化的数据段（BSS）之上。

- **堆的起始点**：紧接在 BSS 段结束之后。
    
- **堆的结束点**：由 program break 指针定义。
`brk` 和 `sbrk` 系统调用就是用来移动这个指针，从而**扩张或收缩堆**的大小。

```c
#include <unistd.h>

int brk(void *addr);
void *sbrk(intptr_t increment);
```

| 函数         | 参数                   | 返回值                                                                          | 说明                                 |
| ---------- | -------------------- | ---------------------------------------------------------------------------- | ---------------------------------- |
| **`brk`**  | `void *addr`         | **成功**：返回 `0`  <br>**失败**：返回 `-1`，并设置 `errno`                                | 将 program break 直接设置为指定的地址 `addr`。 |
| **`sbrk`** | `intptr_t increment` | **成功**：返回**设置之前**的 program break 地址  <br>**失败**：返回 `(void *) -1`，并设置 `errno` | 将 program break 增加 `increment` 字节。 |

- `sbrk(0)` 是一个非常有用的调用，它返回**当前** program break 的地址，而不做任何改变。这可以用来探查堆的当前大小。
    
- `increment` 可以是正数（扩大堆）、负数（缩小堆）或零。

#### 注意
在现代编程中，**绝对不要**在应用程序代码中直接调用 `brk` 或 `sbrk`。它们会与 `malloc`、`free` 等标准库函数的管理逻辑发生冲突，导致不可预测的后果。

`brk` 和 `sbrk` 维护的 program break 地址，总是按系统页大小对齐的。

调用 `brk` 或 `sbrk` 可能会失败（例如，请求的内存超过了系统的 RLIMIT_DATA 资源限制）。

![[sbrk工作.png]]
- 1. 首次分配时，`glibc` 通过 `sbrk` 向内核“批发”大块内存
    
2. 后续分配优先从 `glibc` 自有内存池中分配，不涉及系统调用
    
3. 释放内存时，`glibc` 通常不会立即用 `sbrk` 缩小堆，而是缓存起来供后续使用


#### brk与malloc
现代的 `malloc` 实现（如 glibc 的 ptmalloc）是一个**复杂的内存管理器**，而 `brk`/`sbrk` 只是它向操作系统**申请原始内存的工具之一**。

|特性|`brk`/`sbrk`（原始工具）|**`malloc`/`free`（现代内存管理器）**|
|---|---|---|
|**功能**|只能调整堆的边界，得到一块**原始的、连续的内存**。|在堆（以及`mmap`区域）之上，实现复杂的**分配、回收、合并**算法。|
|**管理粒度**|**粗粒度**。只能管理整个堆的大小。|**细粒度**。可以分配和释放任意字节大小的内存块。|
|**使用场景**|已被封装，**不建议在应用代码中直接使用**。|**应用程序动态内存分配的标准接口**。|
|**底层机制**|主要维护**主堆** 段。|使用 `brk` 维护主堆，对**大块内存**（如>128KB）使用 `mmap` 匿名映射。|
