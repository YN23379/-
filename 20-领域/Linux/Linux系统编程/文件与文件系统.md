# 文件


## 根文件系统
### 挂载
根文件系统是内核启动时所mount的第一个文件系统，内核代码映像文件保存在根文件系统中，而系统引导启动程序会在根文件系统挂载之后从中把一些基本的初始化脚本和服务等加载到内存中去运行。

```text
根文件系统首先是一种文件系统，该文件系统不仅具有普通文件系统的存储数据文件的功能，但是相对于普通的文件系统，它的特殊之处在于，它是内核启动时所挂载（mount）的第一个文件系统，内核代码的映像文件保存在根文件系统中，系统引导启动程序会在根文件系统挂载之后从中把一些初始化脚本（如rcS,inittab）和服务加载到内存中去运行。
要明白文件系统和内核是完全独立的两个部分。在嵌入式中移植的内核下载到开发板上，是没有办法真正的启动Linux操作系统的，会出现无法加载文件系统的错误。
```


根文件系统包含系统启动时所必须的目录和关键性的文件，以及使其他文件系统得以挂载（mount）所必要的文件。

Linux启动时，第一个必须挂载的是根文件系统；若系统不能从指定设备上挂载根文件系统，则系统会出错而退出启动。成功之后可以自动或手动挂载其他的文件系统。
因此，一个系统中可以同时存在不同的文件系统。
**在 Linux 中将一个文件系统与一个存储设备关联起来的过程称为挂载（mount）**。使用 mount 命令将一个文件系统附着到当前文件系统层次结构中（根）。在执行挂装时，要提供文件系统类型、文件系统和一个挂装点。根文件系统被挂载到根目录下“/”上后，在根目录下就有根文件系统的各个目录，文件：/bin /sbin /mnt等，再将其他分区挂接到/mnt目录上，/mnt目录下就有这个分区的各个目录和文件。
### 系统组成
#### **`/bin` - 用户基础命令**

**存放所有用户在单用户和多用户环境下都必须使用的基础命令二进制文件。** 例如 `ls`, `cp`, `cat`, `bash` 等。这些命令是系统能够正常运作和进行基础恢复的**最小命令集**，即使在其他文件系统（如 `/usr`）尚未挂载时也必须可用。

#### **`/sbin` - 系统管理命令**

**存放用于系统管理和修复的系统级命令二进制文件。** 例如 `fdisk`, `ifconfig`, `fsck` 等。这些命令通常默认只有 **root 用户** 才有权限执行，涉及磁盘分区、网络配置和文件系统修复等关键操作。

#### **`/boot` - 系统启动文件**

**存放系统启动所需的静态文件。** 包括 **Linux 内核镜像**、**初始内存盘** 以及 **引导加载程序** 的配置文件。该目录的内容至关重要，一旦损坏通常会导致系统无法启动。

#### **`/dev` - 设备文件**

**将所有硬件设备和虚拟设备抽象为文件。** 这是 **“一切皆文件”** 哲学的完美体现。例如，`/dev/sda` 代表第一块硬盘，`/dev/tty` 代表终端。应用程序通过读写这些设备文件来完成与硬件的交互。

#### **`/etc` - 系统配置文件**

**存放系统和应用程序的全局配置文件。** 此目录包含的是**静态的配置文件**，而不是可执行程序。例如，用户账户信息、系统服务的启动脚本、网络配置等都在这里。修改该目录下的文件是管理员调整系统行为的主要方式。

#### **`/home` - 用户主目录**

**为每个普通用户提供独立的个人空间。** 每个用户会在此拥有一个以自己用户名命名的子目录（如 `/home/alice`），用于存放个人文档、配置文件、桌面设置等。`root` 用户的家目录是单独的 `/root`。

#### **`/lib` - 系统共享库**

**为 `/bin` 和 `/sbin` 目录下的基础命令提供最基本的共享库文件和内核模块。** 这些库文件是许多程序能够运行的基础依赖，类似于 Windows 系统中的 DLL 文件。

#### **`/opt` - 附加软件包**

**用于安装独立的第三方或商业应用程序。** 这些软件通常不遵循系统的标准包管理，每个软件会拥有自己独立的子目录（如 `/opt/google/chrome`），将其所有文件集中存放，便于管理和卸载。

#### **`/proc` - 进程与内核信息**

**一个虚拟的文件系统，提供内核和进程信息的实时接口。** 它并不占用实际磁盘空间，其中的文件（如 `/proc/cpuinfo`, `/proc/meminfo`）是动态生成的，读取它们实际上是直接向内核查询系统、进程、硬件的实时运行状态。

#### **`/tmp` - 临时文件**

**供所有用户和程序存放临时文件。** 该目录下的文件通常**在系统重启后会被自动清理**。它对所有用户可写，因此需要注意文件权限和安全问题。

#### **`/usr` - 用户程序与数据**

**二级目录层次，存放只读的用户数据和绝大部分应用程序。** 它可以被理解为 `/` 目录的延伸和扩展，在系统启动后挂载。其子目录结构复制了根目录，但包含的是非系统启动所必需的、更丰富的应用和资源。

- **`/usr/bin`**: 面向所有用户的大量**非关键性应用程序**。
    
- **`/usr/sbin`**: 非关键性的**系统管理程序**。
    
- **`/usr/lib`**: 为 `/usr/bin` 和 `/usr/sbin` 中的程序提供共享库。

#### **`/var` - 可变数据**

**存放经常变化的数据文件。** 这是一个“动态”目录，其内容会随着系统运行而不断增长或变化。例如，系统日志、打印队列、邮件、数据库文件以及网站数据等通常都存放在这里。

### 静态动态目录
- **静态目录（相对不变）**：如 `/bin`, `/sbin`, `/usr`, `/lib`, `/boot`, `/etc`。它们存放的是**系统和应用程序本身**，在系统正常运行时，其内容基本保持不变。对它们的写操作通常只发生在**系统更新或软件安装**时。
    
- **动态目录（频繁变化）**：
    
    - **`/etc`** 是配置的枢纽，虽然文件本身是静态的，但其**内容**的修改直接驱动系统行为的变化。
        
    - **`/var`** 是数据的中心，记录着系统的“生活轨迹”，如日志、缓存，其内容持续增长。
        
    - **`/tmp`** 是临时的“工作台”，文件来去匆匆。
        
    - **`/proc` 和 `/sys`** 是内核的“实时仪表盘”，它们不是真实的文件，而是**内核数据结构在内存中的动态映射**，让我们能从用户空间窥探和调整内核与进程的实时状态。

## 文件
在 Linux 操作系统中，所有被操作系统管理的资源，例如网络接口卡、磁盘驱动器、打印机、输入输出设备、普通文件或是目录都被看作是一个文件。

在 Linux 系统中有一个重要的概念：一切都是文件。其实这是 Unix 哲学的一个体现，而 Linux 是重写 Unix 而来，所以这个概念也就传承了下来。在 Unix 系统中，把一切资源都看作是文件，包括硬件设备。UNIX系统把每个硬件都看成是一个文件，通常称为设备文件，这样用户就可以用读写文件的方式实现对硬件的访问。

Linux 支持 5 种文件类型，从**文件系统管理和VFS**（虚拟文件系统）**的视角**进行分类，主要关注文件的**元数据和行为**，而不是其内部内容格式。如下图所示：

### 目标文件
经过汇编器和链接器作用后都会输出一个目标文件
**汇编**：将人类可读的汇编代码.s文件翻译成机器语言指令，把这些指令打包成**可重定位目标程序**的格式，并将结果保存在目标文件.o中。这个文件包含了机器码，但其中函数和全局变量的**内存地址尚未确定**。
目标文件：
（1）可重定位目标文件：包含二进制代码和数据，其形式可以和其他目标文件进行合并，创建一个可执行目标文件

（2）可执行目标文件：包含二进制代码和数据，可直接被加载器加载执行
可执行目标文件在不同的系统或平台上具有不同的命名格式，在Unix和X86-64 Linux上称为ELF
（3）共享目标文件：可被动态的加载和链接

由汇编器生成的就是可重定位目标文件，经过链接器作用后才生成可执行目标文件，链接器的作用就是以一组可重定位目标文件作为输入，生成可加载和运行的可执行目标文件，也就是完成符号解析和重定位


### elf文件
**ELF是Linux和其他类Unix系统的标准可执行文件、目标代码、共享库和核心转储的格式**。
它相当于Windows下的`.exe`（可执行文件）、`.dll`（动态库）和`.obj`（目标文件）的集合体。

#### 基本概念
程序源代码被编译后主要分为两种段（或者说是 节）程序指令和程序数据。代码段.text(或者是.code)就是程序指令，而数据段（.data)和.bss段属于程序数据

.bss段只是为未初始化的全局变量和局部静态变量预留位置，它并没有内容，所以它在文件里是不占据空间的
.data段保存的是已经初始化的全局静态变量和局部静态变量
**DATA段存储已初始化的全局变量和静态变量，在ELF文件中占用实际空间；BSS段存储未初始化的全局变量和静态变量，在文件中只记录大小信息，程序加载时由系统初始化为0。**
这种分离主要是为了优化。BSS段在磁盘上只记录大小信息，加载时由系统批量清零，既节省文件空间又提高加载速度。这体现了操作系统'按需分配'的设计思想。


`.rodata`段存放只读数据，一般是程序里的只读变量（比如const 修饰的）和字符串常量

.dynamic 存放动态链接信息

ELF 文件中的 LOAD 段只包含程序的静态内容：代码段、只读数据段和数据段。
堆和栈都不在 ELF 中，堆是通过` brk/mmap` 系统调用在运行时动态扩展的，栈是由操作系统在线程创建时自动分配的。这种设计实现了静态代码和动态运行时的分离。

魔术字：
1. **`7f 45 4c 46` - ELF 身份标识**
    - `7f`: 这是一个固定的魔数，非打印字符。
    - `45 4c 46`: 这三个字节对应的 **ASCII 字符就是 `E`、`L`、`F`**。
    - **作用**：这是最直接的判断。如果一个文件的前4个字节不是 `7f 45 4c 46`，那么系统就可以立刻断定它**不是**一个 ELF 文件，无需进行后续复杂的解析。
2. **`02` - 文件类别**
    - `01`: 表示 `ELF32`（32 位架构）
    - `02`: 表示 `ELF64`（64 位架构）
    - **作用**：告诉系统应该用 32 位还是 64 位的结构来解析这个文件的其余部分。你的文件是 `02`，所以是 **ELF64**，这与下面 `Class:` 一行的显示一致。
3. **`01` - 数据编码（字节序）**
    - `01`: 表示小端序
    - `02`: 表示大端序
    - **作用**：指明该文件中多字节数据（如整数、地址）的存储顺序。你的文件是 `01`，即 **小端序**，这与下面 `Data:` 一行的 `2's complement, little endian` 一致。这对于在不同字节序的机器间正确交换数据至关重要。
4. **`01` - ELF 头版本**
    - 目前通常都是 `01`（当前版本）。这个字段为未来的格式扩展预留。
5. **`00` - 操作系统 ABI**
    - 标识该 ELF 文件针对哪个操作系统 ABI。`00` 通常表示 **System V**（即通用的 UNIX 系统），这也是最常见的一种。其他值可能指向 Linux、HP-UX 等。
6. **`00` - ABI 版本**
    - 指定 ABI 的版本。通常为 `00`。
7. **剩余的 7 个 `00` - 填充字节**
    - 为了使 ELF 头结构在内存中对齐并达到标准大小（64字节），这些位置被用作填充，目前未使用，必须为 `00`。

**Program Header** 是给**操作系统**看的，在命令行输入 `./app` 时，操作系统（实际上是加载器）就读取这个表，然后按照上面的指示，把文件的不同部分“映射”到进程的内存空间里。每一个 `LOAD` 类型的条目，都代表了一段需要被加载到内存的数据。
- **Type**：段的类型。`LOAD` 是最重要的，表示需要被加载到内存的段。
- **Offset**：该段数据在 **文件** 中的起始位置。
- **VirtAddr**：该段应该被加载到 **进程虚拟内存** 的起始地址。
- **FileSiz**：该段在 **文件** 中的大小。
- **MemSiz**：该段在 **内存** 中的大小。**如果 MemSiz > FileSiz，多出来的部分在内存中初始化为0**。这是 `.bss` 段（未初始化全局变量）的实现机制。
- **Flags**：内存权限。
    - `R` = Read（读）
    - `W` = Write（写）
    - `E` = Execute（执行）
- **Align**：对齐要求。`0x1000`（4096字节）是典型的内存页大小。

对于LOAD段，看文件位置，内存位置，权限和内容
第一个LOAD：
**元数据段**：内容，根据 “Section to Segment mapping”，它包含了 `.interp`（指定动态链接器）、各种 `.note` 段、以及动态链接所需的符号表（`.dynsym`）、字符串表（`.dynstr`）等。**没有代码和数据，主要是给动态链接器用的系统信息。**
- **权限**：`R`（只读）
- **内容**：ELF头、程序头表、只读数据
- **特点**：`Filesize` = `Memsize`

第二个LOAD：
**代码段**：包含 `.init`, `.plt`, `.text`, `.fini`。.text就是所有代码，.plt是过程链接表，调用动态库函数（如 `printf`, `fopen`）的跳板。
初始化：直接从文件中将 `0x1791` 字节的代码拷贝到内存 `0x1000` 处。
- **权限**：`R E`（可读可执行）
- **内容**：程序代码（.text段）
- **特点**：Filesize = Memsize

第三个LOAD
**只读数据段**：包含 `.rodata`, `.eh_frame`。.rodata就是**只读数据**。程序里所有的字符串常量，全局常量等。- **`.eh_frame`**：用于栈展开的异常处理信息。
**初始化**：直接从文件拷贝到内存。
- **权限**：`R`（只读）
- **内容**：只读数据（.rodata段）
- **特点**：Filesize = Memsize

第四个LOAD
**数据段**：包含`.data`, `.bss`, `.dynamic`, `.got`。
- **权限**：`RW`（可读写）
- **内容**：已初始化数据（.data） + 未初始化数据（.bss）
- **Filesize (0x2e0)**：.data段的大小（需要从文件加载的初始数据）
- **Memsize (0x2b10)**：.data + .bss的总大小
- **`.got`（全局偏移表）**：动态链接库中全局变量和地址的缓存区。

注意没有栈段，**栈段不是从文件加载的**，它是由操作系统在**程序启动时自动创建**的。

- **代码段、只读数据段**：直接从文件对应部分拷贝。
- **已初始化数据段（.data）**：直接从文件对应部分拷贝。
- **未初始化数据段（.bss）**：由操作系统在加载时主动初始化为0。
- **栈**：由操作系统在运行时创建和管理。

**初始化**：
 **`FileSiz > 0`** -> **从文件拷贝**。
- **源**：从**磁盘上的ELF文件**中读取
- **内容**：对应段的原始数据（代码、数据等）
- **目标**：拷贝到**进程的虚拟内存**中


- **`MemSiz > FileSiz`** -> **剩余部分清零**。
**主要用途：.bss段（未初始化数据段）**
清零原因：
1. **安全性**：避免内存中残留其他进程的敏感数据
    
2. **C语言标准要求**：未初始化的全局/静态变量必须初始化为0
    
3. **确定性**：保证程序每次运行的行为一致



**Section Header** 是给**编译器/链接器**看的“零件清单”，告诉它这个箱子里有哪些零件（节），以及如何组装。
**不要主动去读 `readelf -S` 的输出！** 那样会眼花缭乱。而是在遇到问题时，把它当作字典来查。
- **场景一**：程序崩溃了，日志给你一个地址 `0x1234`。
    
    - 你才会去用 `addr2line -e app 0x1234`，如果这个命令失效，你才会用 `readelf -S app` 去看看哪个节区包含这个地址，然后再精确定位。
        
- **场景二**：你想知道你的程序里到底调用了哪些动态库函数。
    
    - 你才会去用 `readelf -S app | grep dyn` 来找到 `.dynsym` 的位置，然后再用 `readelf -s app` 去查看。

| **`readelf -S <file>`** | **查看节头表**      | **分析内存占用和代码尺寸，优化体积。**           |
| **`readelf -l <file>`** | **查看程序头表**     | 分析运行时内存段布局。                     |
| **`readelf -d <file>`** | **查看动态段**      | 检查动态库依赖。                        |
| **`readelf -s <file>`** | **查看符号表**      | 查找函数/变量地址，解决链接问题。               |
| **`objdump -d <file>`** | **反汇编**        | 分析生成的机器代码，进行底层调试。               |
| **`size <file>`**       | **查看段大小摘要**    | **快速获取text/data/bss段的大小，非常常用。** |
| **`strip <file>`**      | **删除符号表等调试信息** | **发布版本时极大减小可执行文件体积。**           |
| **`file <file>`**       | **查看文件类型**     | 快速确认是否是ELF文件及其架构。               |
对于size查看
- **代码段过大**：考虑函数拆分、链接时优化
    
- **数据段过大**：检查全局变量使用，惰性初始化
    
- **.bss段过大**：评估大数组/缓冲区的必要性
#### `objdump`
`readelf` 看**文件结构**，`objdump` 看**文件内容**。
`objdump` 是 GNU Binutils 中的反汇编和分析工具，主要用途：

1. **反汇编**：将机器代码转换为汇编代码
    
2. **段分析**：查看各段的内存布局和内容
    
3. **符号查看**：显示符号表信息
    
4. **重定位分析**：查看目标文件的重定位信息
    
5. **动态段分析**：查看共享库的依赖关系"

```text
# 1. 反汇编代码段
objdump -d program          # 反汇编所有代码
objdump -D program          # 反汇编所有段（包括数据）

# 2. 显示段头信息
objdump -h program          # 类似 readelf -S

# 3. 显示所有段内容
objdump -s program          # 十六进制+ASCII显示

# 4. 显示符号表
objdump -t program          # 符号表
objdump -T program          # 动态符号表

# 5. 显示重定位信息（针对.o文件）
objdump -r object.o

# 6. 反汇编特定函数
objdump -d program --disassemble=main
```
**`readelf`**：

- 专门解析ELF格式结构
    
- 显示ELF头、程序头、节头等元数据
    
- 更适合分析文件布局和依赖关系
**`objdump`**：

- 重点是反汇编和内容显示
    
- 可以查看机器指令的汇编代码
    
- 更适合代码级分析和调试

## `bashrc`

1. **`~/.bashrc`**（家目录）

- **作用范围**：仅对**当前用户**有效
    
- **文件路径**：`/home/orangepi/.bashrc`
    
- **适用场景**：个人自定义配置，如 PATH、别名等
    
- **推荐使用**：✅ 修改这个文件
    
2. **`/etc/bash.bashrc`**（系统级）

- **作用范围**：对**所有用户**有效
    
- **文件路径**：`/etc/bash.bashrc`
    
- **适用场景**：系统全局配置
    
- **需要权限**：需要 `sudo` 编辑
    
3. **`/etc/profile`** 和 **`~/.profile`**

- 系统级和用户级的登录shell配置文件
    
- 也会在登录时执行
