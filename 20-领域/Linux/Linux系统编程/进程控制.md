### 进程状态：
操作系统理论中的状态:
**创建态**：进程正在被创建，操作系统正在为其分配PCB、地址空间、资源等，创建完成后进入就绪态
**就绪态**：进程已获得除CPU外的所有必要资源，随时可以运行。等待操作系统调度器分配CPU时间片，获得CPU则进入运行态
**运行态**：进程正在CPU上执行指令，时间片用完 → 就绪态， 
需要等待I/O等事件 → 阻塞态
执行结束 → 终止态
**阻塞态**：进程因等待某些事件（如I/O完成、信号量、消息等）而无法继续执行，即使CPU空闲，该进程也不能运行，**直到等待的事件发生** → **就绪态**
**结束态** ：进程已结束执行，但还在进程表中占有一个位置，保留退出状态码供父进程查询，父进程通过wait()（阻塞）系统调用（或者是waitpid（），可以非阻塞）回收后彻底消失
（若只有主进程且在终端运行，它的父进程一般是shell，通过shell来回收，如果是图形界面运行它的父进程是桌面环境）

Linux内核具体实现：
1. **运行态 (Running/TASK_RUNNING)** - 正在CPU执行或在就绪队列等待调度
2. **可中断睡眠 (Interruptible Sleep/TASK_INTERRUPTIBLE)** - 等待资源，可被信号唤醒
3. **不可中断睡眠 (Uninterruptible Sleep/TASK_UNINTERRUPTIBLE)** - 等待硬件资源，不能被信号唤醒
4. **僵死态 (Zombie/TASK_ZOMBIE)** - 进程已终止，但父进程还未wait()
5. **停止态 (Stopped/TASK_STOPED)** - 进程被信号(SIGSTOP)暂停执行"
TASK_RUNNING    // 包含"就绪"和"运行"
TASK_INTERRUPTIBLE     // 阻塞态(可中断)
TASK_UNINTERRUPTIBLE   // 阻塞态(不可中断)  
TASK_ZOMBIE     // 终止态
TASK_STOPPED    // 暂停


在Linux内核中，主要通过5种状态来管理：TASK_RUNNING包含就绪和运行；TASK_INTERRUPTIBLE和TASK_UNINTERRUPTIBLE对应阻塞态，区别在于能否被信号唤醒；TASK_STOPPED是暂停状态；TASK_ZOMBIE是终止态等待回收。

操作系统为每个进程维护了一个数据结构，称为**进程控制块 (PCB)**。PCB 是进程存在的唯一标志，它包含了：

1. **进程标识符 (PID)**：进程的“身份证号”。
2. **进程状态**：运行、就绪、阻塞等。
3. **程序计数器**：下一条要执行的指令的地址。
4. **CPU 寄存器**：当进程被切换时，需要保存现场。
5. **内存管理信息**：如基址寄存器、界限寄存器、页表等。
6. **记账信息**：CPU 使用时间、时间限制等。
7. **I/O 状态信息**：分配给进程的 I/O 设备、打开的文件列表等。

一个进程的真实面貌是：PCB + 程序代码 + 相关数据集合。


***僵尸进程：子进程已终止，但父进程尚未wait()***（或者是waitpid（），可以非阻塞）
**危害：占用内核进程表项**
- 每个进程在内核中都有一个`task_struct`结构体
- 系统有最大进程数限制（`/proc/sys/kernel/pid_max`）
- 如果僵尸进程太多，可能导致**无法创建新进程**
- 进程ID（PID）被占用
- 退出状态码、运行时间统计等信息占用的内存
- 一些文件锁可能未被释放

***孤儿进程：父进程先终止，子进程被init进程(pid=1)收养***
***无害：init进程会自动wait()回收***
####  wait与waitpid
用于回收子进程资源
```c
// 方式1：wait() - 阻塞等待
pid_t wait(int *status);

// 方式2：waitpid() - 更灵活，可以非阻塞
pid_t waitpid(pid_t pid, int *status, int options);
// 使用 WNOHANG 选项可以非阻塞检查
```

**进程控制操作**：

- **创建**：`fork()` + `exec()` (Unix/Linux)
- **终止**：`exit()` (主动), `kill()` (被动)
- **等待**：`wait()`, `waitpid()` (父进程回收子进程资源，避免僵尸进程)

## 进程间通信IPC
在进程之间**传递数据**。

进程间通信（IPC）：管道是最基本的IPC，共享内存是最快的IPC
信号（异步机制），套接字（功能最强大，可用于网络通信），消息队列（内核的一个链表）。主要成本是上下文切换和数据拷贝
**管道**：
**匿名管道**：半双工通信，只能单向，用于有亲缘关系的进程。
`ps aux | grep nginx`
**命名管道**（FIFO）：有名字的文件，可用于无亲缘关系进程。
`mkfifo("/tmp/myfifo", 0666); // 创建命名管道,c语言`

**消息队列**
内核维护的**消息链表**。支持按类型读取消息，比管道更结构化。

管道的通信是无结构的字节流，发送方写入`AAAABBBB`，接收方可能一次读到`AAAA`，另一次读到`BBBB`，无法区分原始消息边界。
消息队列**把数据封装成带有类型和长度的独立消息单元。**
结构化：
1. **消息边界**：每个发送操作都对应一个完整的接收操作，解决了TCP/管道中的**消息粘包**问题。
2. **消息类型**：每个消息都带一个类型字段，接收方可以**选择性地读取**特定类型的消息，实现了简单的优先级或分类处理。
3. **内核持久化**：消息队列的生命周期不依赖于创建它的进程，即便进程退出，队列和其中的消息依然存在。

**共享内存**
**最快**的IPC方式。
多个进程**直接读写**同一块内存区域。
必须配合**同步机制**使用，否则会产生数据混乱。

**信号**：
用于通知进程**某个事件已发生**的异步机制。
不传递数据，只传递信号编号（如 `SIGINT`, `SIGKILL`）。

**套接字**
功能最强大，可用于**网络通信**。
包括Unix域套接字（本机）和网络套接字。


1.“共享内存最快，为什么不是所有IPC都用它？”
  因为共享内存需要程序员自己处理同步问题（用信号量/互斥锁），否则会产生数据竞争。其他IPC如管道，内核帮我们处理了同步，更安全但性能有损失。”

2.“线程有自己的栈，那堆是共享的吗？
是的。堆是进程级别的资源，被该进程的所有线程共享。这正是为什么多线程操作堆上的全局变量时需要加锁保护。”

3.“进程上下文切换比线程上下文切换开销大在哪里？

最核心的开销是**页表切换**（即CR3寄存器的切换），这会导致TLB快表被刷新，引发大量缓存失效。线程切换在同一进程内，地址空间不变，没有这个开销。”

4.“并发在单核上有什么用？明明没有加快速度。”

并发主要提升**响应性**和**资源利用率**。比如一个线程在等待I/O（如读磁盘）时，CPU可以立刻切换到另一个线程计算，避免了CPU空转等待，从用户体验上看程序响应更快了。”

5.并发解决等待问题’具体指什么？”
当任务中有大量I/O等待或睡眠时，并发能让CPU在等待期间去执行其他就绪任务，把原本串行的‘计算->等待->计算’流程，重叠成并发的‘计算+等待+计算’，大幅提升系统吞吐量。


## 进程同步IPC
协调多个进程的执行**顺序**或**节奏**，防止因并发访问共享资源而导致的数据混乱（竞态条件）。

**信号量**

- 一个**计数器**，用于控制对多个共享资源的访问。
- **P操作**：申请资源（计数器-1），若为0则阻塞。
- **V操作**：释放资源（计数器+1），唤醒等待者。

**互斥锁**

- 信号量的一种特例（取值0/1）。
- 保证**同一时间只有一个进程**进入临界区。

**条件变量**

- 让进程在某个**条件不满足时睡眠**，条件满足时被唤醒。
- 必须与互斥锁配合使用。

| 机制       | 主要用途 | 特点          |
| -------- | ---- | ----------- |
| **管道**   | 数据传递 | 简单，单向，有亲缘关系 |
| **共享内存** | 数据传递 | **最快**，需同步  |
| **信号**   | 事件通知 | 异步，不传递数据    |
| **信号量**  | 进程同步 | 控制资源访问      |
| **互斥锁**  | 进程同步 | 保护临界区       |
- **数据量小、简单通信** → 管道
    
- **高性能、频繁数据交换** → 共享内存 + 信号量
    
- **结构化消息、解耦** → 消息队列
    
- **跨网络通信** → 套接字
    
- **紧急事件通知** → 信号

### 进程组
多个进程的集合就是进程组, 这个组中必须有一个组长, 组长就是进程组中的第一个进程，组长以外的都是普通的成员，每个进程组都有一个唯一的组ID，进程组的ID和组长的PID是一样的。

进程组中的成员是可以转移的，如果当前进程组中的成员被转移到了其他的组，或者进制中的所有进程都退出了，那么这个进程组也就不存在了。如果进程组中组长死了, 但是当前进程组中有其他进程，这个进程组还是继续存在的。下面介绍几个常用的进程组函数：

得到当前进程所在的进程组的组ID
```c
pid_t getpgrp(void);
```

获取指定的进程所在的进程组的组ID，参数 pid 就是指定的进程
```c
pid_t getpgid(pid_t pid);
```

将某个进程移动到其他进程组中或者创建新的进程组
```c
int setpgid(pid_t pid, pid_t pgid);
```
参数:

pid: 某个进程的进程ID
pgid: 某个进程组的组ID
如果pgid对应的进程组存在，pid对应的进程会移动到这个组中, pid != pgid
如果pgid对应的进程组不存在，会创建一个新的进程组, 因此要求 pid == pgid, 当前进程就是组长了
返回值：函数调用成功返回0，失败返回-1
### 会话
会话(session)是由一个或多个进程组组成的，一个会话可以对应一个控制终端, 也可以没有。一个普通的进程可以调用 setsid() 函数使自己成为新 session 的领头进程（会长），并且这个 session 领头进程还会被放入到一个新的进程组中。先来看一下setsid()函数的原型:
```c
#include <unistd.h>

// 获取某个进程所属的会话ID
pid_t getsid(pid_t pid);

// 将某个进程变成会话 =>> 得到一个守护进程
// 使用哪个进程调用这个函数, 这个进程就会变成一个会话
pid_t setsid(void);

```


### cpu时间片
Linux采用完全公平调度器(Completely Fair Scheduler)，为每个进程维护虚拟运行时间，
通过红黑树选择运行时间最少的进程，保证所有进程公平获得CPU。
时间片通常是几毫秒到几百毫秒，通过时钟中断进行调度。

CFS的核心是虚拟运行时间(`vruntime`)，公式是：
`vruntime = actual_time * (NICE_0_LOAD / weight)`
```text
1. 高优先级进程 → 权重高 → vruntime增长慢 → 更容易被调度
2. 低优先级进程 → 权重低 → vruntime增长快 → 更难被调度  
3. 调度器总是选择vruntime最小的进程运行
   
对于普通进程weight由nice值决定
```
高优先级进程weight大，vruntime增长慢，更容易被调度。
这不同于传统固定时间片分配，而是通过权重保证比例公平。

CFS抛弃了传统固定时间片的概念，改用vruntime来衡量CPU使用量。每个进程按权重比例推进vruntime，调度器总是选择vruntime最小的进程，这样既保证了公平性，又能灵活处理优先级。我在系统监控项目中就是通过解析/proc/stat中的jiffies变化来观察这种调度行为的。


我之前做系统监控时，就是通过解析/proc/stat中的jiffies
来计算实际CPU使用率的，其中就涉及这些调度统计。

### 守护进程
是运行在后台的一种特殊类型的进程。它们通常在系统启动时启动，并在系统关闭时终止。守护进程的主要功能是提供持续运行的服务，如网络服务、系统日志记录、定时任务执行等，而不与任何终端或用户直接交互。

### 多进程
#### fork
1. `fork()` 的核心理解
- 创建一个新的进程，该进程是调用进程（父进程）的一个**副本**。
- **返回值**：在父进程中返回**子进程的PID**，在子进程中返回 **0**。通过这个返回值来区分父子进程的代码路径。
- **写时复制**：调用`fork()` 后，父子进程**共享**物理内存页，直到任一进程试图修改某页时，内核才会为该进程复制一个副本。这是 `fork` 高效的核心。
fork之后，**子进程获得的是父进程资源的“副本”或“引用”**：内存空间的副本包括代码段、数据段、BSS段、堆和栈。
子进程会复制父进程的文件描述符表。意味着父子进程指向同一个**打开文件描述**，共享文件偏移量。

[[系统调用#`clone`]]
1. **`fork()`**
    - **核心**：创建一个与父进程**几乎完全相同**的子进程（代码、数据、堆栈的副本）。
    - **特点**：**调用一次，返回两次**；在父进程中返回子进程的 PID，在子进程中返回 0。
    - **用途**：最基础、最常用的创建进程方式，适合父子进程执行不同代码分支。
        - 现代操作系统使用 **写时复制** 技术来优化 `fork()`。子进程与父进程最初**共享**相同的物理内存页，只有当任一方向试图修改某个内存页时，才会为该页创建一个副本。这极大地减少了 `fork()` 在时间和空间上的开销。
    - 
2. **`vfork()`**
    - **核心**：创建一个子进程，但**不与父进程共享地址空间**。在子进程调用 `exec()` 或 `exit()` 之前，父进程会被**挂起**。
    - **特点**：为了保证 `exec()` 之前的效率，但现代 `fork()` 的写时复制机制已使其大多情况下不再必要，**已基本被弃用**。
    - `vfork()`已被弃用，它会阻塞父进程直到子进程退出或执行新程序；

3. **`exec()` 系列函数**
    - **核心**：**不是创建新进程**，而是**将当前进程的映像替换为一个全新的程序**。
    - **特点**：进程的 PID 不变，但执行的代码和数据被完全替换。
    - **用途**：通常与 `fork()` 配合使用，形成 **`fork-exec` 模型**：由 `fork()` 创建新进程，再由 `exec()` 加载并执行目标程序。这是 **Shell 执行命令的标准方式**。
```c
// 经典模式
pid_t pid = fork();
if (pid == 0) {
    // 子进程
    execl("/bin/ls", "ls", "-l", NULL); // 子进程“变身”为 ls 命令
    // 如果 execl 成功，这行之后的代码都不会执行
    perror("execl failed");
    exit(1);
} else if (pid > 0) {
    // 父进程
    wait(NULL); // 等待子进程结束
}
```

### 进程创建
导致进程创建的事件，主要来自四个层面：  
1. **系统启动**：内核创建第一个用户进程（如 `systemd` 或 `init`），它是所有用户进程的祖先。
2. **用户交互**：用户在 Shell 中输入命令，Shell 通过 `fork()` + `exec()` 创建新进程来执行该命令。
3. **进程主动调用**：正在运行的进程通过 `fork()` 或 `clone()` 系统调用主动创建子进程。
4. **系统调度**：由作业调度系统（如 `cron` 定时任务）在后台自动创建进程执行任务。

几乎所有用户进程的创建，最终都源于一个已有进程调用 `fork()` 或 `clone()` 系统调用。

`systemd`和init：
内核完成自身初始化后，会**手动创建一个内核线程**来执行 `/sbin/init`（或 `systemd`）,这是第一个用户态进程，固定PID为1，之后所有用户进程都直接或间接由它创建
`systemd` 是` init` 的现代化升级版，它通过并行启动、统一配置和更强的服务管理能力，成为现代 Linux 的标准初始化系统。

fork和clone的区别：
`fork()` 创建的是完整的进程副本，而 `clone()` 可以通过参数选择性地共享地址空间、文件描述符等资源，`pthread` 线程就是基于 `clone()` 实现的，因此线程更轻量。
**`fork()`**：当前进程（父进程）主动创建自己的一个副本（子进程）。
**`clone()`**：提供更精细控制的轻量级进程创建，也是 POSIX 线程（pthread）的底层基础。

shell执行命令的具体过程：
Shell 先调用 `fork()` 创建子进程，子进程再调用 `exec()` 替换为要执行的程序，父进程（Shell）通过 `wait()` 等待子进程结束。

**批处理作业的初始化**
主要存在于大型机或服务器环境，由作业调度系统（如 `cron` 定时任务、批处理队列）在特定时间或条件下自动创建进程来执行任务。

- **内核机制**：虽然不创建传统的用户进程，但内核也会为处理中断、管理硬件等创建内核线程（`kthreadd` 是其始祖）。
    
- **远程请求**：通过网络接收到远程连接请求时（如 SSH 客户端连接），`sshd` 守护进程会为每个新会话创建一个新进程。

## 技巧

### 获取PID
未运行程序
```
# 1. 运行你的监控程序
./monitor &

# 2. 获取PID
MONITOR_PID=$(pidof monitor)

# 3. 查看该进程的内存映射（验证内存布局）
cat /proc/$MONITOR_PID/maps

# 4. 查看该进程的状态
cat /proc/$MONITOR_PID/status

# 5. 查看该进程打开的文件
ls -la /proc/$MONITOR_PID/fd
```

运行中程序
```
# 如果你的程序名是 monitor
ps aux | grep monitor

# 或者更精确的：
ps -ef | grep monitor

# 示例输出：
# user     12345  0.0  0.1   12345   678 pts/0    S+   14:30   0:00 ./monitor
# ↑ 这就是进程ID (PID)
```

```
# 直接通过程序名获取PID
pidof monitor
# 输出: 12345

# 如果程序有多个实例：
pidof -x monitor
```
