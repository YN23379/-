# 信号处理

> 一句话：信号是**软件层面的中断**——异步、随机、打断当前执行流去处理紧急事件。

## 一、信号是什么

信号（Signal）是 Unix 和类 Unix 系统中的一种**异步事件通知机制**。信号可以在进程运行时从外部触发，通知进程某些事件已经发生。信号可以由以下几种方式产生：

- **用户输入**：例如，用户按下 `Ctrl+C` 会发送 `SIGINT` 信号。
- **系统事件**：例如，进程试图访问非法内存时会触发 `SIGSEGV` 信号。
- **其他进程**：一个进程可以使用 `kill` 系统调用向另一个进程发送信号。
- **进程自身**：进程可以使用 `raise` 函数向自身发送信号。

**与硬件中断的类比**（理解信号的最佳视角）：

| | 硬件中断 | 信号 |
|---|---|---|
| 触发源 | 外设硬件 | 内核/其他进程/自身 |
| 时机 | 异步、随机 | 异步、随机 |
| 处理 | 中断服务程序 | 信号处理函数 |
| 铁律 | 短小快、不可重入函数 | **同样适用**（见第五节） |

## 二、常见信号表

| 信号 | 编号 | 默认行为 | 产生条件 | 可捕捉/忽略？ |
|---|---|---|---|---|
| `SIGHUP` | 1 | 终止 | 终端断开（常用于守护进程重载配置） | 可 |
| **`SIGINT`** | 2 | 终止 | `Ctrl+C` | 可 |
| `SIGQUIT` | 3 | 终止+core | `Ctrl+\` | 可 |
| **`SIGKILL`** | 9 | 终止 | `kill -9` | **不可** |
| `SIGSEGV` | 11 | 终止+core | 非法内存访问（段错误） | 可（但处理完还会再犯） |
| **`SIGTERM`** | 15 | 终止 | `kill` 默认（"请优雅退出"） | 可 |
| `SIGCHLD` | 17 | 忽略 | 子进程终止（回收僵尸进程用） | 可 |
| **`SIGSTOP`** | 19 | 暂停 | 挂起进程 | **不可** |
| `SIGALRM` | 14 | 终止 | `alarm()` 定时到 | 可 |

**`SIGKILL`/`SIGSTOP` 为什么不可捕捉、不可忽略？**——这是**故意的**：
必须保证 root 和内核总有手段控制任何进程。如果允许进程屏蔽 SIGKILL，
就可能出现"杀不死"的进程，系统失去最终控制权。

## 三、进程对信号的三种处理方式

1. **执行默认动作（SIG_DFL）**：多数是终止进程，部分忽略。
2. **忽略（SIG_IGN）**：丢弃该信号，当没发生过。
3. **捕捉并执行自定义处理函数**：内核在合适时机切换到你的函数执行。

```c
/* 旧接口：简单但行为在不同系统有差异 */
signal(SIGINT, handler);

/* 推荐：sigaction，可精确控制（如自动重启系统调用、屏蔽处理期间到达的信号） */
struct sigaction sa;
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = 0;
sigaction(SIGINT, &sa, NULL);
```

## 四、不可靠信号 vs 可靠信号（排队问题）

| | 不可靠信号（标准信号） | 可靠信号（实时信号） |
|---|---|---|
| 编号 | 1~31 | `SIGRTMIN`(34) ~ `SIGRTMAX`(64) |
| **到达方式** | **不排队**：同一信号多次产生，只记"有一个未决" | **排队**：发几次就递送几次 |
| 处理期间同信号再到达 | 合并为一次（可能"丢"中间次数） | 按序逐个递送 |

**推论**：不能靠"连续发 3 次 SIGUSR1"让处理函数跑 3 遍——它可能只跑 1 次。
需要计数的场景要么用实时信号，要么改用其他 IPC。

**"未决"（pending）= 已产生、尚未递送**。信号可以先**阻塞**（挡住不递送，挂在未决集），
解除阻塞后才递送——`sigprocmask()` 管阻塞集，`sigpending()` 查未决集。

## 五、信号处理函数的铁律（异步安全）

信号随时可能打断主流程——**处理函数打断的那行代码可能正拿着锁、正在 malloc 一半**。
所以：

1. 处理函数内**只能调用异步信号安全函数**（`write` 可以，`printf/malloc` 不行——它们内部有锁）。
2. 最稳的写法：处理函数只设一个标志位，主循环去检查：

```c
volatile sig_atomic_t got_signal = 0;   /* sig_atomic_t：读写不可分割 */

void handler(int sig) { got_signal = 1; }   /* 只做这一件事 */

int main(void) {
    signal(SIGINT, handler);
    while (!got_signal) { /* 主循环 */ }
    /* 退出清理在这里做，不在 handler 里做 */
}
```

3. `volatile` 防止编译器把标志位优化进寄存器（主循环永远看不到变化）。

## 六、经典应用：回收僵尸进程

子进程退出后，若父进程没调 `wait()`，会留下僵尸进程。异步方案：

```c
signal(SIGCHLD, on_child);
void on_child(int sig) {
    while (waitpid(-1, NULL, WNOHANG) > 0) ;   /* 循环：可能多个子进程同时退出 */
}
```

> 必须用 `WNOHANG` + 循环：信号不排队，5 个子进程同时退出可能只触发 1 次 handler。

## 附：PV 操作（信号量）备忘

> 2026-09-18 整改：本篇原先混入一段 PV 操作，它属于**同步机制**而非信号，
> 已移至 [[20-领域/Linux/Linux系统编程/多线程编程.md|多线程编程]]。

PV 操作由 Dijkstra 提出（P=Proberen 尝试，V=Verhogen 增加），**必须成对使用**：
P（wait）申请资源——信号量 >0 则减 1 通过，=0 则阻塞等待；
V（signal）释放资源——信号量加 1，唤醒等待者。
