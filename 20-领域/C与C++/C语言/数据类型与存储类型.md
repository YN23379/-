#数据类型

## 基本数据类型

| 数据类型                 | 32位系统   | 64位系统   | 取值范围（32位）                | 取值范围（64位）        |
| -------------------- | ------- | ------- | ------------------------ | ---------------- |
| `char`               | 1字节     | 1字节     | -128 到 127               | -128 到 127       |
| `unsigned char`      | 1字节     | 1字节     | 0 到 255                  | 0 到 255          |
| `short`              | 2字节     | 2字节     | -32,768 到 32,767         | -32,768 到 32,767 |
| `unsigned short`     | 2字节     | 2字节     | 0 到 65,535               | 0 到 65,535       |
| **`int`**            | **4字节** | **4字节** | -2^31 到 2^31-1           | -2^31 到 2^31-1   |
| `unsigned int`       | 4字节     | 4字节     | 0 到 2^32-1               | 0 到 2^32-1       |
| **`long`**           | **4字节** | **8字节** | -2^31 到 2^31-1           | -2^63 到 2^63-1   |
| `unsigned long`      | 4字节     | 8字节     | 0 到 2^32-1               | 0 到 2^64-1       |
| `long long`          | 8字节     | 8字节     | -2^63 到 2^63-1           | -2^63 到 2^63-1   |
| `unsigned long long` | 8字节     | 8字节     | 0 到 2^64-1               | 0 到 2^64-1       |
| **指针 (`void*`)**     | **4字节** | **8字节** | -                        | -                |
| `float`              | 4字节     | 4字节     | 约 ±3.4e±38 (6-7位有效数字)    | 同32位             |
| `double`             | 8字节     | 8字节     | 约 ±1.7e±308 (15-16位有效数字) | 同32位             |
IEEE 754规定的32位单精度浮点数float的存储结构如下:  
- 符号位(S): 1位,用于表示正负  
- 指数位(E): 8位,用于表示指数  
- 尾数位(M): 23位,用于表示有效数字
float的取值范围是-3.4E+38,3.4E+38

- `char`, `short`, `int`, `float`, `double`, `long long` 的大小在32/64位系统下**保持不变**。
- `int` 通常被视为机器的“最自然大小”，在32/64位下均为4字节。
最自然大小是在该平台上，处理器能最**高效**处理的整型大小，通常是该架构的**字长(word size)**，但**不一定**
16位：`int`通常是2字节（匹配16位寄存器）
32位：`int`通常是4字节（匹配32位寄存器）
**64位：多数系统保持`int`为4字节**

- 为避免歧义，定义固定宽度类型时使用 `<stdint.h>`：
    - `int32_t` (固定4字节)
    - `uint64_t` (固定8字节)
    - `size_t` (用于表示大小，32位是4字节，64位是8字节)


在 C 语言标准中，每个整数类型都有一个 **integer conversion rank**（整数转换等级），用于决定在算术运算和比较中的类型转换顺序。

### rank
rank从低到高
```text
1. char / unsigned char / signed char
2. short / unsigned short
3. int / unsigned int
4. long / unsigned long
5. long long / unsigned long long
   
_Bool 的 rank 低于任何标准整数类型
```
**相同 rank 的不同符号类型**：如果 `int` 和 `unsigned int` 运算（rank 相同）
有符号会**转换为无符号**
**不同 rank 的类型**：
等级低的类型转换为等级高的类型，如果等级高的类型能表示原类型的所有值，则直接转换，否则，行为依赖具体规则
```c
// 示例1：不同rank
short s = 10;
unsigned int ui = 20;
s + ui;  // short → int → unsigned int (rank不同，先升到int)

// 示例2：相同rank
long x = -10;
unsigned long y = 20;
x + y;  // long → unsigned long (rank相同，有符号转无符号)

// 示例3：字符类型
char c = 'A';
unsigned int ui = 100;
c + ui;  // char先提升为int，然后int和unsigned int运算
         // rank不同(int vs unsigned int)，int先转换为unsigned int
```

### 结构体
结构体可以包含多种不同的数据类型
结构体之间不能直接用`==或!=`运算符比较,需要逐个成员比较。
不同结构体中的成员名可以相同,只要在各自的结构体内部成员名唯一即可。
结构体可以以值传递或引用传递的方式传递给函数,取决于具体函数定义,并不总是以引用方式传递。
结构的标记名是可以没有的  
结构是不可以比较的
#### 位段
结构体可以实现位段（bit field），位段的声明类似与结构体，但是只能声明int，signed int和unsigned int，如果声明为int，是有符号还是无符号取决于编译器，所以应该显式声明符号
在可移植性的程序里序注意：
1.int位段是当做无符号还是有符号
2.位段里位的最大数目
3.**位段成员在内存中是从左往右还是从右往左分配的**
4.如果一个声明指定两个位段，而第二个较大，无法容纳第一个位段剩余的位时，编译器可能把第二个位段放在内存的下一个字，有可能直接放在第一个位段的后面，造成内存位置的边界形成重叠

位段声明类似结构体，但声明类型只有三种，变量名后加冒号和
```c
struct CHAR{
	unsigned int ch :7;
	unsigned int font :6;
	unsigned int size :19;
};//总共32位，4字节
```
- 位段成员**共享**基础类型的内存空间
    
- 总位数超过基础类型大小时，会开辟新的存储单元
不同编译器可能布局不同
大端系统：高位在前
小端系统：低位在前
```c
struct SignedExample {
    int value : 3;        // 范围：-4 到 3
};
// 注意符号位扩展
```

```c
struct Danger {
    unsigned int a : 3;
};
struct Danger d;
d.a = 10;  // ❌ 10 > 7，超出3位表示范围，未定义行为！
```

常用于硬件寄存器映射和通信协议
## 存储类型
程序运行时，操作系统会给它分配一块 “[虚拟地址空间](https://so.csdn.net/so/search?q=%E8%99%9A%E6%8B%9F%E5%9C%B0%E5%9D%80%E7%A9%BA%E9%97%B4&spm=1001.2101.3001.7020)”，里面专门用来存变量的区域主要有 4 个 ——**静态数据区（含全局数据区 + 常量区）、栈区、堆区**。这四个区域的 “内存管理规则” 完全不同，直接决定了变量的 “生存期”（从创建到销毁的时间）。

### auto
**auto存储类是所有局部变量默认的存储类**。是默认的栈区变量
栈区变量的 “分配时机” 是 “执行到定义代码时”
定义在函数中的变量默认为 auto 存储类，这意味着它们在函数开始时被创建，在函数结束时被销毁。



### register
**register** 存储类用于定义存储在寄存器中而不是 RAM 中的局部变量。
这意味着变量的最大尺寸等于寄存器的大小（通常是一个字），且不能对它应用一元的 取地址'&' 运算符（因为它没有内存位置）。      

register 存储类定义存储在寄存器，所以变量的访问速度更快，但是它不能直接取地址，因为它不是存储在 RAM 中的。在需要频繁访问的变量上使用 register 存储类可以提高程序的运行速度。
现代优化编译器通常能自动做出更好的寄存器分配决策，所以显式使用register的意义不大。甚至可能干扰编译器的优化策略。C++17中已弃用register关键字。

寄存器只用于需要快速访问的变量，比如计数器
1.只有局部变量和函数参数能定义为register：
全局变量和静态变量不能用register，因为它们的生存期是 “整个程序”，而寄存器数量有限，不可能长期占用一个寄存器给全局变量。

2.static变量不能和register一起用：
**一个变量只能有一个存储类别** ——static是 “放静态数据区”，register是 “放寄存器”，两者冲突，比如register static int a = 10;会直接报错。

3.只有 “小类型” 变量适合register：
寄存器的长度通常和 CPU 字长一致（比如 32 位 CPU 寄存器是 4 字节，64 位是 8 字节），所以int（4 字节）、char（1 字节）、short（2 字节）适合用register；而double（8 字节，部分 CPU 支持）、long long（8 字节）或结构体（更大）不推荐，因为可能放不下寄存器，编译器会自动当成普通变量处理。

4.编译器有 “最终决定权”：
即使写了register，如果寄存器已经被其他变量占用，或者编译器判断这个变量 “不常用”，也会自动忽略register，把变量放到栈区 ——register只是 “建议”，不是 “强制”。
现在很多优秀的编译器（比如 GCC、Clang）还会自动识别频繁使用的变量（比如循环变量），即使你没写register，也会主动放到寄存器里优化。

### static
**static** **存储类用于限制变量/函数的作用域或延长局部变量的生命周期**。
**静态局部变量，函数结束后不销毁**。**作用域不变，只在定义它的代码块内有效**

`static`关键字的功能根据它修饰的对象不同而不同，主要有三种用法：
**修饰函数内的局部变量**：当 `static` 用在**函数内部**修饰局部变量时，它会将变量从栈区移至全局数据区（静态区）。这**改变了变量的生命周期**，使其不随函数调用结束而销毁，而是在整个程序运行期间都存在，从而实现在多次函数调用间保持状态。
**修饰全局变量或函数**：当 `static` 修饰**全局变量或函数**时，它**不改变生命周期**而是**将其链接属性从外部链接改为内部链接**。也就是把这个变量或函数的作用域被限制在**当前源文件内部**，其他文件无法通过 `extern` 访问，从而实现了信息隐藏和避免命名冲突。

**静态变量在程序中只被初始化一次，即使函数被调用多次，该变量的值也不会重置**。

静态变量能够更改外部链接属性的原因：
静态变量就初始化一次，只占用一个内存空间，编译器在读到static之后就会对他赋
予不同的作用域，使得它只能在作用域内有效，如果作用域之外的文件调用它，就会
报错显示没有初始化该函数/变量
### extern
**extern存储类用于定义在其他文件中声明的全局变量或函数**。
当使用 extern 关键字时，不会为变量分配任何存储空间，而只是对编译器说明该变量在其他文件中定义。

主要是为了**实现跨文件访问**，**用于声明一个在其他源文件中已定义的全局变量或函数，告知编译器该符号的定义在外部，由链接器在最终阶段完成绑定**。

使用 **extern** 时，对于无法初始化的变量，会把变量名指向一个之前定义过的存储位置。


## 关键字

### volatile
**volatile关键字 指出变量是随时可能发生变化的**，核心作用是防止编译器优化，确保每次访问都从原始地址读取数据。
1. 并行设备的硬件寄存器，确保每次访问都是真实的硬件状态。（因为每次都需要从地址读取，不进行假设）
2. 中断服务程序中的全局变量，使用volalile关键字可以进行保护，防止编译器优化导致主程序读取到的值不是最新的。
3. 多线程环境下的共享变量，避免编译器优化而忽略其他线程的修改。使用volatile可以关闭系统调度防止编译器对代码进行优化防止语句只执行一次


### const
**`const` 关键字用于定义只读变量，在编译期进行保护，防止程序意外修改被标记的数据**
1.声明常变量，，使得指定的变量不能被修改。  
2.修饰函数形参，使得形参在函数内不能被修改，表示输入参数。  
3.修饰函数返回值，使得函数的返回值不能被修改。
（const变量保存在常量区）<[可执行程序内存分布](https://blog.csdn.net/Ivan804638781/article/details/110010286)>
```c
a)char * const p;

b)char const *p;
c)const char *p;

d)char const* const p;
```

a)是指针常量，指向char数据类型，p是常量。
【指针不可更改】

`b，c`)是指针，常量指针，指向char数据类型，p指向的数据是常量。
【所指的内容不可更改】

d)一个指针，指向常量的常指针，指向char数据类型，p是常量，p指向的数据也是常量。
【指针和所指向的数据都不可更改】
