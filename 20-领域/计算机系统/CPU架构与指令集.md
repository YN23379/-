# CPU 架构与指令集

> 一句话：搞懂"指令集怎么定、CPU 怎么跑一条指令"，才能理解 x86 和 ARM 为什么长两个样。

## 一、CISC vs RISC（两种设计哲学）

CISC（复杂指令集）和 RISC（精简指令集）是设计微处理器的两种思路：都追求高效，但平衡点不同——

> **RISC 降低硬件执行指令的复杂度，把灵活性交给编译器**（所以 RISC 对编译器要求高）；
> **CISC 强化单条指令的硬件功能**（所以 CPU 实现更复杂）。

五个维度的具体差异：

| 维度 | RISC | CISC |
|---|---|---|
| **指令集** | 种类少、**一个周期一条指令**（周期固定）；复杂操作由几条指令组合 | 指令**长度不固定**，单条指令功能强大 |
| **流水线** | 指令规整，天然适合流水线，**吞吐量大** | 指令执行要调用微程序，流水线效率低 |
| **寄存器** | **通用寄存器多**（ARM 27 个），寄存器操作为主 | 寄存器多为特定用途，**通用寄存器少**（x86 32位只有 8 个） |
| **Load-store 结构** | **只对寄存器中的数据运算**，访存用专门的 load/store 指令（访存慢、也伤存储寿命） | 可以直接对存储器中的数据运算 |
| **寻址方式** | 简化、数量少 | 复杂、寻址方式众多 |

**记忆锚点**：RISC = "简单指令 + 多寄存器 + 只碰寄存器"；CISC = "复杂指令 + 少寄存器 + 能碰内存"。

## 二、冯诺依曼 vs 哈佛（存储结构）

指令和数据怎么放，决定了总线怎么设计：

| 特性 | 冯诺依曼架构 | 哈佛架构 |
|---|---|---|
| **存储结构** | 程序和数据共享存储空间 | 程序和数据分开存储 |
| **总线** | 单总线（冯·诺依曼瓶颈） | 双总线（指令 + 数据） |
| **访问方式** | 串行访问 | 并行访问 |
| **性能** | 较低 | 较高 |
| **成本** | 较低 | 较高 |

**嵌入式系统多用哈佛架构**，三个原因：

1. **性能**：指令和数据可同时读取，避免总线竞争
2. **实时性**：适合实时控制（如 DSP、单片机）
3. **安全性**：程序区只读，防止数据覆盖代码

> 注意：现代 ARM Cortex-M 用的是**改进的哈佛架构**（总线矩阵上指令/数据总线分离，但统一编址），
> 严格说不是纯哈佛。`嵌入式通用/ARM架构` 里的"内存映射"讲的就是这个。

## 三、四大指令集架构

目前最常见的四大架构：**x86、ARM、MIPS、RISC-V**。核心区别在指令集和设计理念。

### 1. x86（CISC 代表）

```asm
MOV AX, [BX+SI+0x1234]  ; 一条指令完成：地址计算 + 内存读取
```

- **主导者**：Intel、AMD
- **主要领域**：个人电脑、服务器、高性能计算
- **特点**：指令长度不固定、功能强大；硬件电路复杂、功耗较高；**极强的向后兼容性**（能跑 40 年前的软件）
- **现状**：桌面和服务器市场近乎垄断

### 2. ARM（RISC 代表）

```asm
LDR R1, [R2, #0x10]  ; 加载：地址 = R2 + 0x10
ADD R3, R1, R4       ; 计算：R3 = R1 + R4
```

- **主导者**：ARM 公司（**只设计架构，不生产芯片**，靠授权）
- **主要领域**：移动设备、嵌入式系统、物联网
- **特点**：指令长度固定（32/64 位）、功耗极低、能效比优秀；授权模式让众多厂商都能造 ARM 芯片

### 3. MIPS（经典 RISC）

- **主要领域**：路由器、网络设备、早期嵌入式系统
- **特点**：设计干净优雅，曾是体系结构课程的教学典范
- **现状**：逐渐被 ARM 取代

### 4. RISC-V（新兴开源 RISC）

- **特点**：**完全开源**，任何公司可免费使用和修改
- **优势**：无授权费、可按需添加自定义指令、获谷歌/华为/西部数据等支持
- **主要领域**：新兴 IoT 设备、学术研究、定制芯片

## 四、位宽、地址总线与寄存器数量（易混点）

- 32 位 CPU 通常有 32 位地址总线 → 寻址空间 = 2³² = 4GB
- 但**地址总线可以比位宽宽**（如 ARM Cortex-M3 是 32 位架构，地址总线可外扩）
- **数据处理长度**（8/16/32 位）和**地址总线宽度**是两回事，别混
- 通用寄存器数量**不绝对**：RISC（ARM、MIPS）常见 32 个；x86 32 位只有 8 个

## 五、流水线（CPU 并行的本质）

**流水线 = 把一条指令拆成几个小步骤，让多条指令的不同步骤重叠执行**。

经典五级流水线：

```
取指(IF) → 译码(ID) → 执行(EX) → 访存(MEM) → 写回(WB)
```

就像洗衣机流水作业：第一台在甩干时，第二台在漂洗，第三台在洗涤——单个周期没变快，但**吞吐率翻了数倍**。

**流水线冒险**（什么时候流水线会"断"）：

| 冒险类型 | 原因 | 典型解法 |
|---|---|---|
| 结构冒险 | 两条指令抢同一个硬件部件 | 资源重复（哈佛架构的指令/数据分开就是解法之一） |
| 数据冒险 | 后一条要用前一条还没写回的结果 | 转发/旁路（forwarding）、插气泡 |
| 控制冒险 | 遇到分支，不知道下一条取哪 | 分支预测、延迟槽 |

> 这也是 RISC 适合流水线的根本原因：**指令等长、步骤固定**，流水线各级时间才均衡。
> CISC 一条指令要拆成微程序，级数不固定，流水线效率就上不去。

## 面试高频追问

- **为什么嵌入式多用哈佛/RISC？** 实时性（并行取指）、程序区只读安全、流水线效率高。
- **ARM 为什么省电？** 指令规整→译码简单、晶体管少；Load-store 不频繁访存。
- **x86 怎么活下来的？** 向后兼容 + 现代内部已把 CISC 指令**翻译成类 RISC 微操作**再流水执行——外观 CISC、内核 RISC。
- **32 位 CPU 一定只能用 4GB 内存吗？** 地址总线可以比位宽宽（PAE 等技术），不一定。
