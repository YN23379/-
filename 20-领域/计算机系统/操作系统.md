## 概念

### 特性

操作系统具有四个基本特性,分别是并发性、共享性、异步性和虚拟性,
**并发性**指多个程序同时执行的特性。在单处理器系统中,是通过多道程序轮流使用处理器,造成"同时"执行的假象;在多处理器系统中,则可以实现真正的并行执行。

**共享性**指系统中的资源可以被多个并发执行的程序共同使用。有两种共享方式:  
- 互斥共享:某一时刻只允许一个进程访问该资源  
- 同时共享:允许多个进程同时访问该资源

**异步性**指程序执行的结果不是一次性连续完成的,而是走走停停,以不可预知的速度向前推进。这是由于共享资源等因素造成的。

**虚拟性**指把一个物理实体转变为若干个逻辑实体。比如:  
- 虚拟处理器：通过多道程序设计技术可以让每个用户感觉有一个处理器专门为他服务  
- 虚拟内存：让用户感觉拥有一个比实际物理内存更大的存储空间


## 中断

中断是CPU对系统发生的某个事件作出的一种反应。
中断现场保护主要是把一些重要的寄存器如PSW、工作寄存器和SFR等的内容压入堆栈。

中断是指外部硬件产生的一个电信号从CPU的中断引脚进入，打断CPU的运行。
异常是指软件运行过程中发生了一些必须作出处理的事件，CPU自动产生一个陷入来
打断CPU的运行。异常在处理的时候必须考虑与处理器的时钟同步，实际上异常也称
为同步中断，在处理器执行到因编译错误而导致的错误指令时，或者在执行期间出现
特殊错误，必须靠内核处理的时候，处理器就会产生一个异常。

中断的响应流程：cpu接受中断->保存中断上下文跳转到中断处理历程->执行中断上
半部->执行中断下半部->恢复中断上下文。

硬中断是由**硬件设备**发起的信号，通知CPU有紧急事件需要处理。是中断的上半部，
不能睡眠，不能调度，不能访问用户空间
软中断是**软件层面**的中断机制，用于处理可以推迟执行的任务。是中断下半部，
能睡眠，能调度，能访问用户空间

软中断由内核代码主动触发，是异步的（可延迟），而且是可选触发，
异常是CPU自身（指令执行错误）触发的，它触发之后必须立刻执行，异常相当于是同步中断，是可以预测，与**指令执行**完全同步，处理**必须立即响应**的。


**中断服务程序的铁律**：不能有耗时、不可重入的操作。一般不会有返回值，浮点运算，中断函数一般是void
**ISR 短、小、快，不做耗时和复杂操作。**

`printf`（不可重入、慢）
`hal_delay`（阻塞）
`return`值（无人接收）。


## 存储
### 存储器
#### **寄存器 (Register)**
在CPU核心内部
**速度**：最快（1个时钟周期）
**容量**：最小（几十到几百字节）
- **特点**：
    - 直接参与运算
    - 每个寄存器有特定功能（如：EAX，EBX，PC，SP等）
    - 编译器/汇编器管理
在**CPU运算单元和缓存**之间

#### **缓存 (Cache)**
- **位置**：CPU内部（现代CPU通常有3级缓存）
    - L1 Cache：最近最快，分指令/数据缓存
    - L2 Cache：稍大稍慢
    - L3 Cache：最大最慢，可能多核共享

- **速度**：比内存快10-100倍
- **容量**：KB到MB级别（L1: 32-64KB，L3: 8-32MB）
- **特点**：
    - 透明管理（硬件自动缓存热点数据）
    - 减少CPU访问内存的等待时间
**关系**：**CPU和主内存之间的缓冲区**

#### **内存 (RAM - Random Access Memory)**
主板上
- **速度**：比缓存慢，比存储设备快
- **容量**：GB级别（4GB，8GB，16GB等）
- **特点**：
    - 易失性（断电数据丢失）
    - 随机访问，速度相对均匀
    - 作为程序运行时的"工作空间"
**关系**：**CPU和外存之间的桥梁**

#### **Flash/外存**
- **类型**：
    - **SSD**（基于Flash）：较快
    - **HDD**（机械硬盘）：较慢
    - **Flash芯片**：嵌入式系统中

- **速度**：最慢（毫秒级，比内存慢1000+倍）
- **容量**：GB到TB级别
- **特点**：
    - 非易失性（断电数据保留）
    - 适合长期存储
    - SSD无机械部件，比HDD快
**永久存储数据**
完整的数据访问路径
```text
CPU核心
    ↓ ← 寄存器直接交互
运算单元 (ALU)
    ↓ ← 寄存器传输
寄存器文件 (Registers)
    ↓ ← 1个时钟周期
L1 缓存 (32KB, ~4周期)
    ↓ ← 速度差异开始
L2 缓存 (256KB, ~10周期)
    ↓
L3 缓存 (8MB, ~40周期)
    ↓ ← 缓存未命中时
内存控制器
    ↓ ← 通过总线
主内存 RAM (~100-200周期)
    ↓ ← 需要时加载/交换
存储控制器
    ↓
外部存储 (SSD/HDD, ~100,000+周期)
```

## 进程管理

### 进程与程序的区别

| | 程序 | 进程 |
|---|---|---|
| 本质 | 静态的代码+数据 | **程序一次执行的动态过程** |
| 存在 | 文件（永久） | 内存中的实体（有生命周期） |
| 组成 | — | **PCB + 代码段 + 数据段 + 栈** |

**PCB（进程控制块）**是进程存在的唯一标志——操作系统管理进程就是管理 PCB
（Linux 里就是 `task_struct`，见 [[20-领域/Linux/Linux内核.md|Linux内核]]）。

### 进程三状态模型（最小集）

```text
        创建 → 就绪 ⇄ 运行 → 终止
                ↑        │
                └─ 等待事件(阻塞)
```

- **就绪 → 运行**：被调度程序选中（获得 CPU）
- **运行 → 就绪**：时间片用完 / 被更高优先级抢占
- **运行 → 阻塞**：主动等待事件（IO、锁、延时）——**只能由自己阻塞自己**
- **阻塞 → 就绪**：等待的事件到达（**不能直接从阻塞跳到运行**）

> 五状态模型在此基础上加"创建"和"终止"两个中间态；挂起态是内存不足时把进程换出到外存。

### 处理机调度三层次

| 层次 | 做什么 | 频率 |
|---|---|---|
| 高级调度（作业调度） | 从外存选作业装入内存 | 慢 |
| **中级调度（内存调度）** | 挂起/激活，换入换出提高内存利用率 | 中 |
| **低级调度（进程调度）** | 从就绪队列选一个进程上 CPU | **最频繁，毫秒级，任何 OS 必有** |

常见调度算法与取舍：

| 算法 | 特点 | 缺点 |
|---|---|---|
| FCFS 先来先服务 | 简单公平 | 对短作业不利（护航效应） |
| SJF 短作业优先 | 平均等待时间最短 | 长作业饥饿；需要预知运行时间 |
| **时间片轮转 RR** | 公平、响应快 | 时间片太大退化成 FCFS，太小切换开销大 |
| **优先级调度** | 区分轻重缓急 | 低优先级饥饿 → 老化(aging)解决 |
| 多级反馈队列 | 综合最优（不需预知时长） | 实现复杂 |

### 进程同步与互斥

- **互斥**：临界资源一次只能一个进程用（打印机、共享变量）
- **同步**：多个协作进程按一定次序执行（生产者必须等缓冲区有空位）

**信号量机制**（P/V 原语）：`P(S)` 申请（S 减 1，<0 阻塞自己）；`V(S)` 释放（S 加 1，唤醒等待者）。

- 生产者-消费者：**互斥 P 在同步 P 之后**（顺序错了会死锁）——这是经典考题
- **死锁四条件**：互斥、占有且等待、不可抢占、循环等待——**破坏任意一条即可预防**

### 进程间通信（IPC）方式对比

| 方式 | 速度 | 能否大数据 | 适用 |
|---|---|---|---|
| 匿名管道 | 中 | 有容量限制 | 父子进程，命令行 `\|` |
| 命名管道 FIFO | 中 | 同上 | 无亲缘进程 |
| **消息队列** | 中 | 消息边界清晰 | 少量结构化数据 |
| **共享内存** | **最快**（零拷贝） | 大 | 大量数据，**需配信号量同步** |
| **信号** | 低 | 1 个信号码 | 异步事件通知 |
| socket | 低 | 大 | 跨主机 |

## 内存管理

### 操作系统要解决的四个问题

1. **地址隔离**：进程 A 不能访问进程 B 的内存
2. **容量扩展**：程序可以比物理内存大
3. **高效分配**：多进程动态申请/释放，减少碎片
4. **保护与共享**：只读段不可写；必要的共享库映射

### 虚拟内存机制（现代 OS 的核心）

每个进程看到连续的"虚拟地址空间"，实际由 **MMU 通过页表映射到离散的物理页**：

```text
虚拟地址 = 虚拟页号 VPN + 页内偏移
              │ 查页表
              ▼
物理页号 PPN + 页内偏移 → 物理地址
```

- **分页**：物理内存切成固定大小页（4KB），**彻底解决外部碎片**（内部碎片只有最后一页）
- **页表**：虚拟页 → 物理页的映射表；多级页表（x86-64 四/五级）只为用到的部分建表，省内存
- **TLB**：页表的硬件缓存——没有它每次访存要多查一次内存，性能崩溃
- **缺页中断**：访问的页不在内存 → 触发缺页异常 → OS 从磁盘调入 → **对应用完全透明**
  （这是"程序可以比物理内存大"的实现机制）
- **页面置换**：内存满时按算法淘汰（OPT 理论最优不可实现；LRU 近似；Clock 是 LRU 的低开销近似）

### 分段 vs 分页

| | 分页 | 分段 |
|---|---|---|
| 单位大小 | 固定（4KB） | 不固定（按逻辑段） |
| 碎片 | 内部碎片 | 外部碎片 |
| 对程序员 | 透明 | 可见（代码段/数据段/栈段有语义） |

现代 x86-64 / ARM 实际以**分页为主**，分段大多退化成平坦模式。

## 文件与 IO 管理

### 文件系统要解决什么

把"磁盘上的连续字节块"抽象成"有名字、可按路径查找的文件与目录"：

- **FAT**：链式分配，简单但随机访问慢、不支持权限
- **inode（UNIX 系）**：每个文件一个 inode 存元数据 + 数据块指针；目录是"文件名→inode 号"的映射表
  ——**硬链接就是多个目录项指向同一 inode**，删除文件是 inode 链接数减 1
- **日志文件系统**（ext4）：先写日志再写数据，掉电后可恢复（嵌入式 Flash 文件系统如 JFFS2/UBIFS 同理，
  为了磨损均衡和掉电安全）

### IO 管理的三种方式（演进：CPU 越来越闲）

| 方式 | CPU 参与 | 特点 |
|---|---|---|
| 程序直接控制（轮询） | 全程忙等 | 简单，浪费 CPU |
| **中断驱动** | 每字节/块中断一次 | 解放 CPU，但大量数据时中断频繁 |
| **DMA** | 仅开始/结束参与 | **一块数据直接在设备和内存间搬运**，适合大块传输 |

> 嵌入式对应关系：串口收发用中断+环形缓冲；SD 卡/网口大流量用 DMA——
> 见 [[20-领域/Linux/Linux系统编程/网络编程.md|网络编程]] 的零拷贝一节。
