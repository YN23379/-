## 一、STM32 内部域

STM32 将内部模块按**供电、复位、安全隔离**划分为多个独立域，每个域可独立控制通断电。

|域|主要包含|掉电后数据|供电来源|
|---|---|---|---|
|**核心域**|CPU、普通SRAM、Flash、大部分外设|丢失|VDD 主电源|
|**备份域**|备份SRAM、RTC、备份寄存器、LSE|**保持**|VBAT 引脚（纽扣电池）|

**核心思想**：将需要“断电不丢数据”的模块隔离出来，由备用电池单独供电。主电源断开时，仅备份域继续工作。

**所属知识点**：低功耗设计与数据保持。

---

## 二、备份域详解

备份域 = 一组由 VBAT 引脚独立供电的特殊外设集合，主电源断开后仍能继续运行。

|模块|功能|
|---|---|
|备份SRAM（BKPSRAM）|小容量SRAM（常见4KB），掉电保持数据|
|备份寄存器（BKP）|若干32位寄存器，掉电保持|
|RTC|实时时钟，掉电继续走时|
|LSE振荡器|32.768kHz晶振，为RTC提供时钟|

### 供电切换机制

- VDD 存在时：备份域由 VDD 供电
- VDD 掉电时：**硬件自动**切换至 VBAT 供电

VBAT 通常接 3V 纽扣电池（如 CR2032），切换过程无需软件干预。

---

## 三、电源控制器（PWR）


PWR 是备份域的**“门卫”**，访问备份域必须先通过它授权。

### 主要职责

|功能|说明|
|---|---|
|备份域写保护控制|默认禁止写入，需调用 `HAL_PWR_EnableBkUpAccess()` 解除|
|低功耗模式管理|控制睡眠、停止、待机模式的电源策略|
|备份稳压器控制|开关备份SRAM专用的内部稳压器|
|电压监控|检测主电源掉电，触发备份切换|

## 四、备份SRAM的时钟来源

### 挂载位置

备份SRAM挂在 **AHB1 总线**上，地址固定。
备份SRAM不是挂在普通AHB总线上，而是挂在**AHB1总线**上，但它属于**备份域**这个特殊电源域。

在STM32F4/F7等系列中，备份SRAM的地址空间是固定的，例如：

STM32F407: 0x40024000 - 0x40024FFF （4KB）
STM32F429: 0x40024000 - 0x40024FFF （4KB）
### 时钟路径

```text


HSE（外部晶振，如8MHz）
    │
    ▼
PLL（倍频）
    │
    ▼
SYSCLK（系统时钟，如168MHz）
    │
    ▼
AHB1总线时钟（HCLK）
    │
    ├──▶ GPIO、DMA、普通SRAM
    └──▶ 备份SRAM
```

**关键结论**：备份SRAM的时钟来自 **AHB1 总线**，不是 PLL 直接提供。

```c
使能电源接口时钟
__HAL_RCC_PWR_CLK_ENABLE();
//备份SRAM和备份寄存器属于备份域，由电源控制器（PWR）管理。  
//只有先给PWR模块提供时钟，才能配置后续的备份域功能。

使能备份域访问
HAL_PWR_EnableBkUpAccess();
//STM32的备份域（备份SRAM、RTC、备份寄存器）默认是写保护的，防止意外修改。
//这行代码会设置PWR_CR寄存器里的 DBP位（Disable Backup Protection），解除写保护。

给备份SRAM提供时钟
__HAL_RCC_BKPSRAM_CLK_ENABLE();
//备份SRAM和普通SRAM不同，它在主电源断电后由 VBAT引脚（纽扣电池）供电维持数据。  
//但即使有VBAT供电，备份SRAM的时钟也必须使能，否则CPU无法访问它。

使能备份稳压器
(void)HAL_PWREx_EnableBkUpReg();
//备份SRAM需要一个专门的低压稳压器来供电。在低功耗模式下，这个稳压器默认被关闭以省电。
//这里把它打开，确保备份SRAM随时可读写。
//`(void) 的作用是显式忽略返回值，告诉编译器“我知道这个函数有返回值，但我故意不用”，避免静态分析工具报警告。

```

|维度|依赖|作用|
|---|---|---|
|**数据保持**|VBAT 供电|掉电后数据不丢|
|**读写访问**|AHB1 总线时钟|CPU 能访问它|

**时钟决定“能不能访问”，电源决定“能不能记住”。**

## 五、初始化流程与最关键操作

### 完整初始化步骤


```c
// 第1步：使能PWR模块时钟（否则PWR寄存器无法访问）
__HAL_RCC_PWR_CLK_ENABLE();
// 第2步：解除备份域写保护（最关键一步）
HAL_PWR_EnableBkUpAccess();
// 第3步：使能备份SRAM总线时钟
__HAL_RCC_BKPSRAM_CLK_ENABLE();
// 第4步：使能备份稳压器
HAL_PWREx_EnableBkUpReg();
```

### 最关键操作

> **`HAL_PWR_EnableBkUpAccess()` —— 解除备份域写保护**

**原因**：上电复位后备份域默认写保护。不执行此句，后续所有写入被硬件**静默忽略**，程序不报错但数据写不进去。这是最常见的坑。

---

## 六、初始化后如何使用

执行完上述 4 步后，可将备份SRAM当作**掉电不丢失的普通RAM**，直接通过指针读写：


```c
uint32_t *p = (uint32_t *)0x40024000;
*p = 0x12345678;   // 直接写入
uint32_t val = *p;  // 直接读取
```

### 使用注意事项

1. **VBAT 必须有电**：纽扣电池没电时，主电源断开数据同样丢失。
    
2. **必须校验数据有效性**：突然掉电可能导致写入一半，数据损坏。通常用 CRC 校验判断数据是否可信。
    

	**典型上电恢复流程**：
```c
if (校验通过) {
    加载备份数据到运行缓存;
} else {
    缓存清零;
    写入默认值到备份SRAM;
}
```




## 临界区保护机制

### 保护方式与适用范围

临界区保护的目标，是在访问共享数据时避免并发破坏。  
在 Cortex-M 与 uC/OS-II 中，常用的保护手段可分为中断级保护和任务级同步两类。

| 方式 | 保护对象 | 实现方式 | 对中断的影响 | 典型场景 |
|---|---|---|---|---|
| `__disable_irq()` | 全部中断 | 置位 `PRIMASK` | 屏蔽所有中断 | 极短临界区、系统启动 |
| `OS_ENTER_CRITICAL()` | 低优先级中断 | 设置 `BASEPRI` | 只屏蔽部分中断 | RTOS 内核临界区 |
| `Mutex` | 共享资源 | 任务阻塞 | 不影响中断 | 任务间互斥 |
| `Semaphore` | 同步或资源 | 任务阻塞 | 不影响中断 | 任务同步、通信 |

`__disable_irq()` 和 `OS_ENTER_CRITICAL()` 作用于中断响应路径，`Mutex` 和 `Semaphore` 作用于任务调度路径。

### `BASEPRI` 与 `OS_ENTER_CRITICAL()`

`BASEPRI` 是 Cortex-M 内核寄存器，用于屏蔽优先级数值大于等于它的中断。  
BASEPRI 是 8 位寄存器，但 STM32F407 只使用高 4 位（bit7～bit4），低 4 位固定为 0。
```text
BASEPRI 寄存器（8位）
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ b7  │ b6  │ b5  │ b4  │ b3  │ b2  │ b1  │ b0  │
│ 有效 │ 有效 │ 有效 │ 有效 │  0  │  0  │  0  │  0  │
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
```
STM32 中断优先级数值越小，实际优先级越高，`0` 最高，`15` 最低。

当 `BASEPRI = 4` 时：

- 优先级 `4` 到 `15` 的中断被屏蔽
- 优先级 `0` 到 `3` 的中断仍可响应

STM32F407 只使用 4 位优先级字段，因此需要将边界值左移 4 位：

```c
4 << (8 - 4) = 4 << 4 = 0x40
```

`OS_ENTER_CRITICAL()` 的实现方式如下：

```
#define OS_ENTER_CRITICAL()  do { cpu_sr = OS_CPU_SR_Save(CPU_CFG_KA_IPL_BOUNDARY << (8u - CPU_CFG_NVIC_PRIO_BITS)); } while (0)
#define OS_EXIT_CRITICAL()   do { OS_CPU_SR_Restore(cpu_sr); } while (0)
```

相关配置通常为：

```
#define CPU_CFG_NVIC_PRIO_BITS       4u
#define CPU_CFG_KA_IPL_BOUNDARY      4u
```

保存和恢复的核心过程为：

```
CPU_SR OS_CPU_SR_Save(CPU_INT08U prio)
{
    CPU_SR cpu_sr;
    cpu_sr = __get_BASEPRI();
    __set_BASEPRI(prio);
    return cpu_sr;
}
```

进入临界区后，`BASEPRI` 被设置为 `0x40`，优先级 `4` 到 `15` 的中断被屏蔽，优先级 `0` 到 `3` 的中断仍可进入。退出时恢复进入前保存的寄存器值，因此该方式支持嵌套调用。

```
OS_ENTER_CRITICAL();
OS_ENTER_CRITICAL();
OS_EXIT_CRITICAL();
OS_EXIT_CRITICAL();
```

### 高优先级中断与 uC/OS API

优先级 `0` 到 `3` 的中断不受 `BASEPRI` 管控。  
若任务正在临界区内修改内核数据结构，而高优先级中断中又调用了 `OSQPost()`、`OSSemPost()` 之类的 API，就可能出现同一份内核数据被同时修改，导致结构损坏。

高优先级中断通常用于最紧急的实时处理，例如电机控制、紧急停机。  
这类中断要求尽量短的响应时间，不适合再进入 uC/OS 的临界区保护流程。  
因此，uC/OS 将可调用 API 的中断范围限定在 `BASEPRI` 可管理的区间内，以保证内核保护逻辑一致。

### 与 `__disable_irq()` 的比较

|对比项|`__disable_irq()`|`OS_ENTER_CRITICAL()`|
|---|---|---|
|屏蔽范围|全部中断|优先级较低的中断|
|使用寄存器|`PRIMASK`|`BASEPRI`|
|实时性影响|大|较小|
|恢复方式|手动重新使能|保存旧值后恢复|
|嵌套支持|需额外处理|支持|

### 设计要点

`PRIMASK` 适合完全屏蔽中断的极短操作，`BASEPRI` 适合 RTOS 内核的常规临界区保护。  
固定优先级边界可以减少内核保护逻辑的复杂度，同时保留高优先级中断的响应能力。

## GPIO（通用输入/输出）

> 本节原在 `F:\Backup\一些资料\笔记` 那份笔记里（2026-09-17 重构时合并进来）。

GPIO（General Purpose Input Output）通用输入输出口，是 MCU 与外部世界交互的最基本接口。

- 每个 GPIO 端口有 16 个引脚（如 PA0~PA15）
- 电平范围：0V~3.3V，部分引脚可容忍 5V 输入（**不能输出 5V**）
- STM32 的 GPIO 挂载在 **APB2 总线**上（AHB → APB2 → GPIO）

### 八种工作模式

| 模式 | 方向 | 典型用途 | 电气特性 |
| ---- | --- | -------- | -------- |
| 推挽输出 | 输出 | 驱动 LED、蜂鸣器、控制信号 | 可输出引脚电平，高电平接 VDD，低电平接 VSS |
| 开漏输出 | 输出 | I2C 等多设备总线，需外部上拉 | 可输出引脚电平，高电平为高阻态、无驱动能力，低电平接 VSS |
| 复用推挽 | 输出 | 作为 UART/SPI/I2C 的 TX/SCK 等引脚 | 由片上外设控制，高电平接 VDD、有驱动能力，低电平接 VSS |
| 复用开漏 | 输出 | I2C 的 SDA/SCL | 由片上外设控制，高电平为高阻态，低电平接 VSS |
| 浮空输入 | 输入 | 读取外部电平（无内部上拉） | 可读取引脚电平，引脚悬空时电平不确定 |
| 上拉输入 | 输入 | 按键检测（默认高电平） | 内部接上拉电阻，悬空时默认高电平 |
| 下拉输入 | 输入 | 按键检测（默认低电平） | 内部接下拉电阻，悬空时默认低电平 |
| 模拟输入 | 输入 | ADC 采样 | GPIO 数字功能无效，引脚直接接入内部 ADC |

**4 种输入模式**

- **浮空**：引脚内部什么都不接，电平完全取决于外部信号。外部没接好时电平是浮动的、容易受干扰，实际项目中很少单独用。
- **上拉**：内部通过一个电阻把引脚拉到 VDD（高电平）。外部没驱动时读到高电平，适合按键检测（按键按下接地，读到低电平）。
- **下拉**：内部通过一个电阻把引脚拉到 VSS（低电平）。外部没驱动时读到低电平，适合按键检测（按键按下接 VDD，读到高电平）。
- **模拟**：引脚断开数字电路，直接连接 ADC，用于采集模拟信号（如电压值）。

上拉和下拉的本质区别在于**默认电平**不同：上拉默认高、下拉默认低，分别对应不同的外部电路设计，选哪个取决于外部电路怎么接更方便。

**4 种输出模式**：推挽、开漏、复用推挽、复用开漏。核心区别在于**驱动能力**和**总线兼容性**。

- **推挽**：能主动输出高电平也能主动输出低电平，驱动能力强，点 LED、控制蜂鸣器都用这个。
- **开漏**：只能主动拉低，不能主动输出高电平（高电平要靠外部上拉电阻）。用于 I2C 等多设备共享总线的场景，多个设备都可以拉低总线而不会短路。
- **复用推挽 / 复用开漏**：引脚不再由程序直接控制，而是交给 UART、SPI、I2C 等片上外设使用。比如 UART 的 TX 引脚配置为复用推挽，I2C 的 SCL/SDA 配置为复用开漏。

标准库写法：

```c
// 初始化（需要四个结构体成员）
GPIO_InitTypeDef GPIO_InitStruct;
GPIO_InitStruct.GPIO_Pin   = GPIO_Pin_13;
GPIO_InitStruct.GPIO_Mode  = GPIO_Mode_Out_PP;   // 推挽输出
GPIO_InitStruct.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(GPIOC, &GPIO_InitStruct);

// 操作电平
GPIO_SetBits(GPIOC, GPIO_Pin_13);          // 输出高电平
GPIO_ResetBits(GPIOC, GPIO_Pin_13);        // 输出低电平
GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0);  // 读取输入电平
```

> 对比提示：i.MX95 上并没有"GPIO 控制器自带八种模式"这套概念——
> 引脚功能由 **IOMUXC** 决定（复用功能选择 + 上下拉/驱动强度等 pad 属性），
> 而高低电平由独立的 **RGPIO** 外设控制。两块芯片的"引脚控制"分层方式不同，
> 不能直接把 STM32 的 GPIO 模式表套到 i.MX95 上。

## RCC（复位与时钟控制）

RCC：Reset and Clock Control，复位和时钟控制器。

**使用任何外设之前必须先使能它的时钟。**

**系统时钟初始化由启动文件和 `SystemInit()` 完成**，不需要自己配置 PLL。绝大多数项目直接用默认的 72 MHz
（HSE 8 MHz → PLL ×9 → 72 MHz）。如果要改主频，在 `system_stm32f10x.c` 里改 `PLL_MUL` 宏就行，不需要动别的地方。

**不同外设挂在不同总线上**，使能时钟的 API 前缀不一样：

系统时钟 SYSCLK 通常由外部晶振（HSE，8 MHz）经 PLL 9 倍频得到 72 MHz，再通过 AHB/APB1/APB2 分频器分配到各总线。
GPIO 挂在 APB2 上（72 MHz），定时器挂在 APB1 上（36 MHz），USART1 挂在 APB2 上，USART2/3 挂在 APB1 上。
频率决定速度，总线决定挂载位置。

| 总线 | 使能函数 |
| --- | --- |
| APB2 | `RCC_APB2PeriphClockCmd()` |
| APB1 | `RCC_APB1PeriphClockCmd()` |
| AHB | `RCC_AHBPeriphClockCmd()` |

配置 GPIO 前必须调用 `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE)`，否则寄存器写不进去。

调试时若遇到外设不工作或频率异常，**优先检查时钟是否使能**，其次检查时钟源配置是否正确。大部分外设问题都出在时钟未使能。

uC/OS 的任务调度依赖 SysTick 定时器，SysTick 的时钟来自 AHB（72 MHz），因此系统时钟配置决定了 uC/OS 的时间基准。时钟配错了，整个 uC/OS 的时序都会偏。

> 对比提示：STM32 的时钟树在片上由 RCC 外设配置、由 `SystemInit()` 一次性设好；
> i.MX95 的主频/功耗档位由 **System Manager（SM）** 统一管理，Linux 侧通过 **SCMI** 时钟协议申请，
> 并且要区分"SM 性能档位 / 外设根时钟 / 实测频率"三个层次，不能只看一个宏。

## 附：标准库工程建立步骤（Keil）

1. 建立工程文件夹，Keil 中新建工程，选择型号。
2. 工程文件夹里建立 `Start`、`Library`、`User` 等文件夹，把固件库里的文件复制到工程文件夹来。
3. 工程里对应建立 `Start`、`Library`、`User` 等同名分组，然后把文件夹内的文件添加到工程分组里。
4. 工程选项 → C/C++ → Include Paths 内声明所有包含头文件的文件夹。
5. 工程选项 → C/C++ → Define 内定义 `USE_STDPERIPH_DRIVER`。
6. 工程选项 → Debug，下拉列表选择对应调试器 → Settings → Flash Download，勾选 `Reset and Run`。
