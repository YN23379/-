# 原码、反码与补码

计算机里由于运算器、存储器的位数限制，二进制数的表示必须统一对应的位数。
对于有符号数，符号也要占其中一位。
**原码、反码、补码都是专门为解决有符号整数的表示和运算而设计的。**

原码表示的两个缺陷：

1. 负数原码的递增方向和真值递增方向相反，不利于加减法运算。
2. 数 0 的表示不唯一（+0 与 -0），破坏了编码的唯一性原则。

补码针对这两点改进：

1. 负数与非负数的补码都和真值同向递增，加减法可以直接做。
2. 数 0 的补码只有一种表示，满足编码唯一性。
3. 补码能多表示一个负数：n 位补码的最小值是 $-2^{n-1}$，最大值是 $2^{n-1}-1$。

### 三码对照（先看例子）

以 8 位为例，求 -5 的三种编码：

| 十进制 | 原码 | 反码 | 补码 |
|---|---|---|---|
| +5 | 0000 0101 | 0000 0101 | 0000 0101 |
| -5 | 1000 0101 | 1111 1010 | **1111 1011** |
| -1 | 1000 0001 | 1111 1110 | **1111 1111** |

规则：正数三码相同；负数反码 = 原码除符号位按位取反；**补码 = 反码 + 1**。

### 补码的数学本质：模运算

补码不是"发明出来的规则"，而是**模运算的自然结果**：

```text
n 位系统的模 = 2^n。减一个数 ≡ 加上它的补数（模 2^n）。
-x ≡ 2^n - x   (mod 2^n)

例：8 位系统算 5 - 3：
  5 + (2^8 - 3) = 5 + 253 = 258
  258 mod 256 = 2   ✓ 正确
```

所以**硬件上只需要一个加法器**：`a - b` 就是 `a + 补码(b)`，减法/带符号运算全部统一——
这就是补码统治所有现代 CPU 的根本原因（电路简单 = 便宜 + 快）。

### n 位补码的表示范围推导

```text
最大值：0111...1 = +2^(n-1) - 1
最小值：1000...0 = -2^(n-1)      ← 没有对应的 +2^(n-1)，所以负数多一个
0 只有一种表示：0000...0
```

**常见坑**：`-128` 的补码还是 `1000 0000`，对它取负（+128）**溢出**，结果还是 -128。

### 移位与溢出规则（面试常问）

| 操作 | 规则 | 例（8 位） |
|---|---|---|
| 左移 `<<` | 低位补 0，**相当于 ×2**（未溢出时） | 0001 0100 << 1 = 0010 1000 |
| 算术右移 `>>`（有符号数） | **高位补符号位** | 1111 0000 >> 1 = 1111 1000（-16→-8） |
| 逻辑右移 `>>`（无符号数） | 高位补 0 | 1111 0000 >> 1 = 0111 1000 |
| unsigned 溢出 | **回绕**（mod 2^n） | 255+1 = 0 |
| signed 溢出 | **未定义行为 UB** | 不要依赖它 |

> **有符号数的右移是算术右移还是逻辑右移？** C 标准说这是**实现定义**——
> 但所有主流编译器对有符号负数都做**算术右移**（保留符号）。
> 写跨平台代码时不要依赖这一点，用显式掩码处理。

### 与嵌入式强相关的一个细节

把 `int` 截断成 `char`：**保留低 8 位，重新按补码解释**：

```c
int a = 300;          /* 0x12C */
char c = a;           /* 低 8 位 0x2C = 44 */
char d = 513;         /* 0x201 → 低 8 位 0x01 = 1 */
```

这是为什么跨函数传参、协议打包时推荐用 `int8_t/uint8_t`（stdint.h）显式声明宽度——
见 [[20-领域/C与C++/C语言/数据类型与存储类型.md|数据类型与存储类型]]。

### 补码的运算规则与快速求法

- 补码加减法与实数相同，**最高位的进位丢弃**（这正是模运算的含义）。
- 补码表示范围有限，运算结果超出范围就**溢出**（硬件用标志位检测）。

求一个负数的补码，有两种等价做法：

1. **常规做法**：符号位保持 1，数值位全部取反，末位加 1。
2. **快速做法**：符号位保持 1，从右往左找到第一个 `1`，
   这个 `1` 及其右边的 `0` 保持不变，其余数值位取反。

第 2 种做法避免了末位加 1 可能引起的连锁进位，而且**它就是补码硬件逻辑电路的实现基础**——
这也是为什么这个技巧值得记住，而不是纯应试口诀。
