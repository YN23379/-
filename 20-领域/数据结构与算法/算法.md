## 字符串模式匹配

### 朴素模式匹配算法

主串长n，子串长m
将主串中所有长度为m的子串分别与模式串对比，直至找到对应的完全匹配的子串或者找完、

### KMP算法

**解决什么问题**：朴素匹配最坏 O(n·m)——每次失配主串都往回挪一位重新比。
KMP 做到 **O(n+m)**，核心是两句话：

1. **主串指针永不回退**；
2. 失配时**模式串**利用"自己已匹配部分的前后缀信息"跳到该跳的位置。

#### 核心原理：最长相等前后缀

失配发生在模式串第 j 位时，前面 j-1 位是**已经匹配成功的**。这段已知信息里，
如果存在"**前缀 == 后缀**"的最长部分（长度为 next[j-1]），那么：

```text
主串：  A B A B C A B A A ...
模式串：    A B A B D
                 ↑ 在 D 失配（前面 ABAB 已匹配）
已匹配部分 ABAB 的最长相等前后缀 = "AB"（长度 2）
→ 模式串直接滑到让前缀 AB 对齐刚才的后缀 AB，从模式串第 3 位继续比
主串：  A B A B C A B A A ...
模式串：        A B A B D
```

**主串指针一步都没回退**——这就是 KMP 快的全部原因。
朴素算法里"回退主串重新比"的那些比较，全被 next 数组跳过了。

#### next 数组的含义与计算

`next[j]` = 模式串 **[0..j-1]** 这段的"最长相等前后缀长度"。

以 `ABABC` 为例手算（这是面试常让你现场做的）：

| j | 子串 [0..j-1] | 最长相等前后缀 | next[j] |
|---|---|---|---|
| 0 | （空） | 定义为 0（有的教材记 -1） | 0 |
| 1 | A | 无 | 0 |
| 2 | AB | 无 | 0 |
| 3 | ABA | A | 1 |
| 4 | ABAB | AB | 2 |

```c
void getNext(const char *p, int m, int next[]) {
    next[0] = 0;
    int k = 0;                       /* k = 当前最长相等前后缀长度 */
    for (int j = 1; j < m; j++) {
        while (k > 0 && p[j] != p[k])
            k = next[k - 1];         /* 失配：回退到次长的相等前后缀 */
        if (p[j] == p[k])
            k++;                     /* 延伸 */
        next[j] = k;
    }
}
```

#### 匹配主流程

```c
int kmpSearch(const char *s, int n, const char *p, int m, int next[]) {
    int j = 0;
    for (int i = 0; i < n; i++) {    /* i 只前进，永不回退 */
        while (j > 0 && s[i] != p[j])
            j = next[j - 1];         /* 失配：模式串回退到 next 位置 */
        if (s[i] == p[j])
            j++;
        if (j == m)
            return i - m + 1;        /* 完整匹配，返回起始下标 */
    }
    return -1;
}
```

#### 复杂度

- 时间 **O(n + m)**：主串指针只前进；模式串指针虽然会回退，但**总回退次数 ≤ 总前进次数**（摊还分析）。
- 空间 O(m)（next 数组）。

#### nextval 的优化

`next[j]` 跳过去之后，如果**跳到的那位字符和失配字符相同**，必然再失配一次——白比。
nextval 直接跳到"下一个不同字符"的位置：

```text
模式串：A B A B A
next   ：0 0 1 2 3
nextval：0 0 0 0 3   ← 第 2/4 位回退后仍是 B/A，等于多跳一步
```

#### 对比记忆

| 算法 | 预处理 | 匹配 | 特点 |
|---|---|---|---|
| 朴素 | 无 | O(n·m) | 最坏时主串大量回退 |
| **KMP** | O(m) | O(n) | 主串不回退，适合**流式**输入（读一点比一点） |
| BM/Sunday | O(m+σ) | 实际常快于 KMP | 从右往左比，坏字符规则，文本编辑器常用 |

> KMP 的适用场景提示：**模式串固定、主串是流**（网络数据、日志）时优势最大；
> 普通一次性搜索，std::strstr 等用 BM 变体反而更快。

## DP（动态规划）
**动态规划（Dynamic Programming）**：  
把复杂问题分解成小问题，保存小问题的解，避免重复计算。

特点：

1. **最优子结构**：大问题的最优解包含小问题的最优解
    
2. **重叠子问题**：同样的子问题反复出现
    
3. **状态转移方程**：从小问题解推出大问题解的公式


### **二维矩阵最值**
#### [最大正方形](https://leetcode.cn/problems/maximal-square/)

1. 定义 `dp[i][j]` = 以 `(i, j)` 为右下角的最大正方形边长
    
2. 初始化：第一行和第一列直接等于 `matrix` 中的值（0 或 1）
    
3. 状态转移：
    
    - 如果 `matrix[i][j] == '0'` → `dp[i][j] = 0`
        
    - 如果 `matrix[i][j] == '1'` →  
        `dp[i][j] = min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) + 1`
        
4. 记录过程中最大的 `dp[i][j]`，最后返回其平方（面积）


```c
 for (int i = 0; i < rows; i++) {
        for (int j = 0; j < cols; j++) {
            if (matrix[i][j] == '1') {
                if (i == 0 || j == 0) {
                    dp[i][j] = 1;
                } else {
                    dp[i][j] = fmin(fmin(dp[i-1][j], dp[i][j-1]), dp[i-1][j-1]) + 1;
                }
                maxSide = fmax(maxSide, dp[i][j]);
            } else {
                dp[i][j] = 0;
            }
        }
    }
```


## 多数元素

### Boyer-Moore 投票算法
[169. 多数元素](https://leetcode.cn/problems/majority-element/)
**绝对多数**：出现次数 **> n/2**
**保证存在**多数元素

- 把多数元素记作 `+1` 票，其他元素记作 `-1` 票
    
- 维护候选元素 `candidate` 和计数器 `count`
    
- 遍历时：
    
    - `count == 0` → 选择当前元素为候选
        
    - 当前元素 == candidate → `count++`
        
    - 当前元素 ≠ candidate → `count--`
        
- 最终 `candidate` 就是多数元素
```c
int majorityElement(int* nums, int n) {
    int candidate = nums[0], count = 1;
    for (int i = 1; i < n; i++) {
        if (count == 0) candidate = nums[i];
        count += (nums[i] == candidate) ? 1 : -1;
    }
    return candidate;
}
```

|方法|时间复杂度|空间复杂度|适用场景|
|---|---|---|---|
|**Boyer-Moore**|O(n)|O(1)|**推荐**，保证存在多数元素时|
|哈希表|O(n)|O(n)|需要统计所有元素频率时|
|排序|O(nlogn)|O(1)|简单实现，数据量不大时|
|分治|O(nlogn)|O(logn)|练习分治思想|

## LCA 最近公共祖先（Lowest Common Ancestor）

## 最近公共祖先 (LCA) 问题

### 问题定义

**最近公共祖先** (Lowest Common Ancestor)：对于有根树 T 的两个节点 p、q，最近公共祖先表示为一个节点 x，满足：
- x 是 p、q 的祖先
- x 的深度尽可能大
- 一个节点可以是它自己的祖先

### 应用场景

1. 计算树中两节点的最短路径
2. 家族关系分析
3. 文件系统目录关系
4. 编译器的继承关系分析

### 标准递归解法

#### 核心思想
每个递归调用返回"在当前子树中关于p和q的最有价值信息"

#### 递归契约
- **返回NULL**：当前子树中既没有p也没有q
- **返回p或q**：在当前子树中找到了其中一个目标节点
- **返回其他节点**：已经找到了p和q的最近公共祖先

#### 算法模板

```c
struct TreeNode* lowestCommonAncestor(struct TreeNode* root, struct TreeNode* p, struct TreeNode* q) {
    // 基础情况
    if (root == NULL) return NULL;
    if (root == p || root == q) return root;
    
    // 向左右子树询问
    struct TreeNode* left = lowestCommonAncestor(root->left, p, q);
    struct TreeNode* right = lowestCommonAncestor(root->right, p, q);
    
    // 决策逻辑
    if (left != NULL && right != NULL) return root;  // 左右都有信息 → 我是LCA
    if (left != NULL) return left;                   // 只有左边有信息
    return right;                                    // 只有右边有信息
}
```

#### 时间复杂度

- **O(n)**：每个节点最多访问一次
    
- n为树中节点数量
    

#### 空间复杂度

- **O(h)**：递归栈深度，h为树的高度
    
- 最坏情况O(n)（链状树）
    
- 平均情况O(log n)（平衡树）
    

#### 关键理解点

1. **信息传递思维**：递归函数在传递"关于p和q的状态信息"
    
2. **信任递归**：相信子调用能正确返回它管辖范围内的信息
    
3. **决策在汇合点**：当信息从左右两边汇集时，当前节点就是LCA
    
4. **提前返回**：一旦找到LCA，直接返回结果，不再继续搜索

#### 变种与扩展

1. **多叉树LCA**：遍历所有子节点，统计非NULL结果数量
    
2. **带父指针的LCA**：可以转化为链表相交问题
    
3. **多次查询优化**：使用Tarjan离线算法或倍增法
    
4. **BST中的LCA**：利用BST性质，O(h)时间解决
