# 通信协议

## 五种总线横向对比

| 特性       | RS232C         | UART (Universal Asynchronous Receiver/Transmitter)**通用异步收发器** | SPI  (Serial Peripheral Interface) **串行外设接口** | I2C (Inter-Integrated Circuit) **内部集成电路总线** | CAN(Controller Area Network) **控制器局域网络** |
| -------- | -------------- | ------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------- | ---------------------------------------- |
| **通信类型** | 异步             | 异步                                                            | 同步                                            | 同步                                          | 异步                                       |
| **时钟线**  | 无              | 无                                                             | 有(SCLK)                                       | 有(SCL)                                      | 无                                        |
| **数据线数** | 至少2(TX/RX)     | 2(TX/RX)                                                      | 2+(MOSI/MISO)                                 | 2(SDA/SCL)                                  | 2(CANH/CANL)                             |
| **拓扑结构** | 点对点            | 点对点                                                           | 主从                                            | 多主多从                                        | 多主多从                                     |
| **最大速率** | 20kbps-115kbps | 类似RS232                                                       | 50Mbps+                                       | 3.4Mbps(FM+)                                | 1Mbps                                    |
| **最大距离** | 15m            | 板级                                                            | 板级                                            | 板级                                          | 10km(低速)                                 |
| **电平标准** | ±5V~±15V       | TTL/CMOS                                                      | TTL/CMOS                                      | 开漏(上拉)                                      | 差分                                       |
| **寻址方式** | 物理线路           | 物理线路                                                          | 片选线(CS)                                       | 7/10位地址                                     | 报文ID                                     |
| **应用场景** | PC串口、老设备       | 芯片间通信                                                         | 高速外设                                          | 低速多设备                                       | 汽车、工业                                    |
**协议（Protocol）**：定义数据如何组织、解释
**RS232标准**：定义物理实现
```text
串行通信
├── 同步串行（有独立时钟线）
│   ├── SPI：高速，主从，全双工
│   ├── I2C：低速，多主，半双工
│   └── I2S：音频专用
│
└── 异步串行（无独立时钟线）
    ├── UART：通用异步收发
    ├── RS232/485：UART的物理层
    └── CAN：差分异步，高可靠
```

UART，SPI，I2C，CAN都是串行总线、
**串行**：数据位**一位一位**依次传输  
**并行**：数据位**同时**通过多根线传输

串行相比并行的优势：
1. **成本低**：布线简单，引脚少
2. **频率高**：串行可以跑GHz级，并行有信号同步问题
3. **距离长**：差分串行抗干扰强，适合长距离
4. **扩展性好**：协议升级容易（如USB 2.0→3.0→4.0）

### RS232
发展历史：
RS-232（1960年） → RS-232A（1963年） → RS-232B（1965年） → RS-232C（1969年）
现在通常直接称 RS232C为RS232
**RS232 是一个物理层和电气接口标准，不是协议。**
RS232C是一种经典的异步串行通信标准，采用负逻辑电平（-5V~-15V表示逻辑1），最大传输距离约15米，使用DB9或DB25连接器。它是早期计算机与调制解调器、终端设备通信的主要接口，现在多用于工业控制和设备调试。

**核心特性**：
1. 电气特性：±5V~±15V（负逻辑，-5V~-15V表示逻辑"1"，+5V~+15V表示逻辑"0"）
2. 通信方式：异步、全双工
3. 最大距离：15米（理论上）
4. 最大速率：20 kbps（原始标准）
5. 连接器：DB9 或 DB25
采用负逻辑主要是出于抗干扰考虑。在工业环境中，正电压更容易受到干扰，负电压相对更稳定。同时-15V~-5V表示逻辑1，+5V~+15V表示逻辑0，电压差较大，噪声容限高，适合长距离传输。

**DB9 引脚（常用引脚）**：
1: DCD (Data Carrier Detect)
2: RXD (Receive Data)  ← 接收
3: TXD (Transmit Data) ← 发送
4: DTR (Data Terminal Ready)
5: GND (Signal Ground) ← 信号地
6: DSR (Data Set Ready)
7: RTS (Request To Send)
8: CTS (Clear To Send)
9: RI (Ring Indicator)

RS232是物理层标准，协议是异步串行通信协议
RS232可以通过硬件实现多点通信（但很少用）
RS232速率现代实现可达1Mbps以上（不一定很慢）
需要**MAX232芯片**把TTL电平转成RS232电平

UART和RS232
UART是通用异步收发器，是一种硬件芯片或IP核；RS232C是电气接口标准，定义了电压电平、连接器等物理层规范。实际应用中，UART负责数据的并串转换，输出TTL电平，再通过MAX232等电平转换芯片转换成RS232电平进行传输。

在实际使用中，RS232通常配合异步串行通信协议（UART协议）工作，后者定义了起始位、数据位、停止位等帧格式。所以常说的'RS232协议'实际上是'在RS232物理层上运行的异步串行协议'。

### RS485
RS485 是另一种串行通信标准，针对 RS232 的缺点改进

|特性|RS232|RS485|
|---|---|---|
|**通信方式**|全双工，点对点|半双工/全双工，多点|
|**拓扑结构**|点对点|总线式（最多32个节点）|
|**传输距离**|15米|1200米（100kbps时）|
|**最大速率**|20kbps-1Mbps|10Mbps（短距离）|
|**电平标准**|单端信号（对地）|**差分信号**|
|**抗干扰**|较弱|强（因差分信号）|
|**连接线**|多根信号线+地|A/B两根差分线+地|

## UART 帧格式详解

UART 一帧的结构（空闲电平为高）：

```text
空闲(高) │ 起始位 │ D0 D1 D2 D3 D4 D5 D6 D7 │ 校验位(可选) │ 停止位(1/1.5/2位,高) │ 空闲
         └ 低电平 ┘                          └─ 可选奇/偶校验 ─┘
```

- **起始位**：拉低 1 位时间，通知接收方"一帧开始"，双方据此对齐采样点。
- **数据位**：5~8 位，**低位在前**（LSB first）。
- **校验位**：奇/偶校验（可选）。偶校验 = 数据位中 1 的个数 + 校验位 = 偶数。
- **停止位**：拉高 1/1.5/2 位，表示帧结束。
- **波特率**：每秒传输的**码元数**（这里即位数）。双方必须约定一致，常见 9600/115200。
  误差超过约 ±2% 就会采样错位——这就是两个波特率"接近但不一样"会乱码的原因。

**常见坑**：波特率"差不多"不行；TX/RX 要**交叉**接（我 TX → 你 RX）；共地必须接，否则电平没有参考点。

## SPI 详解（CPOL/CPHA 四种模式）

**四根线**：SCLK（时钟）、MOSI（主出从入）、MISO（主入从出）、CS/SS（片选，低有效）。

- **全双工**：移位寄存器首尾相接，主从同时各移出一个位、各收进一个位——所以"发一个字节必然收一个字节"。
- **无应答机制、无寻址**：靠 **CS 线**选中从机，一主多从时每从机一根 CS。
- **四种模式由 CPOL 和 CPHA 决定**（主从必须配成一样，这是 SPI 最常见的坑）：

| 模式 | CPOL（空闲电平） | CPHA（采样相位） | 含义 |
|---|---|---|---|
| 0 | 0（空闲低） | 0（第一边沿采样） | 空闲低，上升沿采样 |
| 1 | 0 | 1（第二边沿采样） | 空闲低，下降沿采样 |
| 2 | 1（空闲高） | 0 | 空闲高，下降沿采样 |
| 3 | 1 | 1 | 空闲高，上升沿采样 |

> 记法：CPOL 看空闲电平，CPHA 看在第几个边沿采样。芯片手册写"支持 SPI mode 0,3"就是指只兼容这两种组合。

- **优点**：速度快（几十 Mbps 常见）、全双工、协议简单（没有地址/应答开销）。
- **缺点**：每从机一根 CS（引脚多）、无应答无流控、只适合板级短距离。
- 典型应用：Flash（W25Q）、SD 卡、TFT 屏、ADC/DAC。

## I2C 详解（地址、应答、仲裁）

**两根线**：SCL（时钟）+ SDA（数据），都是**开漏输出 + 上拉电阻**（必须上拉，这是硬件要求）。

**通信流程**：

```text
起始条件：SCL 高时，SDA 由高 → 低
→ 发 7 位从机地址 + 1 位读写方向（0写/1读）
→ 从机在第 9 个时钟拉低 SDA 表示 ACK（应答）；不拉 = NACK
→ 数据传输（每字节都跟一个 ACK/NACK）
→ 停止条件：SCL 高时，SDA 由低 → 高
```

- **寻址**：7 位地址理论支持 127 个设备（0x00 是广播）；10 位是扩展。
- **速度**：标准 100kbps / 快速 400kbps / 高速 3.4Mbps。
- **多主仲裁**：两个主机同时发时，谁发 1 却读到 0（线与结果）就退出——**非破坏性仲裁**，输的一方自动重发，数据不损坏。
- **时钟拉伸（clock stretching）**：从机忙时可以把 SCL 拉低不放，强制主机等待——这是 I2C 少数"从机也能控节奏"的机制。
- **优点**：两线挂多设备、有应答有寻址。**缺点**：速度比 SPI 慢、开漏上拉限制了速度、有地址开销。
- 典型应用：温湿度传感器、EEPROM（24Cxx）、RTC（DS1307）、OLED（SSD1306）。

## CAN 详解（差分、仲裁、错误处理）

**两根差分线**：CAN_H + CAN_L，显性电平（逻辑 0）与隐性电平（逻辑 1）靠**差分电压**区分。

- **多主总线**：任意节点都能主动发；**非破坏性仲裁**——按报文 ID 逐位仲裁，ID 数值小（优先级高）的赢，
  输的节点自动转接收，**不损坏总线上的数据、不需重发**。这是 CAN 与 RS485（靠碰撞重发）的本质区别。
- **错误处理完善**：每帧都有 **CRC 校验 + ACK 应答**；错误计数器（TEC/REC）超限后节点自动"离线"（bus-off），
  防止一个坏节点把整条总线堵死。
- **速度与距离成反比**：1Mbps @ 40m，125kbps @ 500m，10kbps @ 1000m。
- **典型应用**：汽车 ECU（BMS/发动机/仪表）、工业自动化。

## 选型速查（什么时候用哪个）

| 需求 | 选 | 理由 |
|---|---|---|
| 多个低速传感器、引脚紧张 | I2C | 两线 + 地址寻址 |
| 高速大流量（屏/Flash/SD） | SPI | 时钟直连、无协议开销 |
| 长距离、强干扰、多节点 | CAN | 差分 + 非破坏性仲裁 + 完善错误处理 |
| 调试口/简单点对点 | UART | 硬件最简单、全双工 |
| 多设备长距离但要求低成本 | RS485 | 差分 + 总式拓扑（但无仲裁，靠软件轮询） |

**常见误区**：

1. "SPI 一定比 I2C 快" → 大体成立，但 I2C 高速模式也能到 5Mbps，且 SPI 实际速率受从机能力限制。
2. "UART 只能点对点" → 加 RS485 物理层就是多设备总线（Modbus RTU 就是这么干的）。
3. "I2C 要上拉电阻" → 这是**必须**的，不是可选；漏上拉表现为 SDA/SCL 永远拉不高。
4. 速率数字要看条件：CAN 1Mbps 是短距离，长距离必须降波特率。

## 协议演进趋势

- I2C → **I3C**（保留两线，速度更高、支持动态地址、带中断）
- SPI → **Quad/Octal SPI**（4/8 根数据线并行，XIP 运行代码）
- CAN → **CAN FD**（数据段提速，最大 64 字节）
- UART 在调试口、工控场景仍不可替代
