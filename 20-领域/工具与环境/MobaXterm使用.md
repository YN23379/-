# MobaXterm 使用

## 要解决的问题

在一块没有显示器的开发板上做调试，需要**同时**用串口看板子输出、用 SSH 进虚拟机编代码，
还要在两台机器之间传文件。用三个独立工具会很别扭——串口工具、SSH 客户端、SFTP 各开一个，
窗口来回切，路径还要重敲。MobaXterm 是把这三件事合到一个窗口里的工具。

## 它是什么

Windows 上的终端工具，官方定位是"超级终端 + 网络工具包"。对本项目真正有用的只有三块能力：

| 能力 | 用途 |
|---|---|
| 多协议终端会话 | 串口、SSH、Telnet、Rlogin 都能建，串口和 SSH 可以并排开 |
| 内置 Unix 命令集 | 不用装 Cygwin/WSL，直接在 Windows 侧用 `grep`、`ssh`、`tar` 等命令 |
| 集成 SFTP | SSH 会话建立后侧栏自动出现文件树，拖拽即可传输 |

> 会话可以**保存**。板子的串口参数（COM 号、波特率）和虚拟机的 SSH 配置存成会话后，
> 下次点一下就连上，不用重填。这是它比裸串口工具省事的地方。

## 实际怎么用

1. **连开发板**：新建 Serial 会话，选 COM 口、设波特率（本项目用 115200）。
   板子上的 U-Boot 和 Linux 控制台都从这一条串口出来。
2. **连虚拟机**：新建 SSH 会话，填虚拟机的 IP、用户名。
   连上后左侧自动列出远端目录树，编译产物直接用拖拽传回 Windows。
3. **传文件**：优先用 SSH 会话自带的 SFTP 面板；命令行场景用 `scp`。

## 终端跳行与 `stty`

**现象**：串口或 SSH 里输出显示错乱、长行折行位置不对、退格删不干净。

**原因**：终端会话认为自己有 N 列 M 行，而实际窗口大小是另一个值。
程序按错误宽度排版，就会跳行或错位。

**处理**：

```shell
stty cols 120 rows 80    # 直接告诉终端正确的窗口尺寸
stty sane                # 把所有终端设置恢复为合理默认值（设置乱了先用这个）
stty onlcr -ixon         # 精细化调整，见下
```

- `onlcr`：输出时把 `\n` 转换成 `\r\n`。串口终端常见"换行但不回到行首"就是这个没开。
- `-ixon`：禁用软件流控制。开启时误按 `Ctrl+S` 会把终端**冻结**，
  再按 `Ctrl+Q` 才能解冻——不知道这个机制的人会以为板子挂了。

## 虚拟机网络与静态 IP

**NAT 模式下虚拟机 IP 从哪来**：宿主机上的 VMware 会虚拟出一个 DHCP 服务和一块虚拟网络
（例如 `192.168.248.0/24`），虚拟机的 `ens33` 从中自动获取 IP。

**为什么要改成静态 IP**：DHCP 分配的地址会变，每次重启后 SSH 会话就连不上，
要重新查 IP 再改配置。手动填写 IP、掩码、网关、DNS 之后地址固定，SSH 会话可以长期复用。

> 这一步和串口会话保存解决的是同一个问题：**把易变的参数固定下来，
> 让"连接"这个动作不用每次重新配置**。

## 适用范围与边界

- 适用：Windows 上做嵌入式调试，需要串口 + SSH + 文件传输并存的场景。
- 不适用：纯 Linux 开发环境用系统自带终端即可；需要复杂脚本自动化时不方便。
- **注意**：Windows 的串口是**独占**的。MobaXterm 开着串口会话时，
  其他程序（包括 Python 脚本）再打开同一个 COM 口会报 `Access to the port is denied`。
  排查串口的脚本跑之前，先把终端的串口会话关掉。
