# 笔记库重构记录（2026-09-17）

## 一、要解决的问题

原来笔记散在三处，互有重复和分歧，结构不统一，找不到东西：

| 位置 | 规模 | 问题 |
|---|---|---|
| `D:\笔记` | 68 篇 md / 24 MB | 有独立 `.git`、`.obsidian`；`技术栈/` 与 `知识库/` 两套并行目录，同一概念两个地方都有 |
| `F:\Backup\一些资料\笔记` | 135 篇 md | 与 `D:\笔记` **同一个 git 仓库**（同 remote、同 HEAD `f34df7d`），是另一份检出；多出 `Work/`（FRDM-IMX95-PRO 项目档案）、`ARM/` |
| `F:\aa\Typora` | 16 篇 md + 18 PDF + 191 图 / 99 MB | Typora 培训与 stage 笔记，与上面两处完全无关 |

另有 11 篇两边都改过、内容有分歧；若干 0 字节空笔记；`1.md`、`未命名.md` 之类无意义文件名。

## 二、采用的结构与依据

选了三套业界框架，**各管一层**，避免混用导致目录爆炸：

| 框架 | 管什么 | 出处 |
|---|---|---|
| **PARA** | 顶层分区（Projects / Areas / Resources / Archives） | Tiago Forte《Building a Second Brain》 |
| **Diátaxis** | 笔记**类型属性** `doc_type`（教程/怎么做/参考/原理），**不建目录** | [diataxis.fr](https://diataxis.fr/start-here/) |
| **Zettelkasten** | 知识层的写法：一篇一个概念、互相链接 | Luhmann 卡片盒方法 |

数字前缀（`00/10/20/...`）借鉴 **Johnny.Decimal**：排序稳定，每层留插入空间。

最终结构：

```
D:\笔记\
├─ 00-入口\     索引、看板、规则、维护说明、总入口 README
├─ 10-项目\     PARA Projects：FRDM-IMX95-PRO、PLC-微波炉、Stage-Modbus、Stage-PLSR、面试项目
├─ 20-领域\     PARA Areas：C与C++、Linux、计算机系统、数据结构与算法、RTOS、嵌入式通用、芯片与平台-i.MX95、通信协议、工具与环境

└─ 99-模板\     知识库笔记 / 项目档案笔记 / 开发日报 / 面试题
```

## 三、怎么做的（可复现）

| 步骤 | 脚本 | 产物 |
|---|---|---|
| 1 清点 + 逐文件比对 + 三处 zip 备份 | — | `build\notes-backup\20260917-*\` |
| 2 两个仓库各自 git 存档 | — | `D:\笔记` → `e8c79af`；F → `a31e74f` |

| 5 校验 | `apply_restructure.py --stage verify` | 401/401 存在、0 缺失 |

## 四、遇到的问题与根因（按发生顺序）

| # | 现象 | 排查过程 | 根因 | 解决 |
|---|---|---|---|---|
| 1 | 映射报告里 `面试题与面经/` 下的散落文件全被兜底塞进 `40-归档` | 检查规则顺序，发现 `.*\.md$` catch-all 在具体规则之后无条件命中 | 用了**兜底规则**，把"没规则命中"和"确实是垃圾"混为一谈 | 删掉 catch-all，未命中一律进 `映射未覆盖.txt` 报错，逼自己补规则 |
| 2 | `ARM嵌入式系统开发教程.PDF` 没被 PDF 规则命中 | 对比大小写 | 正则没加 `re.IGNORECASE`，`.PDF` ≠ `.pdf` | 全部匹配加 `IGNORECASE` |
| 3 | **图片被抽平到 `90-附件\`**，附件从 57 涨到 249、项目文件从 111 掉到 45 | 看二级目录分布发现 `10-项目/PLC-微波炉` 文件数骤降 | 类型规则放在了目录规则**前面**，把 stage/项目目录里的图抽走了 | 改成**目录规则优先、类型规则只兜底**——图片必须跟着笔记走，否则相对路径全断 |
| 4 | 86 组"内容完全相同"的也各复制了一份进归档 | 归档目录里出现大量 `__from-F` 文件、总数对不上 | 归档逻辑没有按 verdict 分流 | 只在 `有分歧` 时才归档；相同内容靠 md5 判定直接去重 |
| 5 | `shutil.rmtree` 删暂存树报 `WinError 5 拒绝访问` | 定位到 `.git\objects\pack\*.idx` | git pack 文件带**只读属性**，Windows 下 rmtree 不自动改权限 | 加 `onerror` 回调先 `chmod S_IWRITE` 再删 |
| 6 | 链接校验报 29 处断链，其中 `Markdown.md` 一堆 `URL`、`./IAR/IAR.md` | 打开该文件发现它本身是 **Markdown 教程**，这些是代码块里的语法示例 | 校验脚本没有跳过围栏代码块，把示例当成了真链接 | 校验前用 `FENCE` 正则把代码块挖掉；行内代码里的 `[[` 也跳过 |
| 7 | **把 `模版/1.md` 当垃圾模板删了** | 换名后做"映射文件是否都在"的复核，发现 3 条缺失，逐条查内容 | 文件名 `1.md` 让我**只凭文件名判断**，实际内容是《培训营薪资与制度》（5470 字节：8200→9200-10700、试用期考评、福利、发展路径） | 从旧库恢复到 `00-入口\培训营薪资与制度.md` 并补 frontmatter，提交 `e345b3f` |

> 第 7 条是最该记住的教训：**删除前必须看内容，不能只看文件名。**
