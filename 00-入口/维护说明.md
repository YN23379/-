# 维护说明（每周 10 分钟）

本库结构：**PARA 顶层分区 + 数字前缀排序 + Diátaxis 作为属性**。结构只分到二级，
再往下按主题自由建目录，别为了"整齐"把笔记切碎。

## 属性字段（每篇笔记的 frontmatter）

| 字段 | 含义 | 取值 |
|---|---|---|
| `type` | 这篇属于哪一层 | 项目档案 / 知识库 / 参考 / 索引 / 归档 |
| `scope` | **适用范围** | 项目名、领域名或"全库" |
| `doc_type` | Diátaxis 文档类型 | 教程 / 怎么做 / 原理 / 参考 / 未分类 |
| `status` | 整理状态 | 待整理 / 已整理 / 待验证 / 已归档 |
| `evidence` | **结论的依据等级** | 官方资料 / 源码确认 / 实机验证 / 待标注 |
| `tags` | 自由标签 | 数组 |
| `updated` | 最后整理日期 | YYYY-MM-DD |

> 自动生成时 `doc_type` 和 `status` 多数是初判，`evidence` 一律先标 `待标注`——
> 这是故意留的**待办**，不是最终值。用 `看板-待整理.base` 逐个过。

## 每周 10 分钟做什么

1. 打开 `00-入口/看板-待整理.base`，把 `status` 从"待整理"改成"已整理"或"待验证"。
2. 对本周新结论，把 `evidence` 从"待标注"改成实际等级（官方资料 / 源码确认 / 实机验证）。
3. 项目笔记里冒出来的通用原理，提炼一份到 `20-领域/`，两边互相加链接。
4. 新增笔记从 `99-模板/` 起步，不要手写 frontmatter。

## 改名与搬迁规矩

- 不再用 `1.md`、`未命名.md`、`暂时.md`，文件名直接写主题。
- 图片放 `90-附件/`，或与笔记同目录；**搬动图片时必须同步改引用**。
- 40-归档/ 里的东西只加不改；确认无用后再删（有 git 历史与 zip 备份兜底）。

## 可回退性

- 重构前的三处原件都留有 zip 备份：`F:\project\Learning\RTOS\build\notes-backup\`
- 重构前后各有 git 提交；重构本身是独立提交，便于整体回退。
- 逐文件的"旧路径 → 新路径"记录：`build/notes-inventory/映射清单.csv`
- 每个搬迁/去重决定：`build/notes-inventory/执行日志.csv`
